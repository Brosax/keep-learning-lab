Procesos y threads

多任务：进程、线程，以及让它们不打架

10 个要点 阅读约 25 分钟

物理世界里的事情是同时发生的：数据在网口上到达，用户在按键，时间在流逝。一个只有一条执行线的程序，很难同时照顾好它们。Linux 给了两种办法：开几个独立的 proceso (ES) / process (EN)——进程，或者在一个进程里开几条 hilo (ES) / thread (EN)——线程。这一章先看怎样创建、等待、结束它们，再看调度器怎样分配 CPU，最后处理多个线程共用数据时出现的三个问题：竞争条件、同步和死锁。

§1为什么需要多任务 T2.1

一个 while(1) 循环，能同时等网络、等按键、还准时做计算吗？El mundo físico es concurrente.

单片机上常见的写法是一个大循环：轮流检查每件事，有事就处理。它的极限很明显：只要其中一件事处理得久一点（等一个网络包、写一个文件），其他事就全都被耽误；而且每件事的"等待"都得改写成"查一下就走"，程序会越来越难读。

运行 Linux 的板子是一台通用计算机，操作系统提供了 multitarea (ES) / multitasking (EN)——多任务：每件事写成一段自己的、按顺序执行的代码，需要等就直接等（阻塞），由操作系统决定此刻让谁用 CPU。有两种粒度：

grano grueso · 粗粒度

多个进程

每个任务运行在自己的"虚拟机"里：它看到的内存从地址 0 开始、只属于自己，由操作系统把这些虚拟地址翻译成真实的物理地址。好处是隔离：一个进程做了非法操作被终止，不会拖垮别的进程。

grano fino · 细粒度

一个进程里的多个线程

几个任务运行在同一个"虚拟机"里，共用地址空间和资源。创建、切换、通信都更便宜，代价是一个线程出错（比如写坏了共享内存），会影响同一进程里的其他线程。

实际系统里两种通常混着用：几个进程，每个进程里又有几个线程。

还有一个常见的误解：开了两个线程，它们就"真的同时"在跑。不一定。只有一个核时，操作系统把时间切成小片轮流分给它们：这叫 concurrencia (ES) / concurrency (EN)——并发。有多个核时，两个线程才可能在同一时刻各占一个核：这叫 paralelismo (ES) / parallelism (EN)——并行。

一个后果

创建线程的那段代码，常常在新线程真正开始执行之前就跑完了。如果 main 创建完线程就 return，整个进程结束，新线程可能一行都还没执行。§3 讲怎样用 pthread_join 等它。

多任务把"同时照顾几件事"交给操作系统：粗粒度用进程（隔离好、开销大），细粒度用线程（共享内存、开销小）。单核上是并发，多核上才可能并行；执行顺序永远由调度器决定。

§2进程：启动、复制、等待 T2.2 · T2.3 · T2.4

每运行一次程序，就多了一个进程。在程序里，怎样再造一个？Multitarea de grano grueso.

一个 proceso 就是一个正在运行的程序：它有自己的地址空间（代码、全局变量、堆、栈）、打开的文件、一个编号 PID (process identifier)——进程号，以及至少一个线程。

在命令行里 T2.2

命令作用
./prueba运行当前目录下的 prueba。文件必须有执行权限（ls -l 里看到 x）。命令行会一直被占住，直到程序结束。
./prueba &在后台运行，命令行马上可以继续用。但程序仍是这个终端的子进程：终端窗口一关，它也被结束。
nohup ./prueba &脱离终端运行：窗口关了，程序照样跑。
ps aux列出正在运行的进程和它们的属性（PID、用户、CPU、内存……）。
renice -10 -p 123把 PID 123 的 nice 值改成 −10（数值越小，优先级越高；调成负数需要 root）。
kill 123请 PID 123 结束（发 SIGTERM）。不理会时用 kill -9 123 强制结束（SIGKILL）。
pkill nombre结束所有名字是 nombre 的进程，小心误杀。

从程序里启动另一个程序 T2.3

exec 族函数（execl、execv、execle、execve、execlp、execvp）把当前进程的代码换成另一个程序：PID 不变，但原来的程序被整个替换掉。所以 exec 是一种"破坏性"的执行：成功时它不返回，因为已经没有可以返回的程序了；只有失败时才返回 −1。

#include <unistd.h> execl("/bin/ls", "ls", "-l", (char *)0);   // 参数表以空指针结尾perror("execl");                               // 能执行到这里，说明 exec 失败了

名字里的字母有规律：l = 参数一个个列出（list），v = 参数放在数组里（vector），e = 额外传一份环境变量，p = 在 PATH 里找程序。

想启动另一个程序、自己又继续运行，用 posix_spawn / posix_spawnp（<spawn.h>）。它是"非破坏性"的：调用者继续执行，新程序的 PID 通过第一个参数返回。内部做的事，相当于先 fork() 再在子进程里 exec()。

fork：把自己复制一份 T2.4

pid_t fork(void); 让调用它的进程一分为二。调用者是 proceso padre (ES) / parent (EN)——父进程，新的是 proceso hijo (ES) / child (EN)——子进程。子进程得到父进程用户空间的一份副本：同样的代码、同样的变量和值、同样的打开文件。两者从 fork() 返回的地方开始各自继续执行。唯一的区别是返回值：

写成代码，就是靠一个 if 让父子走不同的分支：

#include <stdio.h>#include <stdlib.h>#include <unistd.h>#include <sys/wait.h> int main(void) {    int x = 5;    pid_t pid = fork();    if (pid == -1) {                      // 失败：没有子进程        perror("fork");        return 1;    }    if (pid == 0) {                       // 子进程        x++;        printf("hijo  %d: x = %d\n", (int)getpid(), x);        exit(3);                          // 退出状态 3    }    int st;                               // 父进程：pid 是子进程的 PID    pid_t h = wait(&st);    if (WIFEXITED(st))        printf("padre %d: hijo %d salió con %d, x = %d\n",               (int)getpid(), (int)h, WEXITSTATUS(st), x);   // x 仍是 5    return 0;}
void exit(int status)

结束自己

结束调用它的进程，把 status 交给系统，父进程可以通过 wait 取到。main 里 return n 效果相同。

pid_t wait(int *st)

等任意一个子进程

阻塞，直到某个子进程结束；返回它的 PID。st 里不是退出值本身，而是编码过的状态：先用 WIFEXITED(st) 判断是不是正常退出，再用 WEXITSTATUS(st) 取出 exit 的值。

waitpid(pid, &st, opts)

等指定的子进程

只等 PID 为 pid 的那个（pid = -1 时等任意一个）。opts 写 WNOHANG 时不阻塞：没有子进程结束就立刻返回 0。

僵尸和孤儿

子进程结束后、父进程 wait 之前，它是 proceso zombi (ES) / zombie process (EN)——僵尸进程：只占进程表里的一行，但不 wait 的父进程会让它们越积越多。反过来，父进程先结束，子进程就成了孤儿，由系统的 init 进程（PID 1）收养并替它 wait。长期运行的服务程序要么 wait 每个子进程，要么定期用 waitpid(-1, &st, WNOHANG) 收尸。

父进程里打开的文件，子进程也继承：两边拿到的是同一个打开的文件（共享读写位置）。这在两边都往同一个文件写时要注意。

循环里连续调用 fork() 时，每一个已经存在的进程都会再复制一次，进程数按 2 的幂增长。下面的练习按这个规则出题：

fork 复制整个进程，返回值区分父子：父进程得到子进程 PID，子进程得到 0，失败得到 −1。复制之后两边的内存互不影响。子进程用 exit 结束，父进程用 wait/waitpid 回收，否则留下僵尸。exec 替换当前程序、成功时不返回；posix_spawn 启动新程序并保留调用者。

§3线程：一个进程里的几条执行线 T2.5 · T2.6

不想把整个进程复制一遍，只想多一条执行线，怎么办？Threads: líneas de ejecución concurrente dentro de un proceso.

thread（hilo，线程）是操作系统能调度的最小执行单位：一条在进程内部并发执行的指令流。每个进程至少有一个线程，即 hilo principal (ES) / main thread (EN)——主线程，也就是执行 main 的那条。

同一进程的线程内容
共享代码、全局变量、函数里的 static 变量、堆（malloc 来的内存）、打开的文件、PID、信号处理方式
各自私有程序计数器 PC 和其他 CPU 寄存器、栈（所以局部变量是私有的）、线程号 pthread_t、调度优先级、errno、线程专有数据（TSD）

两个线程执行同一个函数时，函数里的局部变量各有一份（在各自的栈上）；但如果局部变量声明成 static，它就只有一份，两个线程共用。

和进程相比，线程的好处是"轻"：

  • 创建一个线程比创建一个进程快得多（常见的估计是一个数量级），结束也快：只需要删掉线程的上下文和栈，不用删整个进程的控制块。
  • 同一进程的两个线程之间切换更快：要换的只是 PC、几个寄存器和栈指针，不用换地址空间。它仍然是一次上下文切换，只是便宜得多。
  • 线程之间通信直接读写共享内存，不用每次都请内核帮忙。

代价也来自共享：没有隔离，一个线程写坏了内存或者崩溃，整个进程一起完蛋；共享的数据要自己保护（§5）。

线程可以由内核实现（内核知道每个线程，直接调度它们，能用上多核），也可以只在用户空间实现（一个进程在内部自己切换几条执行线，内核只看到一个进程：不用改操作系统，但用不上多核，一个线程阻塞在系统调用里，整个进程都会停）。Linux 现在的线程库是内核级的：每个 pthread 对应一个内核调度实体。

创建、结束和回收 T2.6

为什么要线程？想同时做另一件事，又不想把正在做的事扔下。普通的函数调用会让调用者停下来，等函数执行完才继续；pthread_create 让函数在一条新的执行线上开始运行，调用者自己马上往下走：

#include <pthread.h> int  pthread_create(pthread_t *tid, const pthread_attr_t *attr,                     void *(*funcion)(void *), void *arg);void pthread_exit(void *valor);int  pthread_join(pthread_t tid, void **valor);pthread_t pthread_self(void);int  pthread_equal(pthread_t t1, pthread_t t2);
  • tid：输出参数，存新线程的 identificador (ES) / thread ID (EN)——线程号。
  • attr：创建属性（优先级、调度策略、栈大小……），NULL 表示全部用默认值（§4）。
  • funcion：新线程要执行的函数，必须是 void *f(void *) 这个形状：一个 void * 参数，返回一个 void *。
  • arg：传给 funcion 的那个参数。要传多个值，就把它们放进一个结构体，传结构体的地址。
  • 返回值：成功 0，失败返回错误码（不是 −1，也不设 errno），用 strerror(err) 打印。

线程在三种情况下结束：从 funcion return；自己调用 pthread_exit(valor)；被同一进程的另一个线程取消（pthread_cancel）。前两种情况下，那个 void * 就是线程的"返回值"。另一个线程调用 pthread_join(tid, &r) 会阻塞，直到 tid 结束，然后把这个返回值放进 r。

例子：两个线程各算一半数组的和，主线程等它们算完再相加。参数和结果都放在各自的结构体里：

#include <pthread.h>#include <stdio.h>#include <string.h> typedef struct { const int *v; int n; long suma; } tarea_t; void *sumar(void *arg) {    tarea_t *t = arg;                      // void * → 真正的类型    t->suma = 0;    for (int i = 0; i < t->n; i++)        t->suma += t->v[i];    return t;                              // 等价于 pthread_exit(t)} int main(void) {    static int datos[1000];    for (int i = 0; i < 1000; i++) datos[i] = i;     tarea_t a = { datos, 500, 0 }, b = { datos + 500, 500, 0 };    pthread_t ha, hb;    int err = pthread_create(&ha, NULL, sumar, &a);    if (err) { fprintf(stderr, "create: %s\n", strerror(err)); return 1; }    err = pthread_create(&hb, NULL, sumar, &b);    if (err) { fprintf(stderr, "create: %s\n", strerror(err)); return 1; }     void *r;    pthread_join(ha, &r);                   // 阻塞到 ha 结束；r == &a    pthread_join(hb, NULL);                 // 不要返回值时传 NULL    printf("total = %ld\n", ((tarea_t *)r)->suma + b.suma);   // 499500    return 0;}

编译时要链接线程库：gcc -o suma suma.c -lpthread（或者用 -pthread，同时设置编译和链接选项）。交叉编译给 Raspberry Pi 时，把 gcc 换成工具链的编译器，选项不变。

三个容易犯的错

main 先走了：main 返回（或任何线程调用 exit）会结束整个进程，所有线程一起消失。要么 pthread_join 等它们，要么让 main 调用 pthread_exit(NULL)：只结束主线程，进程等其他线程结束后才退出。用 sleep 等是碰运气。

传了会变的地址：for (i = 0; i < 4; i++) pthread_create(&h[i], NULL, f, &i); 四个线程拿到的是同一个 i 的地址，读到的值取决于它们什么时候开始跑。每个线程要有自己的一份参数（数组元素、结构体）。

返回了栈上的地址：线程函数返回自己局部变量的地址，线程一结束栈就没了，join 拿到的指针指向无效内存。结果要放在调用者给的结构体里，或者用 malloc。

pthread_self() 返回调用者自己的线程号；比较两个线程号要用 pthread_equal(t1, t2)（相同返回非 0，不同返回 0），不要用 ==，因为 pthread_t 不保证是整数。

有时需要"每个线程各一份的全局变量"，叫 thread-specific data (TSD)——线程专有数据：用 pthread_key_create(&key, destructor) 建一把全进程共用的 key，每个线程用 pthread_setspecific(key, ptr) 挂上自己的数据、用 pthread_getspecific(key) 取回；线程结束时 destructor 负责释放。只建一次 key 的惯用法是 pthread_once。

线程共享全局数据和堆，各有自己的栈和寄存器。pthread_create 启动一个 void *f(void *) 函数，参数用结构体打包传地址；线程 return 或 pthread_exit 结束，pthread_join 阻塞等待并取回返回值。编译加 -lpthread；main 返回会带走所有线程。

§4调度：谁先用 CPU T2.7

十个线程都想跑，CPU 只有几个核。谁来决定，按什么规则？Scheduling: SCHED_FIFO, SCHED_RR, SCHED_OTHER.

内核里的 planificador (ES) / scheduler (EN)——调度器负责分配 CPU。从它的角度看，每个线程在任一时刻处于三种状态之一：

en ejecución · running

运行

正占着一个核执行。单核上同一时刻只有一个。

listo · ready

就绪

万事俱备，只差 CPU，在就绪队列里排队。

bloqueado · blocked

阻塞

在等某件事：sleep 到期、read 有数据、pthread_join、pthread_mutex_lock……事情发生后回到就绪，不占 CPU。

运行中的线程会因为三种原因让出 CPU：自己阻塞；被更高优先级的就绪线程抢占（preemption）；或者它的 quantum / time slice——时间片用完了。POSIX 定义了三种调度策略：

策略规则
SCHED_FIFO每个优先级一条队列；总是运行最高优先级队列里排得最久的那个。它一直运行，直到阻塞、主动让出（sched_yield）或被更高优先级抢占；同优先级的其他线程只能等。
SCHED_RR和 FIFO 一样按优先级，但多了一个时间限制：同优先级的线程每次最多用一个时间片，用完排到本优先级队尾，轮流执行（round-robin）。
SCHED_OTHER默认策略，具体做法由操作系统决定。Linux 上是分时调度：所有线程的静态优先级都是 0，按 nice 值和已经用掉的 CPU 时间公平分配。

FIFO 和 RR 是实时策略：在 Linux 上优先级取 1–99（数值越大越优先，可以用 sched_get_priority_min/max 查），而且任何就绪的实时线程都比 SCHED_OTHER 线程先运行。正因为实时线程能把普通线程饿死，设置它们需要超级用户权限。

下面看 SCHED_RR 下三个同优先级线程怎样分时间。规则只有一条：轮到谁，谁最多用一个时间片；没做完就排到队尾；剩下的工作不足一片，做完就让出。

在程序里设置策略和优先级

策略和优先级通过创建属性 pthread_attr_t 交给 pthread_create：

#include <pthread.h>#include <sched.h> pthread_attr_t attr;struct sched_param sp = { .sched_priority = 20 }; pthread_attr_init(&attr);                                  // 先全部设为默认值pthread_attr_setinheritsched(&attr, PTHREAD_EXPLICIT_SCHED); // 不继承创建者的策略pthread_attr_setschedpolicy(&attr, SCHED_RR);pthread_attr_setschedparam(&attr, &sp);                    // 注意传的是地址int err = pthread_create(&tid, &attr, trabajo, NULL);    // 没有权限时返回 EPERMpthread_attr_destroy(&attr);
  • Linux 默认让新线程继承创建者的调度设置，会忽略属性里的策略和优先级；所以要先用 PTHREAD_EXPLICIT_SCHED 关掉继承。
  • 运行中也可以改：pthread_setschedparam(tid, SCHED_FIFO, &sp)，读出用 pthread_getschedparam(tid, &pol, &sp)。
  • sched_yield()：调用者主动让出 CPU，调度器马上运行下一个同优先级的就绪线程；没有这样的线程，它就立刻返回、继续运行。更低优先级的线程不会因此得到 CPU。配合 SCHED_FIFO，可以写出线程之间互相礼让的协作式调度。

线程在运行、就绪、阻塞之间切换。SCHED_FIFO：按优先级，同级先来先跑、跑到阻塞或让出为止；SCHED_RR：再加一个时间片，同级轮转；SCHED_OTHER：默认的分时策略。实时策略要 root，并要关掉属性继承才生效；sched_yield 只让给同优先级。

§5竞争条件与互斥量 T2.8

两个线程各执行一次 count = count + 1，count 一定多 2 吗？Condición de carrera y sección crítica.

C 里的一行 count = count + 1;，到了 CPU 上是三条指令：从内存读进寄存器、寄存器加 1、写回内存。调度器可能在任意两条指令之间切换线程（多核上两个线程甚至真的同时在执行）。看两个线程撞在一起会发生什么：

condición de carrera (ES) / race condition (EN)——竞争条件：程序结果取决于几个线程执行的先后时机。访问共享数据、必须一口气做完不能被别人插进来的那段代码叫 sección crítica (ES) / critical section (EN)——临界区。解决办法是保证同一时刻最多只有一个线程在临界区里：exclusión mutua (ES) / mutual exclusion (EN)——互斥。POSIX 线程为此提供了 mutex——互斥量。

pthread_mutex：一把锁

互斥量是一个由系统管理的变量，表示"这份资源现在被某个线程占着"。用法永远是三步：lock → 临界区 → unlock。

#include <pthread.h> long contador = 0;                                   // 全局：所有线程共享pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;        // 静态初始化，默认属性 void *sumar_mucho(void *arg) {    for (int i = 0; i < 1000000; i++) {        pthread_mutex_lock(&m);                     // 进入临界区        contador++;        pthread_mutex_unlock(&m);                   // 离开临界区    }    return NULL;}// 两个线程都执行 sumar_mucho，join 之后 contador == 2000000。// 去掉 lock/unlock 两行再试：结果通常小于 2000000，而且每次不一样。
函数作用
PTHREAD_MUTEX_INITIALIZER声明时静态初始化，属性全用默认值。简单，能用就用它。
pthread_mutex_init(&m, &attr)在代码里动态初始化，可以给非默认属性；attr 为 NULL 时等同于默认。
pthread_mutex_lock(&m)拿锁；锁被别人占着就阻塞（线程睡眠），直到锁可用。成功返回 0。
pthread_mutex_trylock(&m)试着拿锁；锁空着就拿到并返回 0；被占着就立刻返回非 0（EBUSY），不阻塞。
pthread_mutex_unlock(&m)释放锁，唤醒一个等待者。成功返回 0。
pthread_mutex_destroy(&m)不再使用时销毁，释放资源。

互斥量的类型用 pthread_mutexattr_settype(&attr, tipo) 设置，区别在于"用错了"时的反应：

类型同一线程再次 lock解锁别人的锁 / 解锁未锁的锁
PTHREAD_MUTEX_NORMAL死锁（自己等自己）行为未定义
PTHREAD_MUTEX_ERRORCHECK返回错误返回错误
PTHREAD_MUTEX_RECURSIVE允许；锁几次就要解几次返回错误
PTHREAD_MUTEX_DEFAULT未定义未定义（通常等同 NORMAL）

默认的互斥量只在同一进程的线程之间用（PTHREAD_PROCESS_PRIVATE）。设成 PTHREAD_PROCESS_SHARED（pthread_mutexattr_setpshared）可以在进程之间用，但互斥量本身必须放在几个进程都能访问的共享内存里（mmap 或 shmat 得到的内存）。

锁只是约定

互斥量是建议性的，像交通信号灯：红灯提醒你停下，但路上没有栏杆。一个线程不调用 lock 就直接去改共享变量，没有任何东西能拦住它。所以规则要由程序员自己守住：每一处访问这份数据的代码，都要先拿同一把锁。

竞争条件来自"读-改-写"被其他线程插进来。把访问共享数据的代码放进临界区，用同一个 pthread_mutex 包住：lock 拿不到就睡，trylock 拿不到就返回，unlock 唤醒等待者。临界区要短，锁只是约定。

§6同步：等到条件成立 T2.9

缓冲区空了，消费者该怎么等？一直 lock、检查、unlock 地转圈吗？Variables condicionales, semáforos y productor–consumidor.

互斥量解决的是"别同时进来"。还有另一类问题："等某件事发生再继续"，比如消费者要等缓冲区里有数据。用互斥量反复检查（忙等）会白白烧 CPU。variable condicional (ES) / condition variable (EN)——条件变量让线程睡着等，直到别的线程告诉它"条件可能成立了"。

函数作用
PTHREAD_COND_INITIALIZER静态初始化；也可以用 pthread_cond_init(&c, NULL)，用完 pthread_cond_destroy。
pthread_cond_wait(&c, &m)调用前必须已经锁住 m。它原子地释放 m 并让线程睡在 c 上；被唤醒后重新拿到 m 才返回。进、出这个函数时，线程都持有 m。
pthread_cond_signal(&c)唤醒至少一个睡在 c 上的线程；没人在等就什么也不做（不会"记住"这次通知）。
pthread_cond_broadcast(&c)唤醒所有睡在 c 上的线程，让它们各自重新检查条件。
pthread_cond_timedwait(&c, &m, &t)和 wait 一样，但到了绝对时刻 t（struct timespec）还没被唤醒，就返回 ETIMEDOUT。
为什么一定是 while

被唤醒不等于条件成立：可能有另一个消费者抢先一步把数据取走了；被 broadcast 叫醒的线程只有一个能如愿；系统也允许 despertar espurio (ES) / spurious wakeup (EN)——虚假唤醒，即没人 signal 也醒了。所以条件变量的标准写法是 while (!条件) pthread_cond_wait(...)：醒来就重新检查，不成立就接着睡。

生产者–消费者

经典问题：一个或多个 productor (ES) / producer (EN)——生产者往一个大小为 N 的环形缓冲区里放数据，一个或多个 consumidor (ES) / consumer (EN)——消费者往外取。满了生产者要等，空了消费者要等。用一个互斥量加两个条件变量：

#define N 8int buf[N], ini = 0, fin = 0, n = 0;pthread_mutex_t m        = PTHREAD_MUTEX_INITIALIZER;pthread_cond_t  no_vacio = PTHREAD_COND_INITIALIZER;   // "有数据了"pthread_cond_t  no_lleno = PTHREAD_COND_INITIALIZER;   // "有空位了" void poner(int x) {                              // 生产者调用    pthread_mutex_lock(&m);    while (n == N)        pthread_cond_wait(&no_lleno, &m);    buf[fin] = x;  fin = (fin + 1) % N;  n++;    pthread_cond_signal(&no_vacio);    pthread_mutex_unlock(&m);} int tomar(void) {                                // 消费者调用    pthread_mutex_lock(&m);    while (n == 0)        pthread_cond_wait(&no_vacio, &m);    int x = buf[ini];  ini = (ini + 1) % N;  n--;    pthread_cond_signal(&no_lleno);    pthread_mutex_unlock(&m);    return x;}

顺序是：先在锁里改状态（n++），再 signal。等待的一方总是用 while 检查状态，所以 signal 和改状态谁先谁后（只要都在锁里）不影响正确性。几个线程在等不同的条件、或者一次放进很多数据时，用 broadcast 更稳妥。

带超时的等待要给绝对时间：

struct timespec t;clock_gettime(CLOCK_REALTIME, &t);t.tv_sec += 2;                                     // 最多等 2 秒pthread_mutex_lock(&m);while (n == 0) {    if (pthread_cond_timedwait(&no_vacio, &m, &t) == ETIMEDOUT)        break;                                     // 超时：n 可能仍是 0}pthread_mutex_unlock(&m);

信号量 sem_t

semáforo (ES) / semaphore (EN)——信号量是一个不会小于 0 的计数器，有两个原子操作：sem_wait（P 操作）把它减 1，已经是 0 就阻塞到别人加上来；sem_post（V 操作）把它加 1，唤醒一个等待者。初值为 1、只在 0 和 1 之间变化时，它就是一把锁；初值为 N 时，它数的是"还剩几份资源"。和条件变量不同，信号量记得每一次 post，即使当时没人在等。

函数（<semaphore.h>）作用
sem_init(&s, pshared, valor)初始化为 valor。pshared = 0：只在本进程的线程间用；非 0：进程间共享（要放在共享内存里）。
sem_wait(&s)s > 0 就减 1 返回；s = 0 就阻塞。sem_trywait 不阻塞，sem_timedwait 带绝对超时。
sem_post(&s)加 1，有线程在等就唤醒一个。
sem_destroy(&s)销毁。

用信号量写同一个生产者–消费者：一个信号量数空位，一个数数据，互斥量只保护下标：

#include <semaphore.h>sem_t huecos, datos;sem_init(&huecos, 0, N);                         // 一开始有 N 个空位sem_init(&datos,  0, 0);                         // 一开始没有数据 void poner(int x) {    sem_wait(&huecos);                            // 等一个空位    pthread_mutex_lock(&m);    buf[fin] = x;  fin = (fin + 1) % N;    pthread_mutex_unlock(&m);    sem_post(&datos);                             // 多了一个数据} int tomar(void) {    sem_wait(&datos);                             // 等一个数据    pthread_mutex_lock(&m);    int x = buf[ini];  ini = (ini + 1) % N;    pthread_mutex_unlock(&m);    sem_post(&huecos);                            // 多了一个空位    return x;}

注意 sem_wait 放在 lock 外面：如果先拿锁再在 sem_wait 上睡着，另一方就拿不到锁去 post，两边都卡住（这就是 §7 的死锁）。

条件变量：锁住、while 检查、不成立就 cond_wait（原子地放锁睡觉，醒来重新拿锁）；另一方改完状态 signal 或 broadcast。信号量：一个计数器，sem_wait 减、sem_post 加，适合数资源。生产者–消费者 = 互斥量保护缓冲区 + 两个"等待条件"（有空位、有数据）。

§7死锁与常见错误 T2.10

两个线程都在等对方先放手。谁会先放？Bloqueo mutuo (deadlock).

一个线程需要同时拿两把锁时，问题就来了。线程 1 先锁 A 再锁 B，线程 2 先锁 B 再锁 A：

另一种办法是"拿不到就退"：先拿一把锁，第二把用 pthread_mutex_trylock；拿不到就把手里那把也放掉，从头再来：

for (;;) {    pthread_mutex_lock(&B);    if (pthread_mutex_trylock(&A) == 0)        break;                          // 两把都拿到了    pthread_mutex_unlock(&B);          // 没拿到 A：放掉 B，让对方先走}/* 使用两份资源 */pthread_mutex_unlock(&A);pthread_mutex_unlock(&B);

这样不会死锁，但两个线程可能一直互相礼让、谁也做不成事，所以加锁顺序仍然是首选。

链接错误 undefined reference to pthread_create编译时少了 -lpthread / -pthread（§3）。
几个线程拿到同一个参数传了循环变量的地址 &i。每个线程给一份自己的参数（§3）。

程序卡住不动死锁：加锁顺序不一致；或者在持有锁时阻塞在别的等待上；或者 NORMAL 型互斥量被同一线程 lock 了两次。
忘了 unlock临界区里提前 return 或 break，锁没放。每条离开临界区的路径都要 unlock。

死锁 = 几个线程各持有一份资源、又在等别人手里的那份，形成环。预防：所有线程按同一顺序加锁；或者用 trylock 拿不到就全部放掉重来。持锁时间要短，持锁时不要去等别的事。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01父进程里 int x = 5;，然后 fork()。子进程执行 x = 9; 后退出，父进程 wait 之后打印 x。打印的是？

B。fork 复制整个用户空间，之后两份内存互相独立（§2）。线程才共享变量。

02在子进程里，fork() 的返回值是？

C。父进程得到子进程的 PID（> 0），子进程得到 0；−1 表示失败，只在父进程出现（§2）。

03execl("/bin/date", "date", (char *)0); 之后紧跟着一行 printf("listo\n");。什么时候会打印 listo？

D。exec 成功时当前程序被替换，不再返回；能执行到下一行说明 exec 失败了。想保留调用者，用 posix_spawn 或 fork + exec（§2）。

04同一进程的两个线程执行同一个函数。哪一种变量不是两个线程共享的？

A。普通局部变量在各自的栈上；static 局部变量只有一份，全局变量和堆也是共享的（§3）。

05main 调用 pthread_create 创建一个线程后，紧接着 return 0;。会怎样？

B。main 返回相当于 exit，进程连同所有线程一起结束。要等就 join，或让 main 调用 pthread_exit（§3）。

06线程函数最后执行 pthread_exit(p);。另一个线程怎样拿到 p？

C。pthread_join 的第二个参数是 void **，用来接收线程返回或传给 pthread_exit 的指针；函数本身返回 0 或错误码（§3）。

07SCHED_FIFO 和 SCHED_RR 的区别是？

D。两者都按固定优先级选线程；RR 只多了一个时间限制。默认策略是 SCHED_OTHER（§4）。

08两个线程各对全局变量 c（初值 0）执行 1000 次 c++，没有加锁。join 之后 c 的值是？

A。c++ 是读-改-写三步，交错时一次加法会被另一次覆盖（丢失更新），不会凭空多加（§5）。

09互斥量已经被另一个线程锁住，此时调用 pthread_mutex_trylock(&m)，会怎样？

B。trylock 是不阻塞的 lock：拿到返回 0，拿不到马上返回非 0（EBUSY）（§5）。

10调用 pthread_cond_wait(&c, &m) 时发生了什么？

C。进、出 cond_wait 时线程都持有 m；睡着期间 m 是放开的，另一方才能进来改状态（§6）。条件要由调用者自己用 while 检查。

11为什么 pthread_cond_wait 要写在 while (n == 0) 里，而不是 if (n == 0)？

D。醒来就重新检查，不成立就接着睡（§6）。

12T1 依次 lock(A)、lock(B)，T2 依次 lock(B)、lock(A)，程序偶尔卡死。最直接的改法是？

A。统一加锁顺序，等待关系就不会成环。RECURSIVE 只允许同一线程重复加锁，yield 和优先级只改变出现的概率（§7）。
