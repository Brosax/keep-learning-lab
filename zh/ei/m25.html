§1三种节点：autónomo、móvil、estático 2.5.1

节点在 prestaciones（性能）、conectividad（连接）、movilidad（移动性）、consumo（功耗）和 coste（成本）上差别很大。按这些差别，节点分成三类：

Kbps · µW–mW

Nodo autónomo

典型是环境传感器（温度、湿度）或识别类节点（RFID）。算力和存储都很低，却集成了很多技术：MEMS 传感器、recolector de energía (ES) / energy harvester (EN)——能量收集器、微控制器、射频模块。要能接入 WSN，还要经得起恶劣环境。以 microcontrolador 为核心。

Mbps · mW–W

Nodo móvil

智能手机、平板之类。要处理多媒体：音视频标准、信号处理、压缩，接入速率和 QoS 要求各不相同的网络。靠电池供电，所以能效非常重要。通用的 procesador de aplicaciones（应用处理器）配 DSP 和 GPU，集成在 SOC 里。

Gbps · W

Nodo estático

接市电的设备，例如服务器。速度和功耗都很高，承担人工智能、自然交互、3D 图形、分布式计算等任务。高性能的 GPP（通用处理器）、高性能图形子系统、大容量存储和网络连接。

有些资料正文把这一类叫 móvil，下面的结构图和对比表的标签写的是 portable，指的是同一类。estático 的速度和功耗都是 “muy alta”，量级是 Gbps 和 W。

把三类节点放进一个场景看：汽车、人和房子里散布着大小不同的点，点的大小代表功耗量级：大点 Watt（static），中点 milliWatt（mobile），小点 microWatt（autonomous）。虚线是节点之间的连接，最后通向 cellular network、road information backbone 和 internet backbone。

三类节点的内部结构：切换着看，留意哪些模块每一类都有，哪些模块是后两类才有的。

读图 · 三类节点的结构
  • 三类都有：处理模块、通信模块、电源模块（Battery、BMS、DC/DC）。
  • 只有 autónomo：直接面对物理量的 Sensor interface（Sensor、Ampl.、ADC），以及电源链里的 Solar cell 和 Capacitor（energy harvesting）。处理模块最小：µP/DSP、Timer、RAM/ROM，对应 autónomo 的“baja complejidad computacional y de memoria”。
  • portable 新增：多媒体的 A/V/D interface、Storage、两条射频链，对应 móvil 的“información multimedia”和“conectividad a redes diversas”。
  • estático：处理模块最大（多个 µP 和 DSP），通信多了有线连接，对应 estático 的“altos requerimientos de computación”和 LAN。

图中的缩写：BMS = Battery Management System（电池管理），DC/DC = 直流电压转换器，PLL = Phase-Locked Loop（锁相环，射频链里产生载波），PA = Power Amplifier（功率放大器）。

有些资料的结构图和对比表有两处对不上：结构图里 estático 的处理模块画的是 µP 和 DSP，对比表写的是 GPP、GPU；Power management 里画了 Battery，对比表写的供电是 red eléctrica。

要点 · 2.5.1

抓住一条线来区分：供电方式（energy harvesting/电池 → 电池 → 市电）定下了功耗预算，功耗预算又决定了处理器（微控制器 → DSP/GPU/SOC → GPP/GPU）和连接（WSN → WLAN/3G → LAN/WLAN）。

§2ARM 处理器家族 2.5.2

ARM 是设计 procesadores de aplicaciones（应用处理器）和微控制器的世界领导者，产品针对功耗和成本优化，覆盖几乎所有市场：IoT、嵌入式、手机、wearables（可穿戴设备）、domótica e inmótica（住宅和楼宇自动化）。本节末尾有一个小任务。

先弄清一点：ARM 本身不生产芯片。它设计处理器架构和处理器核，把这些 IP 授权给芯片厂商（ST、NXP、TI、Microchip、高通……），由它们做成具体的芯片。所以同一个 Cortex 核会出现在许多厂商的产品里。

Cortex-M · Microcontroller

面向微控制器。低功耗、低成本、面积小；中断响应快而且时间确定；通常没有 MMU（可以有 MPU），跑裸机程序或 RTOS。从最省电的 M0/M0+，到带 DSP 指令和可选浮点单元的 M4、性能最高的 M7，再到带 TrustZone 安全扩展的 M23/M33，以及面向机器学习的 M55/M85。

对应节点：nodo autónomo、简单的可穿戴设备。

实际芯片的例子：

  • Adafruit GEMMA M0 可穿戴开发板：Microchip ATSAMD21E18（Cortex-M0+），32 kB RAM、256 kB flash，取代了原来的 ATtiny85。
  • ST 的 STM32H753：Cortex-M7，400 MHz。2017 年时，M7 被称为 Arm 性能最高的嵌入式核。
  • Nordic nRF9160 开发套件：Cortex-M33，用于 LTE-M、NB-IoT 蜂窝 IoT 和 GNSS。

Cortex-R · Real-time

面向硬实时、高可靠的场合。响应时间确定，通常用 MPU（内存保护单元）而不是 MMU。典型用途：汽车电子（制动、安全气囊等控制器）、硬盘和 SSD 控制器、蜂窝 modem 的基带。例：R5、R52。

对应：它不对应 §1 三类节点中的哪一类，而是嵌在别的系统里做实时控制的 sistema empotrado（§3）。

Cortex-A · Application

面向应用处理器。性能高，有 MMU，能跑 Linux、Android 等完整的操作系统；常是多核，和 GPU（如 Arm 自己的 Mali）、DSP、modem 一起集成在 SOC 里。用于手机、平板、单板机、网关。

对应节点：nodo móvil，正是 §1 说的“procesadores de aplicaciones + DSP + GPU，集成在 SOC 里”。

实际芯片的例子：

  • Raspberry Pi 3 Model B 和 Qualcomm DragonBoard 410c：ARM Cortex-A53，1.2 GHz；BeagleBone Black：AM335X ARM Cortex-A8，1 GHz。
  • Eurotech ReliaGATE 10-12 IoT 网关：TI AM3352 Cortex-A8，1 GHz，1 GB RAM，整机 2 W。

Neoverse · Infraestructura

面向服务器、数据中心和网络基础设施的高性能核，追求多核扩展能力和每瓦性能。

对应节点：nodo estático。§1 的对比表只说 estático 用 GPP 和 GPU。

其他 Arm 产品

  • Classic（ARM7、ARM9、ARM11）：Cortex 之前的老一代核，新设计已经很少用。
  • SecurCore：面向智能卡和安全芯片。
  • Arm 也授权 CPU 以外的 IP：Mali（GPU）、Ethos（NPU，神经网络处理器，见 §4 的 NPU）。

Arm 的产品线经常更新，以官网为准。

小任务

看看 ARM 为 wearables 提供的方案，弄清它用的是哪类处理器。

离线做不了，这里给一个参考，以官网为准：简单的手环、健身追踪器主要用 Cortex-M（如 M0+、M4、M33、M55）；跑完整操作系统的智能手表用低功耗的 Cortex-A，并常配一颗 Cortex-M 做传感器协处理（sensor hub）。上面例子里的 GEMMA M0（Cortex-M0+）就是一块面向 wearables 的开发板。

要点 · 2.5.2

区分 ARM 家族就看用途：A = 应用处理器（MMU、完整操作系统，手机、平板、单板机）；R = 实时（确定性、高可靠，汽车、存储控制器）；M = 微控制器（低功耗、低成本，裸机或 RTOS，传感器节点）。服务器级的是 Neoverse。

§3Microsistemas：通用与专用 背景

按应用，电子系统分成两类：propósito general（通用）追求灵活、可扩展、高性能和较短的硬件开发周期；propósito específico（专用）为具体应用专门设计，通常优化体积、功耗和成本。

下图把两类系统画成同样的三个单元，挂在一条总线上：UCP（处理）、UCM（存储）、UES（输入输出）。差别在每个单元里装的东西。点击一个单元，对比两边：

UCP · 处理单元

  • General：几个叠在一起的 µP（多核），外加 Caches SRAM。也就是：通用处理器，处理、寻址和内存管理能力强（§4 GPP 的微架构里就有 cache）。
  • Específico：只有一个 µP，没有 cache。这和 §4 的 MCU 一致：为了确定性响应，MCU 一般避开 cache、推测执行这类预测性机制。

UCP = Unidad Central de Proceso（中央处理单元）。

UCM · 存储

  • General：Flash 用于 arranque（启动），DRAM 放 S.O. y aplicaciones（操作系统和应用）。也就是下面说的：非易失的 Flash NOR 用于启动和初始化，易失的 DDR DRAM 放操作系统和应用程序。
  • Específico：Flash NOR 放 programa（程序本身），SRAM 放 variables（变量）。没有操作系统要装，程序直接从 Flash 运行；和 §5 MCU 框图里的“Memoria de programa · Tipo Flash”“Memoria de datos · Tipo SRAM”是同一个意思。

对比记忆：通用系统的 Flash 只管开机，程序搬进 DRAM 跑；专用系统的程序一直在 Flash 里。

UES · 输入输出

  • General：外接常规外设，图里画的是电话、打印机、显示器；常规外设指键盘、鼠标、显示器、打印机、网络连接，走标准 E/S 接口（PCI Express、USB、SATA）。图在这个单元里写的是 “Caches DRAM”。
  • Específico：直接连到它所控制的系统：Sensores、Actuadores、Motores、Videocámara、Teléfono…；单元里有 Flash NAND。

按上下文，UCM 是存储单元，UES 是 E/S 单元（Entrada/Salida）。NAND Flash 常用来存大量数据。

Propósito general · 例：PC
  • 通用处理器，处理、寻址和内存管理能力强。
  • 非易失的 Flash NOR 存启动代码，易失的 DDR DRAM 放操作系统和应用。
  • 高集成度 chipset 连接处理器、存储器和图形、音频、高速通信等子系统，并产生 E/S 总线（现在内存控制器已集成进处理器）。
  • 有操作系统，让应用和硬件解耦；外设用标准接口（PCI Express、USB、SATA）。
Propósito específico
  • sistema empotrado (ES) / embedded system (EN)——嵌入式系统：通常装在它所控制的另一个系统里（不一定，关键是“专用”）。
  • 有的专做 procesado de control（实时仲裁大量事件），有的专做 procesado de señal（对数据流做密集计算），也有介于两者之间的器件。
  • 占处理器市场的 90% 以上。典型例子：微控制器，以及近年的 SOC。

§4Partición HW/SW 与设计方案 2.5.4

今天设计一个可编程电子系统时，硬件和软件能实现的功能没有本质区别。某个功能用 lógica cableada（硬连线逻辑，即硬件）还是用处理器代码（软件）来做，多数时候只是在几个设计指标之间权衡：prestaciones（性能）、consumo（功耗）、tamaño（尺寸），尤其是 flexibilidad（灵活性）。所以 partición hardware/software (ES) / hardware/software partitioning (EN)——软硬件划分，是得到最优设计最关键的步骤之一。

下面这张图把各种方案放在一起：横轴是 programmability（可编程性，从 Inflexible 到 Flexible），纵轴是 peak performance（峰值性能，MIPS，对数刻度），每个椭圆旁边的数字是能效（MIPS/mW）。点击椭圆读它的位置：

ASICs · 左上角

最不灵活，峰值最高（读图约 10⁴·⁵–10⁵·⁴ MIPS），能效 1000 MIPS/mW，全图最高。原因是它只有解决某个问题所需的硬连线逻辑，所以计算效率约为 GPP 的 1000 倍。

TPUs · 紧挨 ASICs

也在 Inflexible 一端，峰值仅次于 ASIC（读图约 10³·⁶–10⁴·⁶ MIPS）。TPU 本身就是为深度学习设计的 ASIC，所以位置挨着 ASIC。图上没标能效。

PLAs · Coarse-grain · Domain LAs

  • PLAs：100 MIPS/mW。
  • Coarse-grain Adaptable Architectures（图中举例 RaPiD、PipeRench）：10 MIPS/mW。
  • Domain LAs（图中举例 RSVP、VEAL、CGRAs）：5–10 MIPS/mW。

这三种加速器只出现在图里，本章没有展开讲，也不在 学习目标 里。图里的 LA 应是 loop accelerator（循环加速器），PLA 应是 programmable loop accelerator，不是可编程逻辑阵列。

FPGAs · 中间偏灵活

峰值跨度很大（读图约 10²·⁴–10³·⁹ MIPS），正上方标的是 1–10 MIPS/mW。FPGA 能重新配置自己的硬连线逻辑；位级并行时性能很高，并行度有限、运算复杂时效率不高，这也许就是它在纵轴上拉得这么长的原因。

图上这个 “1–10 MIPS/mW” 标在 FPGAs 上方、GPUs 左边，按位置归给 FPGAs。

GPUs · 右上

相当灵活（shader 可由用户编程），峰值很高（读图约 10³·⁴–10⁴·⁵ MIPS），在可编程的方案里最高。原因是成千上万个核按 SIMD 大规模并行。图上没标能效。

ASIPs

中等可编程性，峰值约 10²–10³ MIPS，能效 1–10 MIPS/mW。比 GPP 不灵活一点（要为应用改硬件），换来高一个数量级以上的峰值和能效。

DSPs

比 ASIP 更靠灵活一侧，峰值约 10²–10²·⁸ MIPS，能效 1–5 MIPS/mW。专长信号处理，所以在这个领域比 GPP 高效。

GPPs · 右下角

最灵活，但峰值只有约 10¹–10² MIPS，能效 0.1–1 MIPS/mW，全图最低。原因是实现可编程性所需的微架构硬件很耗电，所以计算效率低。

µCs · 最底下

贴着 GPP、在灵活一侧，峰值性能最低（约 10¹ MIPS 出头）。uCs 也属于两端之间的方案，专长事件控制；图上它的位置说明：MCU 不靠峰值算力取胜，而是靠低功耗、低成本和确定性响应（§5）。图上没标能效。

读图 · 性能、能效与灵活性
  • 两端：ASIC 左上（不灵活、峰值最高、1000 MIPS/mW），GPP 右下（最灵活、0.1–1 MIPS/mW）。两者能效差 1000–10 000 倍；上面 ASIC 的说明里“计算效率约为 GPP 的 1000 倍（1000 veces）”，对应的是 GPP 的上限 1 MIPS/mW。
  • 大致规律：越不灵活，峰值和能效越高。GPU 是例外，比较灵活，峰值也很高。
  • 能效从高到低：ASIC 1000 → PLA 100 → coarse-grain 10 → domain LA 5–10 → FPGA、ASIP 1–10 → DSP 1–5 → GPP 0.1–1（MIPS/mW）。
  • ASIC (Application-Specific Integrated Circuit)——专用集成电路：解决非常具体的问题时性能最高、功耗最低，但规格一变就很难快速适应。
  • GPP (General Purpose Processor)——通用处理器：能效很差，有时还达不到系统的性能要求。
  • 两者之间的折中方案想兼顾处理器的灵活和 ASIC 的效率，但不一定做得到：DSP、GPU、ASIP、FPGA、TPU。

这几种方案各有专长：uCs、DSP、GPU、TPU respectivamente（分别）专长于事件控制、信号处理、图形渲染和深度学习；FPGA 能重新配置自己的硬连线逻辑。配对：先点左边的方案，再点右边它的专长。

逐个看：点一个方案读要点。带 ★ 的是目标 2.5.4 点名要区分的五种。

GPP · microprocesador

集成在一颗芯片上的中央处理器（UCP），是 PC 这类应用平台的核心，能执行任何程序。为了这种灵活性，它的指令集越来越强大多样，寻址能力也很大。为提高性能，时钟从 KHz 升到 GHz，寄存器从 4 位经过 8、16、32 位到 64 位；微架构也越来越复杂：内存管理单元、cache、超流水线、分支预测、浮点和多媒体指令、超标量、推测执行、多核、虚拟化……

目标 2.5.4

Microcontrolador · MCU

集成在一颗芯片里的小型可编程数字系统，专用，专长于控制处理。通常工作在实时条件下，要给出确定的响应，所以一般避开微处理器的预测性机制（cache、推测执行），用很快的上下文切换，在几个时钟周期内检测并响应外部事件；通常直接访问硬件，不用操作系统（有时用 RTOS）。

外设很丰富：定时器、并口、串口、PWM、ADC；不少还有 Ethernet、CAN、USB、射频接口或图形控制器，甚至智能卡读卡、MP3 解码、电池充电监测。还有集成 DSP（这种叫 DSC (Digital Signal Controller)）或 FPGA 的混合型 MCU。8 位和 32 位的区别见 §5。

目标 2.5.4

DSP · Digital Signal Processor

专门做信号处理的处理器，架构为实时、密集地处理数据流而优化。通常不用操作系统（用的话是 RTOS），以便把代码效率压到极致。

信号处理要求不高时，可以用 procesadores unificados（统一处理器）：在同一个执行引擎里结合微处理器和 DSP，例如很多微处理器里的多媒体指令。好处是降低成本和复杂度（不必做多处理器系统），开发也更简单。

GPU · Graphics Processing Unit

专门执行大量非常简单、重复的任务，架构大规模并行：成千上万个 core 按 SIMD（Single Instruction Multiple Data，一条指令同时作用于很多数据）方式成组工作，这种结构叫 SM（Streaming Multiprocessor）。在核心上运行的用户程序叫 shader，每次处理一个像素、顶点或几何元素，用 HLSL（DirectX）、GLSL（OpenGL）、Cg（NVIDIA）等高级语言编写。核心有不同类型：INT32（整数）、FP32（浮点）、tensor cores（深度学习）、RT cores（实时光线追踪）。

目标 2.5.4

FPGA · Field Programmable Gate Array

可编程、可重构的逻辑器件，能实现从简单逻辑函数到复杂数字系统的各种电路。位级并行计算性能很高（典型应用：数据加密），但对并行度有限、运算复杂的应用效率不高。很适合小批量生产、短开发周期。

新一代 FPGA 能通过授权、复用 IP (Intellectual Property)——知识产权核，集成处理器、控制器和标准外设（USB、PCI、Ethernet）。处理器分两种：

  • hard core（硬核）：嵌进 FPGA 的已知架构处理器，例如 Xilinx 的 PowerPC、Altera 的 ARM。
  • soft core（软核）：用 FPGA 自己的逻辑资源实现，例如 Altera 的 NIOS、Xilinx 的 MicroBlaze。可以多次实例化，比 hard core 更灵活、更便宜，但性能通常较低。
目标 2.5.4

ASIP · Application Specific Instruction-set Processor

可配置处理器：允许修改硬件以适应某个具体应用的微处理器。可以加入新的专用指令和数据类型、所需宽度的特殊寄存器，以及为定制算法设计的专用执行单元。这样，所需时钟频率比 GPP 低，也不必用外部硬件加速。有高层次设计工具，生成可综合的代码，可以在 FPGA 和 SOC 上实现。例：Cadence、Synopsys 的可配置处理器。

目标 2.5.4

SOC · System On Chip

也把系统集成进一颗芯片，但和 MCU 不同，它能实现完整的通用系统，还能集成模拟器件、传感器和射频单元。通常用一个或多个高性能处理器，跑操作系统（Linux、Windows CE 等），需要外部存储器和标准外设接口。

  • SIP (System In Package)——系统级封装：SOC 的一种变体，把几颗芯片压进一个封装。
  • MSOC (Multiprocessor System-on-Chip)——多处理器片上系统：几十甚至上百个核，用于大规模并行的密集计算（超级计算）。

TPU · Tensor Processing Unit

专为深度学习设计的 ASIC。要做的主要是数据量极大、精度较低的矩阵运算。

NPU · LPU

AI 热潮带来了 NPU (Neural Processing Unit)：直接集成在消费级处理器（手机、笔记本）里的小型 ASIC，为人工神经网络优化；以及 LPU (Language Processing Unit)：为大语言模型（LLM）优化。未来还有模仿人脑结构和工作方式的 chips neuromórficos（神经形态芯片），以及光子计算。

想深入可以读一篇神经网络硬件加速的综述，文献见本节末尾的资料。

按需求选方案：读每个场景，从五种方案里选最合适的一个。

要点 · 2.5.4
  • MCU：单芯片、控制处理、确定性实时，片上外设丰富，通常不用操作系统。
  • DSP：实时、密集处理数据流（信号处理），通常不用操作系统。
  • FPGA：可重构的硬件，位级并行强，适合小批量和短开发周期；可放 hard core 或 soft core。
  • SOC：整套通用系统上一颗芯片：高性能处理器 + 操作系统 + 外部存储，还能集成模拟、传感器、RF。
  • ASIP：能扩展指令、寄存器和执行单元的可配置处理器，按应用定制。

§58 位与 32 位微控制器 2.5.3

市面上的 MCU 数量庞大，厂商还常给同一型号出几十个版本，尽量贴合客户的需求。按位数分，有 4、8、16 和 32 位。

定义 · 位数

MCU 的位数指它基本寄存器的宽度。

Control de sistema · 系统控制

  • Control de interrupciones（中断控制）：对应 §4 说的，MCU 用很快的上下文切换，在几个时钟周期内检测并响应外部事件。
  • Control de depurado（调试控制）、Protección y seguridad（保护与安全）、Gestión de energía（能源管理）：图里只列了名字。调试控制让开发工具能在芯片上设断点、单步执行；保护与安全包括看门狗、内存保护、加密等；能源管理负责时钟和低功耗模式（比如 §6 Waspmote 的 Sleep、Hibernate）。

IoT 带来了集成加密安全区（zonas seguras criptográficas）的 MCU，这就属于 “Protección y seguridad” 这一块。

2.5.3

Procesador · 处理器

Lógica de control（控制逻辑）+ Registros（寄存器）+ Unidad Aritmético Lógica（ALU，算术逻辑单元）。说 MCU 是 8 位还是 32 位，指的就是这里基本寄存器的宽度。

Memoria · 存储器

Memoria de programa · Tipo Flash（程序存储器，Flash）和 Memoria de datos · Tipo SRAM（数据存储器，SRAM）。和 §3 架构图里专用系统的 “Flash NOR → programa、SRAM → variables” 一致。还要记住：存储器在 MCU 里是“稀缺品”，所以代码密度很重要。

例：Waspmote 的 ATmega1281 是 128 KB Flash、8 KB SRAM（§6）。

Entrada/Salida · 片上外设

  • Puertos paralelo（并口）、Comunicaciones serie（串行通信）、Interfaz analógico（模拟接口，ADC 等）。
  • Moduladores de anchura de pulsos：PWM，向外输出。
  • Contadores de eventos：数外部事件，从外部输入。PWM 和事件计数器都连到 Contadores（计数器），后者再连 Temporizadores（定时器）。

MCU 的标准外设也就是这几样：temporizadores、puertos paralelo、puerto serie、PWM、ADC。

图里没画的可选模块：Ethernet、CAN、USB、射频接口、图形控制器；还有集成 DSP（DSC）或 FPGA 的混合型 MCU。

切换看两类的典型特征，以及几颗实际的芯片：

  • 速度高：每秒几千万条指令（decenas de millones de instrucciones por segundo）。
  • densidad de código (ES) / code density (EN)——代码密度高：同样的程序占用的存储器更少，而存储器在 MCU 里是“稀缺品”。
  • 工艺成熟：芯片便宜、功耗很低，开发工具简单、便宜。
  • 编程已从汇编转向 C 这类高级语言：可移植、可复用，靠编译器优化，代码效率损失不大。

4 位 MCU 很便宜，适合简单应用，但架构限制了算力，正在被 8 位取代。

实际的 8 位芯片：

  • ATmega1281：Waspmote 的 MCU，14.7456 MHz，8 KB SRAM、128 KB Flash，属于 8 位 AVR 系列。
  • ATmega 128：Gator 智能屋（见下面的 小任务）传感器平台的处理模块，8 位（an 8-bit Atmel ATmega 128）。
  • ATMega328PU：Arduino Uno 的 8 位 MCU，时钟 16 MHz。
  • 用在需要更高算力和更多存储的地方：工业控制、汽车电子、数据加密、联网、多媒体（音频、图像、视频）。
  • 复杂度高，常要引入 RTOS (Real Time Operating System)——实时操作系统，因此需要更多存储器。
  • 32 位的价格已经降到接近 8 位，迁移越来越容易、越来越划算。
  • 但设计者不愿更换开发工具、放弃成熟高效的代码，因为这两点都影响开发时间和成本；于是很多厂商开发了帮助迁移的新工具。

实际的 32 位芯片：

  • STM32F205（32 位，120 MHz）：Particle Electron，集成蜂窝 modem；Tensilica L106（32 位，80 MHz）：ESP8266-01，集成 WiFi。
  • ATSAMD21E18（Cortex-M0+）：GEMMA M0 用它取代了原来的 ATtiny85，三个 GPIO 焊盘沿用原名，现有的 Arduino 代码不用改就能跑。这正是上面说的“厂商帮助迁移”的一个例子；原来的 ATtiny85 是 8 位 MCU。
  • STM32H753（Cortex-M7，400 MHz）：见 §2。

8 还是 32？每条特征属于哪一类？

新趋势：IoT 带来了集成各种射频收发器和加密安全区（zonas seguras criptográficas）的 MCU；AI 带来了带专用硬件加速器的 MCU。开源架构 RISC-V 的兴起也很值得关注。

小任务

读 Gator 智能屋（“The Gator tech smart house: A programmable pervasive space”）的 SENSOR PLATFORM 一节。§6 的节点架构图沿用这个传感器平台的模块化结构，方框里换成了 Waspmote 的规格。文献见本节末尾的资料。

要点 · 2.5.3

8 位：快（几十 MIPS）、代码密度高、便宜、功耗低、工具简单，C 语言编程。16/32 位：算力和存储更强，用于工业、汽车、加密、联网、多媒体，常配 RTOS、需要更多存储；价格已接近 8 位，但迁移有工具和存量代码的阻力。

§6读一份 WSN mota 的规格 2.5.5

WSN 的 mota 就是 §1 说的 nodo autónomo。这一节拿 Libelium Waspmote V1.2 的规格书做例子（§3 的 小任务）。分析时可以用一个框架：一个 IoT 设备可以用四种能力来描述。

1

Data acquisition and control

采集与控制：传感器、ADC 分辨率（10 位 = 1024 个值）、GPIO 和总线（I2C、SPI、UART）。

2

Data processing and storage

处理与存储：处理器的时钟和核数决定处理速度，非易失 flash 的容量决定离线时能存多少数据。

3

Connectivity

连接：WiFi、Bluetooth、RFID、蜂窝、LPWAN（LoRa、SigFox、NB-IoT），或有线的 Ethernet、UART、CAN。

4

Power management

电源管理：靠电池或太阳能的设备，要周期性进入 sleep 或低功耗模式。

整板数据

重量 20 g，尺寸 73.5 × 51 × 13 mm，工作温度 [−10 ºC, +65 ºC]。对比一下：单板机 Raspberry Pi 3 典型工作电流约 700–1000 mA，是 Waspmote ON 状态 15 mA 的 47–67 倍。

读规格书的几个习惯：

  1. 看脚注和条件。“Operation without recharging: 1 year” 带星号：用 Hibernate 作省电模式时才成立；XBee 的距离是在视距、5 dBi 天线的条件下给的。
  2. 分清整板和单个器件。板载温度传感器能测 −40 到 +85 ºC，整板的工作温度却只有 −10 到 +65 ºC。
  3. 盯住单位和量级。mA 和 µA 差 1000 倍：ON 的 15 mA 约是 Sleep 55 µA 的 270 倍。
  4. 比较 MCU 功耗别只看 µA/MHz。µA/MHz、µA/MIPS 这类指标都不太准，因为没考虑 CPU 架构，每个周期做的事不一样。
  5. 睡得多的节点，看待机电流和唤醒时间。应用大部分时间在睡、周期性醒来时，待机功耗是主导因素；占空比很低的系统，MCU 还要能在几微秒内醒来。

Datasheet 挑战：每题都能在上面的规格里找到答案。

估一估：一节电池能撑多久？用平均电流公式：平均电流 = 各状态的电流 × 时间之和 ÷ 周期。电流都取规格书里的数字，改一改参数看看谁在耗电。

理想估算：忽略传感器、唤醒过程、电池自放电和温度的影响；假设无线模块工作时，它的电流叠加在 ON 的 15 mA 上。默认参数算出来接近一年只是巧合，规格书没写 “1 year” 用的是什么占空比。电池续航的完整计算见 M26 Consumo energético。

要点 · 2.5.5

分析 mota 的规格：按采集与控制、处理与存储、连接、电源四块逐项找数字，再对照应用检查：工作条件（温度、距离的测量条件）、各模式的电流和占空比、无线的灵敏度、速率和消息限制、本地存储够不够离线记录。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01按 §1 的对比表，nodo autónomo 的典型速度和功耗是？

A。Mbps · mW–W 是 portable（móvil），Gbps · W 是 estático（§1 对比表）。

02nodo móvil（智能手机、平板）通常用什么处理器？

C。nodo móvil 的处理器是 procesadores de aplicaciones combinados con DSP y GPU, integrados en SOC；§1 对比表里写的是 DSP, GPU, SOC。

03一个靠电池供电、要求低功耗和确定性中断响应的 WSN 节点，最可能用哪个 Arm 家族？

B。Cortex-M 面向微控制器（§2）。§2 的例子里，可穿戴开发板 GEMMA M0 用的就是 Cortex-M0+。Cortex-A 面向跑完整操作系统的应用处理器，Neoverse 面向服务器，Mali 是 GPU 而不是 CPU。

04Raspberry Pi 3 和 DragonBoard 410c 用的处理器是？

A（§2，Cortex-A 的例子）。Cortex-M7 在 STM32H753 里，ATMega328PU 是 Arduino Uno，Tensilica L106 是 ESP8266（§2、§5）。

05说一个微控制器“是 8 位的”，指的是什么？

D。位数指基本寄存器的宽度：El número de bits se refiere al tamaño de sus registros básicos（§5）。

06下面哪一项是 §5 列出的 8 位 MCU 的典型特征？

B。A、C 是 16/32 位的特点；D 反了：32 位的价格已经接近 8 位（§5）。

0732 位 MCU 已经和 8 位差不多便宜，为什么很多设计者还不迁移？

C。这两点都影响开发时间和成本，所以很多厂商推出了帮助迁移的工具（§5）。

08“可以加入专用指令、专用寄存器和执行单元，以适应某个具体应用的处理器”是？

A。ASIP 能以比 GPP 更低的时钟完成任务，不用外部硬件加速（§4）。SIP 是把几颗芯片装进一个封装。

09关于 FPGA 里的 hard core 和 soft core，哪一项正确？

C。hard core 是嵌进 FPGA 的已知架构处理器（如 Xilinx 的 PowerPC、Altera 的 ARM），soft core 如 NIOS、MicroBlaze（§4）。

10哪种方案专为“实时、密集地处理数据流”而优化，通常不用操作系统？

D（§4）。GPU 擅长大规模并行的简单重复任务，TPU 做数据量大、精度低的矩阵运算，FPGA 擅长位级并行。

11Waspmote 的规格书里，哪一句是对的？

B（§6 的电源管理）。Hibernate 是 0.07 µA，ON 是 15 mA。

12Waspmote 的 LoRa 模块（SX1272）和 LoRaWAN 模块是什么关系？

D。规格书写的是 “Own, developed at Libelium. Not compatible with LoRaWAN.”；LoRaWAN 模块是 LoRaWAN 1.0 Class A。灵敏度 LoRa −137 dBm，还略好于 LoRaWAN 的 −136 dBm（§6）。
