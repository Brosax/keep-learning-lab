§0传一个字节，要几根线？ M33.1

要把一个字节送给外设，可以一次全送过去，也可以一位一位地送。¿Interfaz paralela o interfaz serie?

  • interfaz paralela (ES) / parallel interface (EN)——并行接口：每一位信息用一根物理线，整段时间都占用这根线。
  • interfaz serie (ES) / serial interface (EN)——串行接口：多位信息共用一根线，一位接一位地传；每一位在线上停留的时间叫 tiempo de bit (ES) / bit time (EN)——位时间。

串行接口有一批已经标准化的类型，微控制器通常会把实现主要标准所需的硬件集成在片内（§3）。

串行的优点

  • 需要的线更少
  • 芯片需要的引脚更少
  • 简化 PCB 设计
  • 电路改动更简单
  • 有些串行接口允许多个外设接在同一组线上

缺点

串行总线比并行总线慢。

直观理解：同样一个字节，并行一次送完，串行要排队送 8 次（见上面的动画）。

并行 = 一位一根线、同时送；串行 = 一根线、一位接一位，每位占一个 tiempo de bit。串行用速度换来了线、引脚和 PCB 上的简单。

§1时钟传不传？ M33.2

一串 0 和 1 到了接收端。它怎么知道哪一刻该读下一位？Comunicaciones síncronas y asíncronas.

先记住一句很关键的话：任何数字通信都需要一个时钟，发送端用它决定什么时候送下一位，接收端用它决定输入端的数据什么时候有效、可以读。区别只在于这个时钟从哪里来。

  • comunicación síncrona (ES) / synchronous (EN)——同步通信：时钟信号随数据一起传输。
  • comunicación asíncrona (ES) / asynchronous (EN)——异步通信：不传时钟，收发双方各用自己的时钟，事先约定频率，并用某种方法同步。

同步：时钟随线送过去，至少 3 根线。异步：只送数据，至少 2 根线，代价是两边要约好频率、自己对齐。

§2朝哪个方向？ M33.3

两台设备要互相说话。一根数据线够不够？Símplex, semi-dúplex y dúplex.

类型方向最少线数例子
símplex只有一个方向2：datos + masaUART unidireccional
semi-dúplex双向，但不同时2：datos + masaI2C
dúplex双向，可以同时3：2 × datos + masaSPI，UART bidireccional

半双工和全双工的分界就是数据线的根数：一根只能轮流，两根才能同时。

§3两个同步接口：SPI 与 I2C M33.4

一根时钟线挂着好几个设备。它在跟谁说话？Interfaces serie síncronos SPI e I2C.

微控制器最常集成的串行标准有两类：同步的 SPI、I2C，和异步的 UART。两个同步接口用途相近，规则相同：产生时钟的设备是 maestro (ES) / master (EN)——主机，接收时钟的是 esclavo (ES) / slave (EN)——从机。不同的是"选中从机"的办法。这里只讲概念。

I2CSPI
时钟maestro 产生（同步）maestro 产生（同步）
选中从机每个设备有地址，maestro 发出地址选择线（línea de selección）
数据线1 根 → semi-dúplex2 根 → dúplex
信号datos、reloj、tierra 三根比 I2C 多
协议控制起止条件、读/写位、每字节一个 ACK没有地址，没有确认
特点为连接大量设备设计更简单、更快，适合大量数据

微控制器还在加入其他串行接口 / 总线：USB（Universal Serial Bus）、CAN（Controller Area Network）、LIN（Local Interconnect Network）。本课只要知道名字，不展开。

I2C 靠"地址 + 确认"在少量线上挂很多设备；SPI 靠"选择线 + 两根数据线"换来简单和速度。剩下那个异步的 UART，是这一章的主角。

§4一帧 UART M33.5 · M33.6

没有时钟线，接收端怎么知道"一个字符从这里开始"？La estructura de un carácter o trama.

UART 定义了实现异步串行通信的物理接口，典型应用是 PC 和微控制器之间的通信。按定义，UART 是双向、全双工、不传时钟的通信，一个字符一个字符（一帧一帧）地传；帧与帧之间的间隔没有规定，但帧内部的时序是刚性的：每一位占一个 tiempo de bit，各位的顺序也永远不变。

所以收发双方必须事先约定下面 4 个参数，配置 UART 外设的程序要把它们全部设置好（怎样设置见 M34）：

要约定的 4 个参数

  1. 速率（velocidad de transmisión/recepción），单位 baudio (ES) / baud (EN)——波特；它决定 tiempo de bit
  2. 数据位数：7 或 8
  3. 校验：有没有校验位
  4. 停止位数：1 或 2

baudio 和 bit/s

1 baudio = 信号每秒变化 1 次。UART 的编码方式下，线上每个"信号单元"就是一位，所以这里 波特数 = 每秒位数，tiempo de bit = 1 / baudios。

动手：帧构造器

输入一个字符，改数据位、校验、停止位和波特率，看 TX 线上的波形和时间。打开"RX 采样"能看到接收端在哪里采样（§5）；拖动偏差滑块，模拟接收端时钟偏快或偏慢（§6 详解）。

一帧要多久 M33.6

每一位都占一个 tiempo de bit，所以只要数清一帧有几位：

N = 1 + n_d + n_p + n_s　　T_bit = 1 / v　　t = n_car · N / v

N：每帧位数（1 个起始位 + nd 个数据位 + np = 0 或 1 个校验位 + ns = 1 或 2 个停止位）；v：速率（baudios）；ncar：字符数。帧与帧之间没有空闲时，t 是最短时间。

例 · 9600 baudios，8 个数据位，无校验，1 个停止位

N = 1 + 8 + 0 + 1 = 10 位；Tbit = 1 / 9600 s ≈ 104.2 µs；一帧 ≈ 1.04 ms，每秒最多约 960 个字符。数据位只占 8 / 10 = 80 %，其余 20 % 是起始位和停止位的开销（sobrecarga）。

练习里会出现 8N1、8E1 这样的缩写：数据位数 + 校验（N 无、E 偶、O 奇）+ 停止位数。

一帧 = 起始 0 + 数据（低位先）+（校验）+ 停止 1，全部按同一个 tiempo de bit。速率、数据位、校验、停止位四个参数，两边必须一致。

§5发送器与接收器 M33.7

发送端按自己的时钟把位推出去；接收端没有这根时钟线，它怎么踩准节拍？Esquema general del transmisor y receptor de la UART.

发送端：b7…b0 并行装入移位寄存器（两端固定起始位 0、停止位 1）→ 启动命令开动振荡器 → 逐位移出，b0 在前。接收端：下降沿检测器启动自己的振荡器 → 在每一位中间采样 → 移位寄存器 → 计数器确认收齐 → 并行输出。起始位和停止位建立并保持两边共同的时间基准，这就是 §1 说的"同步策略"。

§6两个时钟差一点点 M33.8

接收端的时钟只慢了 3%。读到第 10 位时，采样点偏了多远？Deriva entre relojes y mayoría de voto.

接收端的时钟只在起始位的下降沿对齐一次，之后就自己走。收发时钟之间的deriva (ES) / drift (EN)——偏差，会让对线路的采样读到错误的值。偏差每一位都在累积，所以一帧越往后越危险。

偏差为什么是"5% 左右"

结论：收发双方不但要约定速率，还要尽可能长时间地保持它不变；时钟之间的偏差超过 5%，解码就可能出错。下面的推导只是帮助理解这个数从哪里来：

t_k = (k + ½)·T_bit·(1 + e) ⇒ |e| < 1/(2k+1)；最后一位 k = N − 1 ⇒ |e| < 1/(2N − 1)

从起始位的下降沿算起，接收端第 k 位（起始位 k = 0）的采样时刻是 tk。e 是接收端 tiempo de bit 的相对偏差。采样点要留在第 k 位里，必须满足上面的不等式；最难满足的是最后一位。10 位的帧：1/19 ≈ 5.3 %；11 位：≈ 4.8 %；12 位：≈ 4.3 %。这是只考虑偏差的理想界限，实际电路还有检测下降沿本身的误差，余量更小。所以具体界限随帧长略有不同，要记的是 5 % 这个整数。

试试看

回到 §4 的帧构造器，打开 RX 采样，把偏差拖到 +6 % 或 −6 %：最后几位的采样点会滑进相邻的位。黄色表示"位置已经错了，但相邻位的值碰巧相同"，红色表示真的读错。换一个字符（比如 'U'，0x55，相邻位交替），读错会更明显。

§7接到 PC：RS-232 与虚拟 COM 口 M33.9

PC 的"串口"也是 UART。为什么不能直接把它接到微控制器的引脚上？El estándar RS-232 y los puertos COM virtuales.

PC 里有一个 UART，接在一套符合 RS-232 标准的电路上，这就是所说的"PC 的串口"（puerto serie del PC）。这个标准规定了：

  • 通信协议；
  • 设备上使用的连接器；
  • 电气特性（线上的电压电平、阻抗……）；
  • 连接距离：15 m；
  • 点对点（punto a punto）：不是多点总线，不能挂两台以上的设备。

RS-232 规定的是 DTE, equipo terminal de datos (ES) / data terminal equipment (EN)——数据终端设备和 DCE, equipo de comunicación de datos (ES)——数据通信设备之间的通信。关键在电平：

除了电气特性，标准还规定了机械特性：连接器是 9 针的 D 型连接器（DB9 / D9）：

2 针

Tx、Rx

数据的发送和接收。

1 针

masa común

公共地。

6 针

control

通信控制信号。

可是现在大多数台式机和笔记本已经没有这种串口和 D9 连接器了，所以要用 USB-RS232 或 USB-UART 转换线，并安装它们的驱动。驱动会创建一个 puerto COM virtual (ES) / virtual COM port, VCP (EN)——虚拟 COM 口，它模拟一个标准 COM 口，用起来和 PC 上任何其他 COM 口一样。

MSP-EXP430F5529LP 开发板自带这条通路（板子的结构见 M12 §1）：

RS-232：mark '1' ≈ −12 V，space '0' ≈ +12 V，15 m，点对点，DB9（2 数据 + 1 地 + 6 控制），所以微控制器要经电平转换才能接。今天多用 USB 转换线和虚拟 COM 口；LaunchPad 上就是 ez-FET 提供的 MSP Application UART1 → USCI_A1（另一个 COM 口 MSP Debug Interface 是调试用的）。下一章 M34 讲怎样配置 USCI_A1 的 UART 模式和波特率寄存器。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01串行接口相对并行接口的优点里，不包括哪一项？

C。正好相反：串行总线比并行总线慢（§0）。

02同步串行通信和异步串行通信最本质的区别是？

B。异步也至少要数据线和地线，而且两边必须约定频率并想办法同步（§1）。

03按 §2 的分类，I2C 属于哪一类？

D。I2C 是同步接口，只有一根数据线（datos，另有 reloj、tierra），两个方向轮流用，所以是半双工（§2、§3）。

04SPI 怎样决定和哪个从机通信？

A。地址和 ACK 是 I2C 的做法；SPI 没有地址也没有确认（§3）。

05UART 线路上没有字符要发时，处于什么状态？

B。空闲是高电平，起始位把线拉低，这个下降沿才能标出一帧的开始（§4）。

06用 8 个数据位发送 0x41（0100 0001），起始位之后线上依次出现的数据位是？

A。数据位从低位到高位发送：b0 = 1 先出去，b7 = 0 最后（§4）。

07停止位的作用是？

C。A 是起始位，B 是校验位；数据位数是事先约定的参数（§4）。

089600 baudios，8 个数据位、无校验、1 个停止位。发送一个字符最少要多少时间？

B。1 + 8 + 0 + 1 = 10 位，10 / 9600 s ≈ 1.04 ms。A 只算了 8 个数据位，C 是按 11 位算的（§4）。

09UART 接收器怎样跟上发送端的节拍？

D。UART 不传时钟；接收时钟的频率要和发送端相同或是它的倍数（§5）。

10接收端为什么常用更高频率的时钟、在位中心附近取几个样本？

A。这就是 mayoría de voto。界限是：偏差超过 5% 就可能解码出错（§6）。

11RS-232 中逻辑 '1'（mark）通常是多少伏？

C。+12 V 是 '0'（space）。标准允许 mark 在 −3…−24 V、space 在 +3…+24 V，所以需要电平转换器（§7）。

12用 USB 线把 MSP-EXP430F5529LP 接到 PC，要和板子做串口通信，应该打开哪个 COM 口？

B。它是 ez-FET 的虚拟 UART 接口，接到 USCI_A1。MSP Debug Interface 虽然也显示成 COM 口，却是下载和调试用的（JTAG / Spy-Bi-Wire）。COM 号因电脑而异，名字不变（§7）。
