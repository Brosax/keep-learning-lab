§0让硬件去数 M31.1

"等 0.5 秒"这件事，一定要 CPU 亲自去等吗？¿Quién cuenta el tiempo: la CPU o un periférico?

定时器有三种用途：

本章

产生事件

Generar eventos：每隔一段时间产生一次中断，可以周期重复。用来安排任务、做时间基准。

M32

产生信号

Generar señales digitales：在引脚上直接输出 PWM（占空比、频率可调），驱动蜂鸣器、电机等。见 M32 PWM。

不学

测量间隔

Medir intervalos：用捕获模式记录两个事件之间的时间。捕获模式本课不讲。

范围

F5529 有两类定时器。Timer_A / Timer_B 几乎一样，Timer_B 多一点功能；本课只学 Timer_A，结论可以直接搬到 Timer_B。Watchdog 是专用定时器（超时产生 PUC 复位，或作间隔定时器），在芯片框图的 SYS 块里（框图见 §1），本模块不学。

定时器是一个在后台按时钟计数的外设。时间由硬件决定，CPU 只需配置一次，然后等 flag 或中断。

§1Timer_A 的结构 M31.2

一个计数器，怎么同时管好几个不同的时间点？Un contador y varios bloques de captura/comparación.

每个 Timer_A（TAx，x = 0、1、2）由三类零件组成：一个contador (ES) / counter (EN)——计数器 TAxR；几个 bloque de captura/comparación (ES) / capture/compare block (EN)——捕获/比较块 TAxCCRn；每个块里还有一个输出单元。跟着信号走一遍：

F5529 上有三个 Timer_A，CCR 的数量不一样。在芯片框图里找到它们：

Timer0_A5

TA0

5 个 CCR：TA0CCR0 – TA0CCR4。中断向量 53（CCR0）和 52（其余）。

Timer1_A3

TA1

3 个 CCR：TA1CCR0 – TA1CCR2。中断向量 49 和 48。

Timer2_A3

TA2

3 个 CCR：TA2CCR0 – TA2CCR2。中断向量 44 和 43。

另有 Timer_B TB0，7 个 CCR，本课不展开。（每个定时器的 CCR 编号：TA0 是 0–4，TA1、TA2 是 0–2；有些资料正文写的 0–5、0–3 各多算了一个。）

一个计数器 TAxR 负责"数"，多个 CCRn 负责"在哪个数上做事"。所有 CCRn 共用同一个 TAxR，所以一个定时器能同时给出好几个时间点。

§2时钟从哪里来 M31.3

TAxR 一秒钟加多少次？由谁决定？TASSEL → ID → TAIDEX → reloj del timer.

TAxR 在 timer clock 的每个上升沿变一次。所以"一拍"有多长，完全由时钟路径决定。下面用 ACLK = 32768 Hz、ID = /2、TAIDEX = /3 演示：

f_timer = f_TASSEL / (ID · IDEX)，ID ∈ {1, 2, 4, 8}，IDEX ∈ {1 … 8}

这些位在哪里？把三个配置寄存器的位图合在一起看：

头文件标签意思写在
TASSEL_1 / TASSEL_2ACLK / SMCLKTAxCTL
ID_0 … ID_3/1、/2、/4、/8TAxCTL
TAIDEX_0 … TAIDEX_7/1 … /8TAxEX0
MC_0 … MC_3stop、up、continuous、up/downTAxCTL
TACLR · TAIE清零 · TAIFG 中断使能TAxCTL
CCIE（CAP 默认 0）CCRn 比较中断使能TAxCCTLn
改分频之后

分频器内部是递减计数器。改了 ID 或 TAIDEX 之后，要把 TACLR 置 1，让 TAxR 和分频逻辑都回到确定的初始状态。

分频越大，一拍越长：同样 16 位（最多 65536 拍），能数的总时间越长，但分辨率越粗。

§3四种计数模式 M31.4

同一个 TAxR，数到哪里就回头？MC = 00 stop · 01 up · 10 continuous · 11 up/down.

TAxCTL 里的两位 MC 决定计数方式：

MC模式TAxR 怎么走一个周期CCR0 还能自由用吗
00stop停住，保持当前值；不用定时器时设 00 可以省电——
01ascendente (ES) / up (EN)——向上0 → TAxCCR0，再回 0CCR0 + 1 拍不能，它是周期寄存器
10continuo (ES) / continuous (EN)——连续0 → 0xFFFF，再回 065536 拍能，和其他 CCRn 一样
11ascendente/descendente (ES) / up/down (EN)——上下0 → TAxCCR0 → 02 · CCR0 拍不能

试试看

① up 模式下把 CCR1 拖到比 CCR0 还大：CCIFG1 一次也不出现，因为 TAxR 永远到不了它。② 换成 up/down：CCIFG1 每个周期出现两次（上坡一次、下坡一次）。③ 把 CCR0 设成 0：up 和 up/down 模式下计数器停住。④ continuous 下打开 "CCR1 += N"，看蓝绿色的阶梯：寄存器值回绕了，但间隔始终是 N。

三种模式的周期，换算成时间：

T_up = (CCR0 + 1) / f_timer　T_cont = 65536 / f_timer　T_up/down = 2·CCR0 / f_timer

式子里的时钟是分频之后的 ftimer，时间单位是秒；continuous 模式用增量 N 代替 65536 时，间隔就是 N / ftimer（见 §7）。三个典型例子都是 10 拍一周期：up 模式 TACCR0 = 9，up/down 模式 TACCR0 = 5，continuous 模式 N = 10（§5 的动画就用这组数）。反过来求 CCR0：up 模式 CCR0 = T · f − 1；up/down 模式 CCR0 = T · f / 2。

例：反过来求 CCR0

SMCLK = 1048576 Hz，ID = /8，TAIDEX = /4 → ftimer = 1048576 / 32 = 32768 Hz。想要 up 模式每 0.25 s 一次 CCR0 中断：

CCR0 = 0.25 · 32768 − 1 = 8191

同样的时钟用 up/down 模式：CCR0 = 0.25 · 32768 / 2 = 4096。注意 up 模式的"− 1"：周期是 CCR0 + 1 拍，因为 0 也算一拍。

up：周期由 CCR0 定，CCR0 + 1 拍；continuous：固定 65536 拍，CCR0 解放出来；up/down：2 · CCR0 拍，波形对称。

§4清零、启动、停止 M31.5

计数器正在跑，这时候改 CCR0，会发生什么？Inicialización, activación y cambio de configuración.

TACLR = 1 时

  • TAxR ← 0x0000
  • 分频器（ID、TAIDEX）的计数复位
  • up/down 模式的方向 ← 向上
  • TACLR 自己自动回 0（读出来总是 0）

只想改计数值，也可以直接写 TAxR。TACLR 不改 MC，也就是说它不会让计数器停下来。

计数器在跑，当且仅当

  • 时钟源是活的
  • MC ≠ 00
  • up 和 up/down 模式下 TAxCCR0 ≠ 0

任何一条不满足就停住，并保持当前状态（计数值、方向、分频）。恢复后从停住的地方继续。例外：up/down 模式下靠写 CCR0 = 0 停住、再写非 0 值重启时，方向被初始化为向上。

运行中修改的后果：

运行中改模式情况结果
MC→ upTAxR > CCR0TAxR 回 0
MC→ up/down向上，且 CCR0 > TAxR继续向上到 CCR0
MC→ up/down向下，且 CCR0 ≤ TAxR继续向下到 0
CCR0up新 CCR0 > TAxR / ≤ TAxR数到新值 / 回 0
CCR0up/down向上，新 CCR0 > TAxR向上数到新值
CCR0up/down向上，新 CCR0 ≤ TAxR掉头向下到 0
CCR0up/down正在向下继续向下到 0，新周期从下一轮生效

TACLR 清计数值、分频器和方向，但不停计数；真正的停止是 MC = 00（或 up、up/down 下 CCR0 = 0）。改配置前先停。

§5比较：flag 在哪一拍置位 M31.6

TAxR 等于 CCR0 的那一拍，和它回到 0 的那一拍，是同一拍吗？CCIFG y TAIFG: ¿cuándo se activan?

本课只用modo comparación (ES) / compare mode (EN)——比较模式：TAxCCTLn 的 CAP = 0（复位值就是 0）。当 TAxR 数到 TAxCCRn 时，硬件同时做三件事：

  • EQUn = 1（内部信号，给输出单元用）
  • CCIFG = 1（TAxCCTLn 的 bit 0）
  • 把所选输入信号锁存到 SCCI（捕获相关，本课不用）

"数到"很重要：只有计数过程中到达才算；用软件直接把某个值写进 TAxR，不会触发对应的动作。下面一拍一拍地看三种模式，数值用 §3 的三个例子（都是 10 拍一周期），另加一个 CCR1 = 3：

两个推论

① up 模式下 CCRn > CCR0 的块永远不会匹配：TAxR 到不了那里。② flag 由硬件置位，与使能位无关；没有使能中断时，flag 照样置 1，可以用轮询去查（这一点和 M21 §1 的端口 flag 一样）。

CCIFG = "数到了 CCRn"；TAIFG = "数回了 0"。up 模式两者差 1 拍，up/down 模式差半个周期，continuous 模式 TAIFG 每 65536 拍一次。

§6两个中断向量 M31.7 · M31.8

TA0 有 5 个 CCIFG 和 1 个 TAIFG，却只有 2 个中断向量。怎么分？Interrupción TAxCCR0 (fuente única) e interrupción TAxIV (fuentes múltiples).

先回忆 M21 §4：可屏蔽中断要 flag、单独使能、GIE 三者同时为 1。定时器的单独使能位有两种：CCIE（TAxCCTLn 的 bit 4，管这个块的 CCIFG）和 TAIE（TAxCTL 的 bit 1，管 TAIFG）。

TAxIV 的取值 M31.8

TAxIV中断源flag 位置TA0TA1 / TA2
0x00没有挂起的中断—✓✓
0x02CCR1（最高）TAxCCTL1 CCIFG✓✓
0x04CCR2TAxCCTL2 CCIFG✓✓
0x06CCR3TAxCCTL3 CCIFG✓—
0x08CCR4TAxCCTL4 CCIFG✓—
0x0ETAIFG（最低）TAxCTL TAIFG✓✓

TAIV 寄存器的定义一直列到 CCR6，所以还有 0x0A、0x0C（CCR5、CCR6）；F5529 的 Timer_A 没有这两个块。TAxIV 只有 bit 3–1 可能为 1，所以读出来总是 0–14 之间的偶数，这就是下面 __even_in_range(…, 14) 的依据。被禁止的中断不影响 TAxIV 的值。

动手看 TAxIV 怎么"报数"。下面是 TA0（CCR1–CCR4 + TAIFG）：点按钮置位 flag、开关使能，然后读 TA0IV。

ISR 里识别中断源有两种写法，和 M21 §7 的 P1IFG / P1IV 完全对应：

#pragma vector=TIMER0_A1_VECTOR           // 52 号：CCR1–4 + TAIFG__interrupt void TA0_A1_ISR(void) {    switch (__even_in_range(TA0IV, 14)) { // 读 TA0IV：清掉它报出的 flag    case  2: … break;                     // CCR1    case  6: … break;                     // CCR3    case 14: … break;                     // TAIFG (0x0E)    default: break;    }}
#pragma vector=TIMER0_A1_VECTOR__interrupt void TA0_A1_ISR(void) {    if (TA0CCTL1 & CCIFG) { TA0CCTL1 &= ~CCIFG; … }  // 要自己清    if (TA0CCTL3 & CCIFG) { TA0CCTL3 &= ~CCIFG; … }    if (TA0CTL & TAIFG)    { TA0CTL &= ~TAIFG; … }}

__even_in_range(TA0IV, 14) 告诉编译器 TA0IV 只会是 0 到 14 之间的偶数，可以生成跳转表。用直接查 flag 的写法时，最好再与上对应的使能位（CCIE / TAIE），理由同 M21 §7。CCR0 的 ISR 单独写在 TIMER0_A0_VECTOR 下，不进这个 switch。

CCR0 → 自己的向量，flag 自动清；其他所有 → TAxIV 向量，读一次 TAxIV 清一个、报一个，剩下的在 RETI 后再触发一次中断。

§7一个计数器，多个节拍 M31.9

两盏灯，一盏每 125 ms 翻一次，一盏每 750 ms 翻一次。只用一个定时器，可以吗？Modo continuo: TAxCCRn(i+1) = TAxCCRn(i) + N.

up 模式只有一个周期（由 CCR0 定），只能给出一种节拍。continuous 模式让 TAxR 不受任何 CCR 约束地一直数，每个 CCRn 各自"追着"TAxR 走：每次匹配后，在 ISR 里把它往前推 N 拍：

TAxCCRn(1) = TAxR + N；TAxCCRn(i+1) = (TAxCCRn(i) + N) mod 65536；N = t · f_timer

把它写成代码。两个例子都用 TA0：

// ACLK = 32768 Hz，ID = /2 → f_timer = 16384 Hz；每 0.5 s 翻转 LED1WDTCTL   = WDTPW + WDTHOLD;P1DIR   |= BIT0;TA0CCR0  = 8192 - 1;                       // 0.5 s · 16384 Hz − 1 = 8191TA0CCTL0 = CCIE;                           // 使能 CCR0 中断（CAP = 0：比较）TA0CTL   = TASSEL_1 + ID_1 + MC_1 + TACLR; // ACLK, /2, up, 清零__bis_SR_register(LPM3_bits + GIE);      // LPM3 下 ACLK 仍在跑 #pragma vector=TIMER0_A0_VECTOR             // 53 号，单源__interrupt void TA0_A0_ISR(void) {    P1OUT ^= BIT0;                          // CCIFG0 已被硬件自动清}
// ACLK = 32768 Hz，/1：CCR1 每 125 ms（N1 = 4096），CCR3 每 750 ms（N3 = 24576），// TAIFG 每 65536 / 32768 = 2 s#define N1  4096#define N3  24576TA0CCR1  = N1;   TA0CCTL1 = CCIE;        // 初值 = TA0R(0) + NTA0CCR3  = N3;   TA0CCTL3 = CCIE;TA0CTL   = TASSEL_1 + ID_0 + MC_2 + TACLR + TAIE;  // ACLK, /1, continuous__bis_SR_register(LPM3_bits + GIE); #pragma vector=TIMER0_A1_VECTOR             // 52 号，多源__interrupt void TA0_A1_ISR(void) {    switch (__even_in_range(TA0IV, 14)) {    case  2: TA0CCR1 += N1; P1OUT ^= BIT0; break;  // 自动 mod 65536    case  6: TA0CCR3 += N3; P4OUT ^= BIT7; break;    case 14: /* 每 2 s：例如数秒 */      break;    default: break;    }}

LED 引脚的方向配置（P1DIR、P4DIR）在例 B 里省略了。CCR0 在 continuous 模式下也能这样用，只是它走自己的 TIMER0_A0 向量。低功耗模式见 M26。

间隔太长怎么办

N 必须小于等于 65536。需要的间隔超过 65536 拍时，有两条路：加大分频（ID、TAIDEX）让每拍更长；或者保留一个较短的时间基准（base de tiempos），在 ISR 里用软件计数器数够若干次再行动。选哪个取决于需要的精度。

up

一个周期事件

周期 = CCR0 + 1。最简单。也用来做 PWM（M32）。CCR0 被占用。

continuous

多个独立节拍

每个 CCRn 一个节拍，ISR 里 += N。也是捕获测时用的模式（本课不学）。

up/down

对称波形

周期 = 2 · CCR0。适合产生不重叠的方波（H 桥驱动电机时的死区）。

continuous + "CCRn += N"：一个计数器给出最多 n 种独立节拍，间隔由硬件保证，不受中断延迟影响；16 位回绕不需要特别处理。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01TAxCTL 的 MC = 10 表示什么模式？

C。00 stop、01 up、10 continuous、11 up/down（§3）。

02SMCLK = 1048576 Hz，ID = /4，TAIDEX = /1，up 模式，TA0CCR0 = 0xFFFF。CCR0 中断的周期是？

B。f = 1048576 / 4 = 262144 Hz；up 周期 = (CCR0 + 1) / f = 65536 / 262144 = 0.25 s。A 忘了 +1；D 是 up/down 的算法（§2、§3）。

03ftimer = 32768 Hz，up/down 模式，TAxCCR0 = 8192。TAIFG 多久置位一次？

D。up/down 周期 = 2 · CCR0 = 16384 拍 = 0.5 s；TAIFG 每周期一次（1 → 0）（§3、§5）。

04continuous 模式，TA0CCR2 = 60000，ISR 里执行 TA0CCR2 += 10000; 之后，TA0CCR2 = ?

A。16 位寄存器按 65536 取模：70000 − 65536 = 4464。TAxR 回绕后正好在 10000 拍后数到 4464（§7）。

05up 模式，TAxCCR0 = 2000，TAxCCR1 = 3000，CCIE1 = 1。CCIFG1 会怎样？

C。up 模式 TAxR 最多数到 CCR0 = 2000，永远到不了 3000（§3、§5）。

06up/down 模式，0 < TAxCCR1 < TAxCCR0。每个周期 CCIFG1 置位几次？

B。上坡数到 CCR1 一次，下坡又数到 CCR1 一次（§5）。

07哪个 flag 在进入 ISR 时由硬件自动清零？

D。TAxCCR0 是单源向量，进入 ISR 时自动清；其余共用 TAxIV 向量，要读 TAxIV 或手动清（§6）。

08TA0 的 CCR3 CCIFG 和 TAIFG 同时挂起，都已使能。ISR 第一次读 TA0IV 得到？

C。CCR3 → 0x06，优先级高于 TAIFG（0x0E，最低）。读完清掉 CCIFG3；RETI 后 TAIFG 再触发一次（§6）。

09把 TACLR 置 1，不会发生的是？

A。TACLR 清 TAxR、分频器和方向，然后自己回 0；它不改 MC（§4）。

10up 模式下给 TAxCCR0 写 0，会怎样？

B。up 和 up/down 模式下 CCR0 = 0 是停止条件之一；再写非 0 值就从 0 向上重新数（§4）。

11SMCLK = 1048576 Hz，ID = /8，TAIDEX = /4。ftimer = ?

D。两级分频相乘：1048576 / (8 · 4) = 32768 Hz（§2）。

12要让 CCRn 块工作在比较模式，应该怎样设置？

A。CAP = 0 比较、CAP = 1 捕获（本课不学）；复位值为 0（§5）。
