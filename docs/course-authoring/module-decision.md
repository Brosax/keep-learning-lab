# 什么时候加图示、代码和练习

模块不是每讲的固定配置。先问一句：**这一讲的讲义里，哪一页靠文字讲不清楚？** 回答不出来，就不加。

## 决策表

| 讲义内容的特点 | 适合的形式 | 例子 |
|---|---|---|
| 一个量随参数连续变化，学生需要"看着它变" | **交互图示** `visual` | 注意力权重随温度变化；学习率与收敛；KV 缓存随序列长度增长 |
| 有固定的先后步骤，但没有可调参数 | **静态流程** `flow` | 预训练 → SFT → RLHF；智能体的感知—计划—行动循环 |
| 几种方法并列比较 | **对比表** `table` | MHA / GQA / MQA；数据并行 / 张量并行 / 流水线并行 |
| 讲义里有公式推导或具体数字 | **手算例题** `kind: "worked-example"` | 交叉熵梯度；6ND 的算力估算 |
| 学生以后要亲手实现，或者讲义本身就是代码 | **代码演示** `codeDemo` | BPE 合并；softmax 的数值稳定写法；top-p 采样 |
| 有自然的课后任务，并能验收 | **练习** `exercise` | 复现一个小实验、填一张表 |
| 概念性、讨论性、访谈或嘉宾讲座 | **只要文字和自测** | 课程导论；Andrew Ng 对谈；行业趋势 |

## 代码演示的门槛

只有满足以下**任意一条**时才加：

- 讲义本身用代码讲解（例如 CS336 的 `lecture_XX.py`）
- 作业会要求实现它，提前跑一遍能帮学生降低门槛
- 光看公式容易出错，跑一次才会发现问题（数值稳定性、边界条件、off-by-one）

**不要**为了"有代码"而写代码：例如把一句定义翻译成三行 JS、打印一个常数，或者用代码重复正文里已经算过的例题。如果代码复现的是讲义自己的例子，并且在此基础上**有所扩展**（换参数、加边界情况、对比另一种写法），和手算例题部分重叠是可以的。

课程作业本身就是动手任务时，不必再加 `exercise`；代码演示也不要直接给出作业的答案。

## 交互图示的门槛

- 必须有一个**会改变结论**的参数。如果滑块拖到头，图和结论都没变，说明这里只需要一张静态图（`flow` 或 `table`）。
- 图上的数值必须能被 oracle 独立验证。
- 标题和步骤都用讲义里的术语。

## 同一门课的几讲之间

- 不要求每讲都配齐所有模块，也不追求几讲之间形式一样。
- 一门偏工程的课（例如 CS336）代码会多一些；一门偏方法论的课（例如 CS329Z 的评测、安全讲次）可能大部分讲次只有文字、流程和表格。这都是正常的。

## 参考：几门课的取舍示例

以下是 CME295 按 2026 年讲义修订后的实际取舍：

| 讲次 | 讲义特点 | 取舍 |
|---|---|---|
| 01 Transformer | 自注意力只以符号形式出现，没有数字和可调参数 | **不加**交互图示和代码；编码器 / 解码器用 `flow`，分词粒度和架构参数用 `table`，沿讲义的 8 个词元例句做一个形状推演的手算例题 |
| 02 LLM 与解码 | 讲义用具体数字演示温度和 top-p 采样（p.107–114） | **交互图示**：调节温度，看 top-p 保留几个候选。原有的代码演示和图示重复，删掉 |
| 04 RL 训练 LLM | 讲义有基线的玩具例子（p.34–36） | **交互图示**：拖动基线 b，看梯度方差和期望怎么变；**练习**：填完讲义里泰迪熊例子的 GRPO 表 |
| 05 LLM 系统 | online softmax 的推导（p.30–47），不跑一遍很容易写错 | **代码演示**：不减最大值时 `exp(1001)` 溢出，用 running max 则正常 |
| 06 AI Agent | 概念和流程为主 | 只用 `flow`、`table` 和一个检索指标的手算例题 |
| 07–09 | 2026 年讲义未发布 | 用 2025 年讲义并写 `sourceStatus`；只有文字、流程、表格和手算例题 |

一个反面例子：修订前，第 1 讲的手算例题用的是第 2 讲才讲的 RoPE，第 5 讲的图示讲的是讲义里根本没出现的量化。这类模块都应该删掉。

其他类型的课程可以参考：
- **讲稿就是代码的课**（例如 CS336 的 `lecture_XX.py`）：代码演示会多一些，但应当演示讲稿里的关键函数，不要另写一套。
- **嘉宾讲座、访谈类讲次，且没有讲义**：写 `sourceStatus`，给出带着问题听课的提纲和自测题，不加任何模块。
