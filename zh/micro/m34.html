§0一个字节的旅程

在 PC 的终端里按下 'A'，MSP430 里是谁把它接住的？¿Quién recibe el carácter dentro del MSP430F5529?

UART 帧是 M33 的"线上格式"；USCI_A 是芯片里把字节变成帧、把帧变回字节的硬件。CPU 只和两个缓冲寄存器、两个 flag 打交道。

§1两种 USCI，四个模块 M34.1 · M34.2

F5529 上有好几个串口模块，哪个能做 UART？接在哪两个引脚上？USCI_A y USCI_B: ¿cuál implementa la UART?

5xx 家族把串行通信集中在 USCI 模块里，分两种，用字母区分：

USCI_A

UART 及其变体

  • UART 模式
  • IrDA 通信的脉冲整形（conformado de pulsos）
  • LIN 通信的自动波特率检测
  • SPI 模式
USCI_B

同步总线

  • I2C 模式
  • SPI 模式

没有 UART。有些 5xx 型号用的是改进版 eUSCI，F5529 用的是 USCI。

MSP430F5529 有 2 个 USCI_A（USCI_A0、USCI_A1）和 2 个 USCI_B。在芯片方块图里它们只占一个方块 "USCI0,1"：

寄存器名里的 x 换成模块号：USCI_A1 的 UCAxTXBUF 就是 UCA1TXBUF，引脚叫 UCA1TXD、UCA1RXD。

USCI_A 默认就在 UART 模式：UCAxCTL0 里的 UCSYNC = 0（异步）、UCMODEx = 00（普通 UART），而这两个字段复位后都是 0。

模块TXDRXD中断向量在 LaunchPad 上
USCI_A0P3.3 · UCA0TXD · 40 脚P3.4 · UCA0RXD · 41 脚56 · 0xFFF0—
USCI_A1P4.4 · UCA1TXD · 51 脚P4.5 · UCA1RXD · 52 脚46 · 0xFFDC经 TXD/RXD 跳线接到 eZ-FET 的 backchannel UART

P4 是可映射端口，51、52 脚的全名是 P4.4/PM_UCA1TXD/PM_UCA1SIMO、P4.5/PM_UCA1RXD/PM_UCA1SOMI：默认映射就是 USCI_A1，SPI 模式下同两个脚做 SIMO / SOMI。向量号见 M21 §4 向量表。

引脚交给外设

这两个引脚不再当普通 GPIO，而是交给 USCI：把 P4SEL 的第 4、5 位置 1（M14 讲过的 PxSEL）。方向由 USCI 自己控制：TXD 是输出，RXD 是输入。

backchannel UART

LaunchPad 上 eZ-FET 和目标芯片之间有一排隔离跳线：JP1 +5V、JP2 +3V3、JP3 GND、JP4.x 是调试用的 SBW，JP6 是串口。其中 JP6.1 TXD 把 P4.4/UCA1TXD 接到 eZ-FET 的 UARTRXD，JP6.2 RXD 把 eZ-FET 的 UARTTXD 接到 P4.5/UCA1RXD——线是交叉的，跳线按 MSP430 这一侧命名。插上时 eZ-FET 再经 USB 在 PC 上虚拟出一个 COM 口，所以和 PC 通信用 USCI_A1，不用另接 USB-串口线。JP6.3 CTS（P1.7）、JP6.4 RTS（P6.7）是硬件流控，本课不用。

§2方块图：两个缓冲，两个 flag M34.3

已经有移位寄存器了，为什么还要一个缓冲寄存器？UCAxTXBUF → registro de desplazamiento → UCAxTXD.

UART 模式下的 USCI_A 分成三块：transmisor、receptor 和 generador de baudios。CPU 只碰两个缓冲寄存器；逐位移出、移入由各自的 registro de desplazamiento (ES) / shift register (EN)——移位寄存器完成，节拍来自波特率发生器。

UCTXIFG：TXBUF 空了

  • 置 1：TXBUF 能接收新字节时；复位（PUC 或 UCSWRST = 1）之后也是 1
  • 清 0：写 UCAxTXBUF 时自动清；读 UCAxIV 也会清（§7）

UCRXIFG：RXBUF 里有新字节

  • 置 1：一个完整字符搬进 UCAxRXBUF 时
  • 清 0：读 UCAxRXBUF 时自动清；复位时清

发送看 UCTXIFG（"能写了吗"），接收看 UCRXIFG（"有货了吗"）。两个 flag 都是读写缓冲时由硬件自动清，一般不用手动清。

§3怎样"数"出 9600 baud M34.4 · M34.5

32768 / 9600 = 3.41。时钟只能一个一个地数，0.41 个周期怎么数？Si N = f(clk) / tasa no es entero, ¿qué se hace con la parte decimal?

波特率发生器的输入叫 BRCLK，由 UCAxCTL1 的 UCSSELx 选择：00 外部引脚 UCAxCLK、01 ACLK、10 / 11 SMCLK。外部时钟脚：USCI_A1 是 P4.0（PM_UCA1CLK，45 脚），USCI_A0 是 P2.7（UCA0CLK，36 脚），见 §1 的引脚图。输出 BITCLK 就是位速率：每 N 个 BRCLK 周期是一个位时间。

N = f(BRCLK) / baud

N 是整数时（例如 1.8432 MHz / 9600 = 192）直接整除就行。不是整数时，分两种情况：

BRCLK 高

小数可以丢掉

XT2 = 8 MHz，9600 baud：N = 833.33。只用 833 → 9603.8 baud，误差 0.04 %，收发双方不会失步。

BRCLK 低

小数不能丢

XT1 = 32768 Hz，4800 baud：N = 6.83。用 7 → 4681 baud，误差 −2.5 %，还能改进——要把小数部分"近似"出来。

小数部分 1/N 越大越要紧。下面用一个例子：32768 Hz → 9600 baud，N = 3.4133。

把这个过程写成计算步骤（UCOS16 = 0，modo de baja frecuencia (ES) / low-frequency mode (EN)——低频模式）：

UCBRx = int(N)　UCBRSx = M = round((N − int N)·8)　N* = UCBRx + M/8
baud_real = f(BRCLK) / N*　error = (baud_real − baud) / baud
baud = f(BRCLK) / (UCBRx + (1/n)·Σ mᵢ)

第一行的 UCBRx、UCBRSx 两式是一定要记住的内容。最后一行是另一种写法：mi 是第 i 位的调制位（0 或 1），n = 8，Σ mi = M，和 N* 是同一个式子。

  1. PASO 1：整数部分写进 UCAxBR0（低字节）和 UCAxBR1（高字节），UCBRx = BR0 + 256·BR1。例：N = 3 + 0.4133 → BR1 = 0x00，BR0 = 0x03。
  2. PASO 2：小数部分 × 8，四舍五入得 M（0.4133 × 8 = 3.3064 → 3），写进 UCAxMCTL 的 UCBRSx。M 是 8 个位时间里数 N + 1 的次数。
  3. PASO 3：近似商 N* = 3 + 3/8 = 3.375，实际 BITCLK = 32768 / 3.375 = 9709.04 baud。不调制时误差 13.78 %，调制后 1.14 %（有些资料写作 13,7 % 和 1,13 %，是截断后的值）。
  4. PASO 4：M 个"1"在 8 位里怎么分布，由调制器按下表决定——TI 逐位计算误差后定下的图样。

采样：多数表决

低频模式下，计数器先数 INT(N/2) + m 个 BRCLK 到位的中点，再数 INT(N/2) + R 个到位的末尾（R 是 N/2 的余数）。每一位在中点附近的 N/2 − ½、N/2、N/2 + ½ 个 BRCLK 处各采一次样（用 BRCLK 的上升沿和下降沿，相隔半个周期），取多数（majority vote——多数表决）。三个样本一共只跨 1 个 BRCLK。这个模式的最大波特率是 BRCLK / 3。

§4UCOS16 = 1：过采样 M34.6

BRCLK 是 1 MHz 时，一位里有 104 个周期，三次采样却挤在中间 1 µs 里。这样的"多数表决"还有意义吗？Modo de sobremuestreo: ventanas de muestreo más acordes con el tiempo de bit.

低频模式的三个样本挤在 1 个 BRCLK 之内（相隔 ½ 个，见 §3 的时序图）。BRCLK 越快，窗口越窄，一个短毛刺就能左右结果。用三个例子比较采样窗口和位时间（9600 baud，Tbit = 104.16 µs）：

例模式BRCLK采样窗口窗口 / Tbit
1UCOS16 = 032768 Hz1/32768 = 30.51 µs29 %
2UCOS16 = 01 MHz1/1 MHz = 1 µs1 %
3UCOS16 = 11 MHz3/153600 ≈ 19.5 µs19 %

例 3 的窗口按 3 个 BITCLK16 周期算。

sobremuestreo (ES) / oversampling (EN)——过采样：先生成一个快 16 倍的 BITCLK16，一位切成 16 份，三个样本各隔一份。

UCBRx = int(N/16)　UCBRFx = round((N/16 − int(N/16))·16)

上式是这一节要记住的内容。例：N = 1048576 / 9600 = 109.226；N/16 = 6.8267 → UCBRx = 6；0.8267 × 16 = 13.23 → UCBRFx = 13。TI 的波特率表里这一行也是 6 · 0 · 13（UCBRx · UCBRSx · UCBRFx）。

按位时间公式（UCBRSx = 0）：每位 16·UCBRx + UCBRFx = 109 个 BRCLK → 1048576 / 109 = 9619.96 baud，误差 +0.21 %。另外，UCBRx = 0 或 1 时第一级分频和调制被旁路，BITCLK16 = BRCLK，UCBRFx 不起作用。

TI 的表格和公式不总是一样

上面的公式给的是"名义值"。TI 的波特率表（UCOS16 = 0 一张、UCOS16 = 1 一张）列出的值，是逐位计算误差、让单个位的最大误差最小的结果；UCOS16 = 1 时还会再用上 UCBRSx。所以个别组合会差 1。题目说“según la tabla del fabricante”时，要用 TI 的波特率表查值，不要用公式算。

§5初始化：先按住复位 M34.7

为什么改 USCI 的配置之前，要先让它"停下来"？La configuración de la USCI sólo se puede realizar mientras UCSWRST = 1.

USCI 由 PUC 或 UCAxCTL1 的 UCSWRST（software reset）位复位。PUC 之后 UCSWRST 自动是 1（UCAxCTL1 的复位值是 01h），模块保持在复位状态。UCSWRST = 1 时，硬件清掉 UCRXIE、UCTXIE、UCRXIFG、UCRXERR、UCBRK、UCPE、UCOE、UCFE、UCSTOE、UCBTOE，并把 UCTXIFG 置 1；清掉 UCSWRST，模块才开始工作。

寄存器名和宏（UCSSEL_1、UCBRS_3、UCBRF_0）在 msp430f5529.h 里定义；数值是 §3 的例子。"配置端口"可以单列一步，也可以并进第 2 步——总之要在清 UCSWRST 之前。

§6收到的字节可能是错的 M34.8

线路上有干扰、波特率不准、CPU 来不及读——USCI 怎么发现，又怎么告诉你？Errores detectados de forma automática por la UART.

每收到一个字符，USCI_A 自动检查下面几种情况，结果放在 UCAxSTAT 里：

位错误什么时候置 1
UCFEerror de trama · framing停止位的位置是低电平；用 2 个停止位时两个都检查
UCPEerror de paridad · parity1 的个数和校验位对不上（UCPEN = 0 时总读出 0）
UCOEsobreescritura · overrun上一个字符还没读，下一个字符又搬进了 RXBUF
UCBRKcondición de BREAK收到 10 个或更多低电平位、没有停止位；UCBRKIE = 1 时还会置 UCRXIFG
UCRXERR汇总这个字符带错：UCBRK、UCPE、UCOE、UCFE 任一置位时也置位

两个相关的使能位在 UCAxCTL1 里：UCRXEIE = 0（默认）时，有帧错误或校验错误的字符不进 RXBUF，也不置 UCRXIFG——错字符直接丢掉；UCRXEIE = 1 时照常收下并置位错误标志，由软件判断。UCBRKIE = 1 时，收到 break 也置 UCRXIFG。

§7一个向量，两种原因 M34.9

收和发共用一个中断向量。进了 ISR，第一件事：是收到了，还是可以发了？Un único vector compartido: el registro UCAxIV.

每个 USCI_Ax 只有一个中断向量，发送和接收共用（USCI_A0 是 56 号 0FFF0h，USCI_A1 是 46 号 0FFDCh；向量表见 M21 §4）。两种请求条件和 M21 §1 的事件链一样：

((UCRXIFG ∧ UCRXIE) 或 (UCTXIFG ∧ UCTXIE)) ∧ GIE ⇒ 中断请求

进了 ISR，读 UCAxIV 就知道是谁（16 位只读，复位 0000h）：0x00 没有中断，0x02 接收（UCRXIFG，优先级最高），0x04 发送（UCTXIFG，优先级最低）。读或写 UCAxIV 都会清掉当前优先级最高的挂起 flag；没使能的源不影响它的值。

一个 ISR 骨架（示意）：接收的字节存进一个小缓冲；发送一个字符串，发完就关掉发送中断：

#pragma vector=USCI_A1_VECTOR                 // 46 号，0xFFDC__interrupt void USCI_A1_ISR(void) {    switch (__even_in_range(UCA1IV, 4)) {    case 0: break;                            // 0x00：没有中断    case 2:                                     // 0x02：UCRXIFG        rx[n++ & 0x0F] = UCA1RXBUF;          // 读出来，存进 16 字节环形缓冲        break;    case 4:                                     // 0x04：UCTXIFG，TXBUF 空        if (*p) UCA1TXBUF = *p++;               // 还有字符：写下一个        else    UCA1IE &= ~UCTXIE;              // 发完了：关掉发送中断        break;    default: break;    }}

发送：轮询

每发一个字节前等 UCTXIFG = 1（§2 的代码）。简单，但 CPU 在等待中什么也做不了：9600 baud 下一个字节要等约 1 ms。

发送：中断

开 UCTXIE，每次 TXBUF 空就进 ISR 写下一个字节，CPU 其余时间可以做别的或睡觉。发完必须关 UCTXIE：TXBUF 一直空，UCTXIFG 一直是 1，不关就会不停地进 ISR（和 M21 §6 忘清 flag 是同一个道理）。

注意 · 资料有误

讲接收中断时，有些资料两处把使能位写成了 UCTXIE，应为 UCRXIE。

USCI_Ax 的中断：一个向量、两个原因。ISR 里读 UCAxIV 分辨（0x02 收、0x04 发），读 IV、读 RXBUF、写 TXBUF 都会清掉对应的 flag。

§8用 driverlib 写出来 M34.10

同样的初始化，能不能不记那么多位名？Programación del MSP430 utilizando una biblioteca de periféricos.

到目前为止我们都直接读写寄存器。实际项目里越来越常用厂商提供的biblioteca de periféricos (ES) / peripheral driver library (EN)——外设驱动库：用函数配置和控制外设，不必在每一步都记住改的是哪个寄存器的哪一位。TI 的这套库叫 driverlib，在 MSPWare 软件包里，以源代码形式提供。

ventajas

好处

抽象层次更高：隐藏外设内部细节，不用每次都核对改的是哪一位。由厂商提供、文档齐全。

desventajas

代价

代码稍慢、更大（有时重复配置、做多余的事）；为了简单，库会加一些限制，灵活性下降。

把 driverlib 加进 CCS 项目

  1. 找到库：MSPWare 安装在 C:\ti\msp\MSPWare_VV_XX_YY_ZZ，其中 driverlib 文件夹里按家族分好：F5529 用 MSP430F5xx_6xx。课程用的版本是 2.91.13.01；文档在 doc 文件夹（课程页面上也有 PDF）。
  2. 复制源文件：在项目里 New → Folder，建一个 driverlib 文件夹；把 MSP430F5xx_6xx 拖进去，选 Copy（本地复制，项目更好移植）。
  3. 删掉 deprecated：如果有 deprecated 子文件夹（旧版驱动），从项目里删除。
  4. Include Options：Properties → Include Options，加两条搜索路径：${workspace_loc:/${ProjName}} 和 ${workspace_loc:/${ProjName}/driverlib/MSP430F5xx_6xx}。
  5. Predefined Symbols：加 __MSP430F5529__（前后各两个下划线），相当于每个源文件开头都有一行 #define __MSP430F5529__，driverlib 据此按我们的芯片编译。
  6. 使用：在要用库的源文件开头写 #include "driverlib.h"。

另一条路：在 CCS 的 View → Resource Explorer 里下载 TI 的示例项目，它们已经带好库和配置；其中有一个空项目（写作 EMPTYPROYECT，拼法如此）可以直接当起点。

#include <msp430.h> void uart_init(void) {    UCA1CTL1 |= UCSWRST;              // ① 复位    UCA1CTL0  = 0;                    // ② 8N1，LSB 先，UART    UCA1CTL1 |= UCSSEL_1;             // ② BRCLK = ACLK    UCA1BR0   = 3;  UCA1BR1 = 0;      // ② UCBRx = 3    UCA1MCTL  = UCBRS_3 + UCBRF_0;    // ② UCBRSx = 3，UCOS16 = 0    P4SEL    |= BIT4 + BIT5;          // ③ 引脚    UCA1CTL1 &= ~UCSWRST;             // ④ 运行    UCA1IFG  &= ~UCRXIFG;    UCA1IE   |= UCRXIE;               // ⑤ 接收中断} void uart_puts(const char *s) {        // 轮询发送一个字符串    while (*s) {        while (!(UCA1IFG & UCTXIFG));        UCA1TXBUF = *s++;    }}
#include "driverlib.h" void uart_init(void) {    GPIO_setAsPeripheralModuleFunctionOutputPin(GPIO_PORT_P4, GPIO_PIN4);  // UCA1TXD    GPIO_setAsPeripheralModuleFunctionInputPin(GPIO_PORT_P4, GPIO_PIN5);   // UCA1RXD     USCI_A_UART_initParam param = {0};    param.selectClockSource = USCI_A_UART_CLOCKSOURCE_ACLK;      // UCSSELx = 01    param.clockPrescalar    = 3;                                 // UCBRx    param.firstModReg       = 0;                                 // UCBRFx（UCOS16 = 0 不用）    param.secondModReg      = 3;                                 // UCBRSx    param.parity            = USCI_A_UART_NO_PARITY;    param.msborLsbFirst     = USCI_A_UART_LSB_FIRST;    param.numberofStopBits  = USCI_A_UART_ONE_STOP_BIT;    param.uartMode          = USCI_A_UART_MODE;    param.overSampling      = USCI_A_UART_LOW_FREQUENCY_BAUDRATE_GENERATION;  // UCOS16 = 0    if (USCI_A_UART_init(USCI_A1_BASE, &param) == STATUS_FAIL)        while (1);                                            // 参数不合法     USCI_A_UART_enable(USCI_A1_BASE);                            // UCSWRST = 0    USCI_A_UART_clearInterrupt(USCI_A1_BASE, USCI_A_UART_RECEIVE_INTERRUPT_FLAG);    USCI_A_UART_enableInterrupt(USCI_A1_BASE, USCI_A_UART_RECEIVE_INTERRUPT);} void uart_puts(const char *s) {    while (*s) {        while (!USCI_A_UART_getInterruptStatus(USCI_A1_BASE, USCI_A_UART_TRANSMIT_INTERRUPT_FLAG));        USCI_A_UART_transmitData(USCI_A1_BASE, *s++);    }}
中断使能放在哪一步

两种顺序都见得到：init → 开中断 → enable，或者先清 UCSWRST、再开 UCRXIE/UCTXIE。UCSWRST 置位时会把这两个使能位清零，所以本页按后一种写：先 enable()，再 enableInterrupt()。USCI_A1_BASE 这个基地址宏来自器件头文件。

driverlib 只是把 §5 的寄存器操作包成函数：init（复位 + 帧格式 + 时钟 + 波特率）→ enable（清 UCSWRST）→ enableInterrupt。波特率参数仍然要你自己算或查表。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01MSP430F5529 有几个 USCI_A、几个 USCI_B？哪一种能做 UART？

A。USCI_A：UART、IrDA、LIN 自动波特率、SPI；USCI_B：I2C、SPI（§1）。

02USCI_A1 的发送引脚 UCA1TXD 是哪一个？

B。P4.4 = UCA1TXD，P4.5 = UCA1RXD；P3.3 是 USCI_A0 的 TXD（§1）。

03CPU 往 UCA1TXBUF 写入一个字节之后，UCTXIFG 会怎样？

C。UCTXIFG 表示"TXBUF 能接收新数据"。双缓冲：前一个字节还在逐位发出时，就可以写下一个（§2）。

04BRCLK = 32768 Hz，9600 baud，UCOS16 = 0。按 §3 的方法，UCBRx 和 UCBRSx 是？

A。N = 3.4133；UCBRx = 3；0.4133 × 8 = 3.31 → 3。实际 9709 baud，误差约 1.1 %（§3）。

05UCA1CTL0 = UCPEN + UCPAR + UCSPB; 对应哪种帧格式？

D。UC7BIT = 0 → 8 位；UCPEN = 1、UCPAR = 1 → 偶校验；UCSPB = 1 → 2 个停止位（§5）。

06UCOS16 = 0（低频模式）时，最大波特率是多少？

B。低频模式最大波特率是 BRCLK 的三分之一。BRCLK/16 是 UCOS16 = 1 的上限（§3、§4）。

07BRCLK = 1048576 Hz，9600 baud，UCOS16 = 1。按 §4 的方法：

C。N/16 = 6.8267 → UCBRx = 6；0.8267 × 16 = 13.2 → UCBRFx = 13。A 是 UCOS16 = 0 时的值（§4）。

08初始化 USCI 的推荐顺序是？

A。只能在 UCSWRST = 1 时配置；UCSWRST 会清掉中断使能，所以开中断放在最后（§5）。

09新字符搬进 UCAxRXBUF 时，上一个字符还没被读。哪一位置 1？

C。overrun（sobreescritura）。UCOE 要靠读 UCAxRXBUF 清除（§6）。

10USCI_A1 的 ISR 里读到 UCA1IV = 0x04，说明什么？

B。0x02 = UCRXIFG（优先级最高），0x04 = UCTXIFG，0x00 = 没有（§7）。

11USCI_A_UART_init() 成功返回后，模块处于什么状态？

D。init 之后模块仍然禁用（remains disabled），enable() 清 UCSWRST（§8）。

12按 §8 的步骤把 driverlib 加进项目时，Predefined Symbols 里要加什么？

A。相当于每个文件开头 #define __MSP430F5529__，driverlib 据此按 F5529 编译（§8）。
