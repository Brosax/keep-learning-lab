§1LaunchPad 的四个区块 M12.1 · M12.2

一根 USB 线，既供电、又下载程序、又能当串口，还能让 F5529 自己做 USB 设备。板上是怎么分工的？Diagrama de bloques de la MSP-EXP430F5529LP.

LaunchPad（TI 对这类开发板的叫法）可以分成四个区块：电源与 hub、programador/depurador (ES) / debugger (EN)——下载调试器 eZ-FET、应用区（MSP430F5529）、jumpers de aislamiento (ES) / isolation jumpers (EN)——隔离跳线。下面一块一块搭起来：

点一个区块，看它的要点：

电源与 hub · Alimentación y hub USB

  • 默认由 USB 主机供电：VBUS = 5 V。
  • 5 V 经跳线送到目标 F5529，给它内置的 USB 外设用（开发 USB 设备时需要）。USB 设备也靠 VBUS 是否存在来判断主机是否接上。
  • 5 V 同时进 TPS62237（DC-DC）得到 3,3 V，经跳线给 F5529 供电。这条 3,3 V 还给 hub 和 eZ-FET 供电。
  • TUSB2046：4 口 hub，用了 2 个——一个给 eZ-FET，一个给 F5529 的 USB；另外两个口不用。所以一根线就能同时调试和开发 USB 应用。
  • 跳线之后，5 V（下图绿色）到 F5529、左侧排针 J1 顶上的 5V 针和左下角电源排针 J3（GND、GND、5V）；3,3 V（黄色）到 F5529、J1 顶上的 3V3 针和右下角电源排针 J10（GND、GND、3V3）。

下载调试器 · eZ-FET

  • 一颗 MSP430F5528（VQFN 封装，在板子右上方），被编程成 USB device。
  • 对 PC 是一个复合 USB 设备：一个接口用于下载和调试（Spy-Bi-Wire），一个接口是虚拟串口，接到 F5529 的 USCI_A1。
  • 板上有两个指示灯，表示它的状态（§2 有表）。

应用区 · Bloque de aplicación

  • MSP430F5529（LQFP 封装，板子中间的 U6）+ 40 针扩展口 + 2 个 LED + 4 个按钮 + 一个晶体 + 一个陶瓷谐振器 + 电容、电阻、跳线。
  • 板上的丝印标出了每个元件在原理图里的名字；按钮、LED、扩展针还标了接到哪个引脚（下面的板面图）。
  • 细节见 §3。

隔离跳线 · Jumpers de aislamiento

  • 位于调试区和应用区之间，分成三组：电源、串口、Spy-Bi-Wire。
  • 从左到右丝印是 GND、5V、3V3、RTS >>、CTS <<、RXD <<、TXD >>、SBW RST、SBW TST，最后一位没有丝印（N/C）。照片在 §2 的跳线模拟器下面。
  • 拔掉它们可以测目标电流、改用外部电源、把 eZ-FET 接到别的目标板（§2 的模拟器）。

§2eZ-FET：一个 USB 口，两个串口 M12.3 · M12.4

插上板子，Windows 的设备管理器里会多出两个 COM 口。为什么是两个？La conexión eZ-FET es un dispositivo USB compuesto.

eZ-FET 对 PC 来说是一个 dispositivo USB compuesto (ES) / composite USB device (EN)——复合 USB 设备：同一个设备里有两个接口。

细节

调试接口是 JTAG 的 Spy-Bi-Wire 版本。更准确地说：MSP430F5xx 同时支持标准的四线 JTAG 和两线的 Spy-Bi-Wire（SBW），而板上的 eZ-FET lite 只支持 SBW。两根线在跳线块上标作 "SBW RST" 和 "SBW TST"。两个接口在 PC 上都是虚拟串口（CDC 接口，虚拟 COM 口）。

什么时候拔跳线

  • 测目标电流：拔掉 3V3，在两针之间串电流表；hub、eZ-FET、DC-DC 的电流不计在内。要测得准，还要拔掉 UART 和 SBW 跳线，避免经 I/O 漏电。
  • 外接 3,3 V：必须拔掉 3V3，防止反向给 eZ-FET 供电。
  • UART 引脚另作他用：拔掉 UART 跳线；只需两个普通 I/O 时，可以只拔 RTS、CTS。
  • 调试别的目标板：拔掉跳线，把自己的板子接到跳线块上。

§3应用区：按钮、LED、时钟 M12.5

XT2 的频率

XT2 是 4 MHz 陶瓷谐振器（Q4，型号 CSTCR4M00），XT1 是 32,768 kHz 晶体（Q2，两边各接 12 pF 电容）。为什么这样选：32 kHz 晶体让 LPM3 的电流更低；4 MHz 谐振器精度 ±2500 ppm，主要给 USB 的 PLL 做参考时钟。

§4抽象的梯子 M12.6

同样是"让 LED 闪"，可以一条条写机器指令，也可以调一个函数。每往上爬一级，你放下了什么、又失去了什么？Niveles de abstracción: cuanto más subimos, más nos "desentendemos del hardware".

同一个闪灯程序，在三个层级上的样子：

        mov.w   #WDTPW|WDTHOLD, &WDTCTL   ; 停 watchdog        bis.b   #BIT0, &P1DIR             ; P1.0 设为输出bucle:  xor.b   #BIT0, &P1OUT             ; 翻转 LED1        mov.w   #50000, R15               ; 延时计数espera: dec.w   R15        jnz     espera        jmp     bucle
#include <msp430.h>volatile unsigned int i;int main(void) {    WDTCTL = WDTPW|WDTHOLD;      // Stop WDT    P1DIR |= BIT0;               // P1.0 set as output    while(1) {        P1OUT ^= BIT0;           // XOR P1.0        for(i=50000;i>0;i--);   // Delay    }}
WDT_A_hold(WDT_A_BASE);                        // 停 watchdogGPIO_setAsOutputPin(GPIO_PORT_P1, GPIO_PIN0);  // P1.0 设为输出while(1) {    GPIO_toggleOutputOnPin(GPIO_PORT_P1, GPIO_PIN0);    for(i=50000;i>0;i--);}

C 版本就是 TI 例程 MSP430F55xx_1.c（"Software Toggle P1.0"）；汇编版和 DriverLib 版按同样的逻辑写成，只是示意。

librerías · 优点

简单、可移植、好读

一份代码几乎不改就能用在另一颗有相同外设的 MSP430 上；函数名接近自然语言，更好维护。

librerías · 代价

可能不够优、也更大

面向一大批芯片的库，可能没提供某些选项、对某个外设不是最优，或者为一件小事带进太多代码。单片机内存紧张，这一点可能很要命。

TI 生态里的其他工具：ULP Advisor（Ultra-Low Power）帮你写更省电的代码；GRACE 用图形界面生成外设配置代码。

越往上越少管硬件：C 抽象掉内存映射，库抽象掉具体芯片，Energia 抽象掉开发板；代价是控制和效率。

§5为什么是 C M12.7

汇编最接近硬件，库最省事。这门课为什么偏偏选 C？C: un lenguaje de nivel medio.

答案是：C 是lenguaje de nivel medio (ES) / middle-level language (EN)——中级语言。它既能像汇编一样访问几乎所有硬件资源，又有高级语言的程序结构，还能让芯片架构对程序员"透明"。学术上的理由有四条：

  1. C 可能是单片机编程里用得最广的语言。
  2. C 帮你管理程序的复杂度。
  3. C 相对标准化：学会用 C 写一颗单片机，换一颗也用得上。
  4. 库越来越常用，而库通常是用 C 写的：会 C，才看得懂库是怎么实现的。

高级语言那一面

  • 用变量自动管理内存：只要给名字和类型，编译器/链接器就按内存映射找地方放它。
  • 函数：参数和返回值传数据，局部变量简化临时存储（对比汇编的子程序）。
  • 模块化：接口放 .h，实现放 .c。
  • 抽象硬件：MSP430 的指令集没有乘除法指令；C 里写 a * b，编译器会生成相应的机器码。有 hardware multiplier (EN)——硬件乘法器、编译选项里又选了用它时，编译器会配置它来算。

低级语言那一面

  • 指针：直接操作内存地址——指向变量，也可以指向函数的起始地址。
  • 精确指定数据大小：单片机内存很紧，这很重要。
  • 编译器扩展（非标准）：指定变量放在哪个地址；把函数定义成中断服务程序（M21 的 #pragma vector / __interrupt）。
学 C 写单片机，需要先会什么？

四条：C 的一般基础（假定大家已经会）；目标单片机的架构（M11、M12 起陆续讲）；所用 IDE 的 C 编译器（后面各章逐步讲）；单片机的汇编。最后一条很有争议：懂汇编有帮助，特殊情况下能写出更优的 C，但只要足够了解架构就不是必须的，所以课程不强调汇编。

对照：只有部分 MSP430 有硬件乘法器（作为外设）；F5529 就有。

C 是中级语言：高级的结构（变量、函数、模块）+ 低级的能力（指针、数据大小、中断函数），所以适合单片机。

§6工具链：编译、汇编、链接 M12.8

存储器里只能放 0 和 1。一行 C 是怎样变成 CPU 能取的位的？Flujo de desarrollo software: del código fuente al código máquina.

先看最底下两层。código máquina (ES) / machine code (EN)——机器码：描述要执行的指令及其操作数大小、个数和位置的位模式。lenguaje ensamblador (ES) / assembly language (EN)——汇编语言：机器码的符号表示，每条指令用一个 nemónico (ES) / mnemonic (EN)——助记符表示，一条汇编生成一条机器指令。例子："把 R3 的低字节送到 R8 的低字节"：

再看翻译程序。三个定义：

programa ensamblador

汇编器

把汇编源代码翻成机器码目标代码（código objeto），这叫"汇编"。另外提供：伪指令（directivas）、标签（代表地址的符号）、表达式、多种数制、宏。

compilador

编译器

把 C 源代码翻成汇编代码（也还是源代码），之后再汇编、链接。另外提供：伪指令、特殊函数（中断服务程序）、访问硬件的内建函数（intrínsecas）、数学和浮点库。

enlazador / linkador

链接器

把多个目标代码文件——你的代码和用到的库（标准库或别的库）——合成一个可执行的机器码文件。就算只有一个源文件也要链接：只有链接器掌握内存映射。

用一小段汇编把"汇编"和"链接"两步串起来：

编译器那一步也有一个例子：一个 for 循环编译出来的汇编。输出仍然是源代码，之后还要汇编、链接。

for (cont = 0; cont < 10; cont++) {    array[cont] += 32;}
          MOV.W   #0x0, R15        ; cont = 0，cont 放在 R15          JMP     ??main_1         ; 先去判断条件??main_0: MOV.W   R15, R14          RLA.W   R14              ; R14 = 2·cont（int 占 2 字节）          ADD.W   SP, R14          ; + SP：array 是栈上的局部数组          ADD.W   #0x20, 0(R14)    ; array[cont] += 32          ADD.W   #0x1, R15        ; cont++??main_1: CMP.W   #0xa, R15        ; cont < 10 ?          JL      ??main_0         ; 是 → 再做一遍循环体

指令是这段 C 编译出来的汇编。编译器替你做了 §5 说的那些事：变量 cont 放进寄存器 R15，局部数组 array 放在栈上（相对 SP），下标乘 2 换成字节地址；??main_0 这样的标签是编译器自己生成的。

IDE (Integrated Development Environment)——集成开发环境，把整条流程集中起来：编辑器、汇编器、编译器、链接器、调试器、模拟器、库、工程管理……课程用的是 CCS + TI 自己的编译器。

为什么是 CCS

MSP430 常用的开发环境有三个：TI 的 Code Composer Studio、IAR Embedded Workbench、开源的 MSPGCC。CCS 和 IAR 的免费授权可能有时间或代码量限制；GCC 的支持不如商业编译器。现在 CCS 加 TI 编译器对 MSP430 没有限制，所以课程用它；大部分示例也能用 GCC 编译。具体地说：到 CCS v6 为止 TI 编译器的免费版限制代码量，CCSv7 起取消了，所以 TI 和 GNU 编译器都可以选。

C →（编译器）→ 汇编 →（汇编器）→ 目标代码 →（链接器 + 库）→ 可执行代码 →（eZ-FET/SBW）→ FLASH。

§7CCS：workspace、project、build M12.9

CCS 一打开就问你要一个文件夹。它要拿这个文件夹做什么？Espacio de trabajo y proyecto.

espacio de trabajo (ES) / workspace (EN)——工作区

最高一层：把一个应用相关的工程都放在一起。CCS 启动时先弹出 Code Composer Studio Launcher（下图）："Select a directory as workspace"，在 Workspace 栏填路径或按 Browse…，再按 Launch；新建时，在指定位置建一个文件夹，存放所有新建或导入的工程。对话框里的 Use this as the default and do not ask again 一旦勾上，以后就不再问（要换用 File – Switch Workspace，见 §8 常见问题）。最好起个有意义的名字，例如 workspace_msp430。

proyecto (ES) / project (EN)——工程

一起编译、汇编、链接成一个可执行程序的所有源文件。每个工程有自己的配置，包括目标芯片和编译/链接工具（见下面的工程属性表）。新建或导入工程时，workspace 里会多一个和工程同名的文件夹。

  • 加文件：Project – Add Files，选 Copy Files（复制进工程）或链接到原来位置上的文件；也可以直接拖进 Project Explorer。

安装和版本，一句话

安装时以 CCS 10.2 为例：自定义安装，只勾 MSP430 ultra-low power MCUs，装完重启。本章的操作步骤按 CCSv8 写，课程现在链接的是 CCS 12.4.0，界面略有差别但不影响。另外两条提醒：workspace 路径里不要有重音字母、ñ 这类字符，只用英文字母和数字；不要把 workspace 搬到别的电脑，要用"导出工程 → 在新电脑导入"。

常见问题
  • could not open source file…：#include 的路径没加进工程配置。
  • Error initializing emulator: No USB FET was found：板子没连好（检查线的两端），或驱动安装有问题。
  • Debug 视图里的运行/调试图标不见了：确认板子已连接、程序已下载，再 View – Debug。
  • CCS 不再询问 workspace：File – Switch Workspace；想每次都问，在 Window – Preferences 里打开 Prompt for workspace on startup。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01课程用的开发系统由哪三部分组成？

A。开发板 + 开发调试环境 CCS + 软件包 MSP430ware（§0）。

02LaunchPad 上 5 V 和 3,3 V 分别给 F5529 做什么用？

C。MSP430 的工作电压是 1,8–3,6 V，所以 3,3 V 给芯片；5 V 用于 F5529 的 USB 外设，开发 USB 设备时需要（§1）。

03为什么插上 LaunchPad 后，设备管理器里会出现两个 COM 口？

B。MSP Debug Interface + MSP Application UART1，后者接 F5529 的 USCI_A1（§2）。

04板上的 eZ-FET lite 用什么接口下载和调试 F5529？

D。F5xx 支持四线 JTAG 和 SBW，但 eZ-FET lite 只支持 SBW；两根线在跳线块上叫 SBW RST、SBW TST（§2）。

05想测 F5529 本身的电流（不含 hub 和 eZ-FET），应该怎么做？

A。3V3 跳线就是目标的 3,3 V 供电；要测得更准，还应拔掉 UART 和 SBW 跳线（§2）。

06按下 S2 时，P1.1 读到什么？

C。S2 → P1.1，S1 → P2.1；按钮另一端接地、板上没有外接电阻，所以要用片内上拉，按下 = 0（§3）。

07跳线 JP8 是做什么的？

B。P1 口有中断能力，需要 P1.0 作中断输入时可以拔掉 JP8（§3）。

08关于 MSP430 DriverLib 这类库，哪一句符合 §4 的说法？

D。把开发板抽象掉的是 Energia，不是 DriverLib（§4）。

09下面哪一项属于 C 的"低级语言"特性？

A。B、C、D 都是高级语言那一面的优点（§5）。

10按 §6 的定义，编译器的输出是什么？

C。C → 汇编（编译器）→ 目标代码（汇编器）→ 可执行代码（链接器）（§6）。

11工程只有一个 main.c，还需要链接器吗？

B。就算只有一个源文件也要链接，这一点要特别记住（§6）。

12调试时想让程序每次执行到 P1OUT ^= BIT0; 都自己停下，并看 P1OUT 怎么变，应该怎么做？

A。这正是 §8 调试模拟器里的练习；两次暂停之间变了的寄存器会标黄（§8）。
