# 课程制作指南 · Keep Learning Lab

这个文件夹说明**怎样把一门公开课加工成本站的课程**，以及怎样修订已有课程。人和 AI 都按同一套流程做。

| 文件 | 用途 |
|---|---|
| [README.md](README.md) | 总流程（本文） |
| [lesson-schema.md](lesson-schema.md) | 课程 JSON 格式：哪些字段必填，哪些按需 |
| [module-decision.md](module-decision.md) | 什么时候加图示、交互实验、代码演示、练习 |
| [checklist.md](checklist.md) | 提交前逐项核对 |
| [prompts/redesign-course.md](prompts/redesign-course.md) | 交给 AI 的完整提示词：新增或重做一门课 |
| [prompts/review-lesson.md](prompts/review-lesson.md) | 交给 AI 的提示词：逐讲审查 |

## 三条原则

1. **讲义优先。** 每一讲的结构、术语、例子和顺序都跟着老师的讲义走。我们做的是"讲清楚老师讲的内容"，不是另写一门课。每个段落都要用 `source` 注明讲义和页码。
2. **形式服从内容。** 图示、交互实验、代码演示和练习都**按需添加**，不是每讲的固定配置。一讲只有文字和自测也完全可以。
3. **没有资料就说没有。** 讲义没公开的讲次，用 `sourceStatus` 写清楚，只依据课表、阅读材料或作业整理，不能编造"老师讲了什么"。

## 流程

```
1 资料盘点 → 2 讲义大纲 → 3 写正文 → 4 决定模块 → 5 自测题 → 6 构建与测试 → 7 浏览器检查
```

### 1. 资料盘点

- 原始资料放在 `zh/<课程>/materials/`，清单在 `zh/<课程>/sources.json`，里面记录了来源 URL、sha256 和讲次对应关系。
- 列出每一讲对应的讲义文件。一讲可能对应多个文件（例如新旧两个学期的幻灯片）；**以当前学期为主**，旧学期只作补充，并且要注明。
- 当前学期还没发布的讲次，可以用往年同主题讲义。这时 `source` 要写年份，例如 `Lecture 8 (2025)`；讲次页再加 `sourceStatus` 说明。一份往年讲义被拆给两讲用也可以，各讲引用自己那部分的页码。正文里的"第几讲"一律用**本站的讲次编号**，不要沿用往年讲义里的编号。
- 官方考试题和答案可以当作资料，用来出自测题或手算例题，但要在 `source` 里注明。如果课程作业要求学生先独立做这套题，就在 `assignments` 里提醒一句。
- 只用官方公开资料。新下载的资料要写进 `sources.json`，并注明许可。

### 2. 讲义大纲（写正文之前）

逐讲阅读讲义，先产出一份大纲，再动笔：

- **幻灯片（PDF）**：多数讲义开头都有 agenda 页，就以它作为这一讲的骨架。幻灯片以图为主，`pdftotext` 抽出的文字不完整，必须**直接看页面**（Claude 的 Read 工具可以按页读 PDF：`pages: "1-20"`）。
- **讲稿代码（`.py`）**：例如 CS336 的 `lecture_XX.py` 本身就是讲稿，按函数顺序读。
- **讲义笔记**：例如 CS229 的 notes，按小节标题读。

大纲的每一条都要写清楚：讲义里的小节名、页码范围、老师用的关键例子或公式。

### 3. 写正文

- `sections` 的顺序对应讲义的顺序，**数量由讲义决定**，不要固定写成 4 段。
- 用中文讲解老师的意思，保留英文术语原文，例如"自注意力（self-attention）"。
- 用老师自己的例子和记号。需要补充时，标注"补充："并说明理由。讲义只有公式没有数字时，可以补一组数字来演示，标"补充"；从截图读出来的数值标"补充（读图推断）"。
- 讲义里只在图上出现、老师没有讲解的标签（例如图注里的一个术语），不要展开成一段正文。
- **不要跨讲预支内容。** 第 1 讲没讲 RoPE，就不要在第 1 讲的例题里用 RoPE。
- 不要整段翻译或照抄讲义，用自己的话解释，并配上出处。

### 4. 决定模块

参照 [module-decision.md](module-decision.md)，逐讲决定是否需要以下模块：

| 模块 | 字段 |
|---|---|
| 交互图示 | `visual` |
| 代码演示 | `codeDemo` |
| 静态流程图 | 段落里的 `flow` |
| 对比表 | 段落里的 `table` |
| 手算例题 | `kind: "worked-example"` |
| 动手练习 | `exercise` |

每加一个模块，都要能说出"它解释了哪一页讲义上的什么内容"。

### 5. 自测题

- 每讲至少 2 题，每题 4 个选项，并附带解析（说明错误选项错在哪里）。
- 题目考的是本讲讲义里的内容。
- 已有题目能保留就保留。只有在题目和讲义矛盾，或者考的是本讲讲义没讲的内容时才改。题目一旦修改，就要递增课程的 `quizRevision`：学习者旧的答题记录会被清空，但笔记和学习目标的进度不受影响。
- 全课程正确答案在 A–D 四个位置上要大致均衡（测试要求最多和最少相差不超过 2），题目之间不能重复。解析里不要用"选项 B"这种位置来指代，要写出选项内容。

### 6. 构建与测试

```bash
python scripts/sync-lesson-references.py <课程>    # 按讲次 resources 同步 sources.json 里的 lesson_references
python scripts/build-courses.py                    # 修改 content/*.json 后必须运行，会更新 data.js 和缓存哈希
node scripts/test-reviewed-course.mjs <课程>        # 课程结构、模块、数值校验
node scripts/test-courses.mjs                      # 所有课程的路由、进度、搜索
python scripts/validate-courses.py                 # 资料链接与格式
```

测试依赖 linkedom，安装方法见根目录 README。图示和代码的数值正确性由 `scripts/oracles/<课程>.mjs` 独立验证：**有模块的讲次必须有 oracle，没有模块的讲次不能有**。

### 7. 浏览器检查

本地起一个静态服务器（`python -m http.server`），至少检查以下几处：

- 一讲有交互图示的课
- 一讲没有任何模块的课
- 手机宽度（375px）下的显示

## 稳定性约定（不要破坏学习者的数据）

- **讲次 `id` 和顺序不变。** 学习进度按 `L<id>.<目标序号>` 保存。
- 学习目标 `objectives` **保持原有数量**。内容可以改，但数量变了会让已勾选的进度错位。
- 不要在 JSON 里自创字段（例如 `answerKey`、`spare`）。需要新字段时，先改渲染器、测试和 [lesson-schema.md](lesson-schema.md)。
- `localStorage` 的键名（`open-seei-*`、`<课程>-web-v1`）不要改。
