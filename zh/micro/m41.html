§0为什么要换一种架构 M41.1

MSP430F5529 已经学了三个 Bloque，为什么最后还要学一颗完全不同的芯片？¿Por qué otra arquitectura?

MSP430 的强项是超低功耗和简单。可是设备如果要联网（Wi-Fi、Bluetooth），或者要跑更重的计算，就需要另一类芯片。先把两颗芯片并排放在一起，看看量级差多少：

MSP430F5529ESP32-S3
CPU16 位 RISC（CPUX，扩展内存）Xtensa 32 位 LX7，双核；单精度 FPU、SIMD 指令
主频最高 25 MHz最高 240 MHz
片上存储Flash 128 KB · SRAM 8 + 2 KBROM 384 KB · SRAM 512 KB · RTC SRAM 16 KB
程序存在哪片上 flashflash：芯片可选封装内 flash；WROOM-1 模块上最多 16 MB Quad SPI flash
I/O63 个 I/O（80 引脚 PN 封装）芯片 45 个 GPIO；WROOM-1 模块引出 36 个
无线没有Wi-Fi 802.11 b/g/n（2.4 GHz）+ Bluetooth LE 5
USBFull-speed USB（集成 PHY）Full-speed USB OTG + USB Serial/JTAG 控制器
供电1.8 – 3.6 V3.0 – 3.6 V
低功耗LPM3 1.9 µA（2.2 V）/ 2.1 µA（3.0 V）；LPM4.5 0.18 µADeep-sleep 7 µA（只有 RTC 域供电）

功耗都是典型值，两颗芯片的测试条件不同，只能看量级。

ESP32-S3 不是"更大的 MSP430"，而是为另一类应用设计的：联网和算力。中断、复位、时钟、低功耗、外设这些概念都还在，只是规模和名字变了（§1 有对照表）。

§1芯片里有什么 M41.2 · M41.3

一颗 7 × 7 mm 的芯片里，装着哪些东西？Diagrama de bloques funcional del ESP32-S3.

下面是芯片功能框图的简化版。点任意一块（或下面的按钮），说明会显示在图下方。

Xtensa® LX7 双核 · CPU0 / CPU1

两个 32 位 Xtensa LX7 核心，主频最高 240 MHz；五级流水线、单精度 FPU、128 位数据总线和专用 SIMD 指令（面向 AI 和 DSP 算法）。CoreMark：双核 240 MHz 时 1329.92 分。对比 F5529：一个 16 位 CPU，最高 25 MHz。调试窗口里能同时看到两个核（§5）。

存储 · ROM / SRAM / Cache

384 KB ROM（启动和核心函数）、512 KB 片上 SRAM（数据和指令）。程序本身放在 flash 里：可以是芯片封装内的 flash，也可以是外部 flash（WROOM-1 模块上最多 16 MB），经 SPI0/1 接口和 cache 映射到 CPU 的地址空间。另有 4096 位 eFuse（一次性编程，1792 位留给用户）。

RTC 与低功耗 · ULP 协处理器

RTC 域在 Deep-sleep 时仍然供电：16 KB RTC SRAM（8 KB fast + 8 KB slow）、RTC GPIO、RTC watchdog、PMU（电源管理单元）。两个 ULP coprocessor (EN)——超低功耗协处理器（ULP-RISC-V 和 ULP-FSM，二者不能同时工作）在睡眠时代替主 CPU，读 RTC GPIO 和传感器。四种功耗模式：Active、Modem-sleep、Light-sleep、Deep-sleep；Deep-sleep 7 µA。

Wi-Fi · IEEE 802.11 b/g/n

2.4 GHz，20 MHz 和 40 MHz 带宽，1T1R 模式下最高 150 Mbps；可以工作在 Station、SoftAP，或 Station + SoftAP 模式。MAC 和 baseband 都在片上。

Bluetooth LE · Bluetooth 5

Bluetooth 5、Bluetooth Mesh；速率 125 Kbps、500 Kbps、1 Mbps、2 Mbps；高功率模式最高 20 dBm。和 Wi-Fi 共用同一根天线（芯片内部有共存机制）。芯片的功能列表里只有 LE。

RF · 2.4 GHz

射频部分：2.4 GHz 接收器、发射器、频率合成器（RF synthesizer）、balun + 开关。MSP430F5529 完全没有这一块。天线不在芯片里：WROOM-1 模块上是 PCB 天线，WROOM-1U 是外接天线座（§2）。

Interrupt Matrix · 中断矩阵

99 个外设中断源作为输入，分配到 CPU0 的 26 个外设中断和 CPU1 的 26 个外设中断（每个核另有 6 个内部中断）。和 MSP430 的固定向量表（M21）不同：哪个外设的中断送到哪个核、哪个中断号，是可以配置的。

Clock · 时钟

CPU 时钟有三个来源：外部主晶振、内部 fast RC（约 17.5 MHz，可调）、PLL；复位后默认是外部主晶振二分频。没有外部主晶振，芯片无法工作——WROOM-1 模块里有一颗 40 MHz 晶振。RTC slow clock 可以来自外部 32 kHz 晶振、内部 slow RC（约 136 kHz）或 fast RC 的 256 分频。

Security · 安全

Secure boot、flash encryption；SHA、AES、RSA、HMAC 硬件加速器，RSA 数字签名外设（RSA_DS），随机数发生器（RNG）。联网设备要保护固件和密钥，所以这些都做进了芯片。

外设 · Peripherals

UART ×3、I2C ×2、I2S ×2、通用 SPI ×2（SPI2/3）、TWAI（兼容 CAN 2.0）、full-speed USB OTG、USB Serial/JTAG、SD/MMC host、LED PWM（最多 8 通道）、MCPWM ×2、RMT、脉冲计数器、LCD 和 camera 接口；两个 12 位 SAR ADC（最多 20 通道）、14 个电容触摸 IO、温度传感器；4 个 54 位通用定时器、52 位系统定时器、3 个 watchdog；GDMA 5 发 5 收。

45 GPIO · IO MUX · GPIO Matrix

45 个可编程 GPIO，其中 4 个是 strapping 引脚（GPIO0、GPIO3、GPIO45、GPIO46），复位时被采样，决定启动方式等配置（§2）。封装内有 flash 或 PSRAM 时，还要占用 6 或 7 个 GPIO。每个引脚接哪个外设，由 IO MUX 和 GPIO Matrix 决定（下面的动画）。

在 MSP430 上学过的概念，在 ESP32-S3 上叫什么

概念MSP430F5529（前几章）ESP32-S3
中断固定向量表 0xFF80–0xFFFF（M21）Interrupt Matrix：99 个源 → 每个 CPU 26 个外设中断，可配置
复位BOR ⊃ POR ⊃ PUC（M21）四级：CPU Reset、Core Reset、System Reset、Chip Reset
时钟UCS：XT1、XT2、DCO + FLL、REFO、VLO（M24）外部主晶振（必需）、fast RC、PLL；RTC slow clock

IO MUX 与 GPIO Matrix M41.3

外设很多，引脚只有 45 个，所以必须 multiplexación de pines (ES) / pin multiplexing (EN)——引脚复用，由软件写寄存器控制。分两层：

  • IO MUX——引脚复用器：每个 GPIO 有一个配置寄存器 IO_MUX_GPIOn_REG，可以在 5 个功能（F0–F4）中选一个：要么经 GPIO Matrix 转接，要么直接连到某些外设。
  • GPIO Matrix——GPIO 矩阵：外设信号和引脚之间的全交换矩阵。175 路外设输入可以来自任何 GPIO，任何 GPIO 的输出可以来自 184 路外设输出中的任何一路。

MSP430 的 PxSEL 是在"GPIO / 固定的外设功能"之间选择；ESP32-S3 的 GPIO Matrix 让外设和引脚之间几乎可以任意连接，需要高速的信号再走 IO MUX 直连。两者本质上都是写寄存器。

§2芯片、模块、开发板 M41.4 · M41.5

你桌上那块板子，是芯片、模块，还是开发板？Chip ESP32-S3 → módulo ESP32-S3-WROOM-1 → placa ESP32-S3-DevKitC-1.

Auto-program：DTR、RTS 怎样把芯片送进下载模式 M41.5

先看启动方式。复位释放的那一刻，芯片采样 strapping pins (EN)——启动配置引脚，把值锁存下来；之后这些引脚就当普通 GPIO 用。启动方式由 GPIO0 和 GPIO46 决定：

启动方式GPIO0GPIO46做什么
SPI Boot（默认）1任意从 flash 启动，运行你的程序
Joint Download Boot00等待通过 USB（USB-Serial-JTAG 或 USB-OTG）或 UART 下载程序

默认值：GPIO0 有弱上拉（= 1），GPIO46 有弱下拉（= 0）。所以什么都不接时，芯片按 SPI Boot 运行程序。

所以"烧录"的关键是：EN 释放的那一刻，让 GPIO0 = 0。手动的办法是按住 BOOT，按一下 RST，再松开 BOOT。DevKitC-1 用两只三极管把 CP2102N 的 DTR、RTS 两根线变成 EN 和 IO0，真值表如下（点一行试试）：

DTRRTSENIO0效果
1111不干预，芯片照常运行
0011不干预，芯片照常运行
1001EN = 0：芯片保持复位
0110IO0 = 0：如果此刻正好释放复位 → 下载模式
读这张真值表

两根线同为 1 或同为 0 时，EN 和 IO0 都是 1（0 / 1 按原理图表格的约定）：串口软件把这两根线一起拉高或拉低，不会误复位芯片。"自动"按钮演示的是这张真值表能实现的一种顺序（不一定是烧录工具实际用的顺序）：先 (1, 0) 把芯片按在复位里，再 (0, 1) 在 IO0 = 0 时释放复位。

插在 "USB" 口（原生 USB）时不需要这套电路：USB Serial/JTAG 控制器本身支持由主机控制的芯片复位和进入下载模式。

RGB LED 接 GPIO38 是 v1.1 版开发板的接法；早期的 v1.0 版接在 GPIO48（板上丝印 RGB@IO48）。写程序前先看一眼自己板子上的丝印。

§3工具链：ESP-IDF 由哪几层组成 M41.6

在 CCS 里点一下 Build 就完了。ESP32-S3 的 "Build" 背后站着哪些工具？Toolchain, CMake/Ninja, OpenOCD, ESP-IDF y Espressif-IDE.

开发环境由四种工具组成，再加一个图形界面。从下往上搭起来：

安装要点（摘要）

  • EIM（在线安装器，约 34 MB）→ 选 Custom Installation，目标芯片选 ESP32-S3。
  • 版本：课程指定的 v6.0.2 或 6.0.3，不一定是最新的；列表里没有就勾选 "Show old stable versions"。
  • 功能包：必选的 core，再加 ide；工具只装默认的，不需要 qemu。
  • 路径：默认 C:/esp；Espressif-IDE 建议解压到 C:/Espressif/tools/Espressif-IDE；workspace 路径同样不要有特殊字符。
  • 驱动：以管理员身份再开一次 EIM → Open Dashboards → Install Drivers，只需要做一次。
  • Espressif-IDE 4.3.0：前提是 Git、Python 和 Java 21+；第一次启动时激活 v6.0.2（以后在 Espressif → ESP-IDF Manager 里切换）。
注意 · Python 版本

安装指南前后两处对 Python 版本的要求不一样（> 3.10 和 > 3.12）；手动安装时按较高的要求。EIM 会自动检查并安装 Python。

vault 的约定

ESP-IDF 不支持路径里有空格，而这个 vault 的路径里有空格。所以 ESP32 工程不放在 vault 里，放到像 SEEI-code\ 这样不带空格的文件夹，笔记里链接过去。

§5调试链：从 IDE 到两个 CPU M41.8

在 CCS 里按一下 Debug 就能单步。在 ESP32-S3 上，这一下要穿过几层？Espressif-IDE → ESP-GDB → OpenOCD → JTAG.

  • 硬件：线插 "USB" 口；在设备管理器里记下 "Dispositivo serie USB" 的 COM 口，Launch Target 里选芯片和这个 COM 口。
  • 一次性：设置 Global OpenOCD Path，重启 IDE。
  • 每个工程：先 build；然后 Debug As → Debug Configurations，新建一个 "ESP-IDF GDB OpenOCD Debugging" 配置，选项保持默认，按 Debug。IDE 会先烧录，再连 JTAG，并提示切换到调试视图。
# PowerShell 1（IDF_v6.0.2_Powershell 快捷方式）：开着别关openocd -f board/esp32s3-builtin.cfg # PowerShell 2：进入要调试的工程文件夹idf.py gdbgui

在 IDE 里调试不成时的备选办法：先关掉 Espressif-IDE，免得它占着连接；提示符变成 (gdb) 之后，就用 GDB 命令调试。

调试链 = 界面（Espressif-IDE）→ 调试器（ESP-GDB）→ 桥（OpenOCD）→ 片内 USB Serial/JTAG → CPU0 / CPU1。哪一环没连上，就从那一环查起：OpenOCD 路径、COM 口、超时。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01ESP32-S3 的 CPU 是？

B。双核 32 位 LX7（CPU0、CPU1），最高 240 MHz。A 是 MSP430F5529（§0、§1）。

02ESP32-S3 片上集成了哪些无线功能？

C。Wi-Fi（2.4 GHz，802.11 b/g/n）+ Bluetooth LE（Bluetooth 5），两者共用一根天线（§1）。

03ULP 协处理器是做什么用的？

A。ULP-RISC-V / ULP-FSM 和 RTC 内存在 Deep-sleep 时仍然供电，可以代替主 CPU 值班（§1）。

04关于 GPIO Matrix 和 IO MUX，哪一句是对的？

D。矩阵灵活但有延迟代价；需要高频性能的信号走 IO MUX 直连（§1）。

05哪些东西在 WROOM-1 模块上，但不在 ESP32-S3 芯片里？

B。A、D 在芯片里；C 在开发板 DevKitC-1 上，不在模块里（§2）。

06按 V1.1 原理图，DevKitC-1 上的 RGB LED 由哪个 GPIO 控制？

C。RGB_CTRL = GPIO38。GPIO0、GPIO46 是 strapping 引脚，GPIO19 是 USB D−（§2）。

07按 §2 的真值表，DTR = 1、RTS = 0 时会怎样？

A。真值表：10 → EN 0、IO0 1；01 → EN 1、IO0 0；11 和 00 → 都是 1。EN 和 IO0 永远不会同时为 0（§2）。

08复位释放时 GPIO0 = 0、GPIO46 = 0（默认），芯片进入什么模式？

D。GPIO0 = 1 才是 SPI Boot。strapping 值在复位释放时被锁存（§2）。

09Espressif-IDE 4.3.0 除了 Git 和 Python，还需要什么？

B。Espressif-IDE 是定制的 Eclipse，需要 Java 21+。qemu 在 EIM 里明确不用装（§3）。

10哪个安装路径最符合本章的建议？

C。C:/esp 是默认路径；其他三个含有 ñ、空格或重音（§3）。

11调试链的正确顺序是？

A。GDB 连 OpenOCD，OpenOCD 经 "USB" 口连片内 USB Serial/JTAG（§5）。

12调试时报 "Process not Terminated"（OpenOCD 与 JTAG 之间超时），本章建议怎么做？

B。另外两个办法：马上再按一次 Debug；或在 Startup 标签取消 "Flash every time with application binaries"（§5）。
