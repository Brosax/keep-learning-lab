§1什么是嵌入式系统 T1.1 · T1.2

路由器、车里的控制器、导航仪都是"电脑"。它们和桌上的 PC 差在哪里？Un sistema empotrado es un sistema informático de uso específico.

一个 sistema empotrado / integrado / embebido (ES) / embedded system (EN)——嵌入式系统，是专门用途的计算机系统。和通用 PC 比，有三点不同：

  • 用途单一：为某个具体任务设计，而不是什么都能干。
  • 板上集成：PC 里插卡的东西（显卡、声卡、调制解调器……）大多直接做在主板上。
  • 在另一台机器上编程：程序不在设备本身上开发，而是在一台 PC 上写好、编译好再放进去。§4 的交叉开发就是从这一点来的。

这个定义很宽，涵盖了很多完全不同的产品：消费电子（DVD 播放器、数码相机、游戏机）、通信设备（手机、路由器、卫星）、工业产品（过程控制、航空电子、汽车电子）。

为什么用 Linux

优点

  • 复用现成组件：内核、编译器、库都有，团队只需专注产品自己的部分。
  • 质量高：Linux kernel、GCC、C 库都经过大量使用的检验。
  • 完全掌控：源代码都在手里，每个组件都能改。
  • 社区支持。
  • 成本低：没有 royalties（按件收取的授权费）。

谁在用

  • GPS 导航仪（TomTom、Garmin）
  • 家用路由器（Linksys、Netgear）
  • 电视、相机、DVD 播放器（Sony、Philips）
  • 平板和手机：Android 的底层就是 Linux kernel

微控制器还是微处理器

嵌入式硬件和 PC 很不一样：CPU 架构五花八门（ARM、MIPS、PowerPC、x86），存储用容量有限的 Flash，RAM 也有限，还有 PC 上少见的总线（I2C、SPI、SSP、CAN）。Linux 对硬件有最低要求：

项目Linux 的最低要求
CPU32 位，并且 GCC 和 Linux kernel 都支持这种架构
MMU标准 Linux 需要；没有 MMU 的 CPU 走 uClinux 项目
RAM至少 8 MB，才能做点实际的事
存储至少 4 MB

MMU (Memory Management Unit)——内存管理单元，负责把程序看到的虚拟地址翻译成物理地址，并检查每次访问有没有越权。Linux 靠它给每个进程一个独立的地址空间，一个进程写坏了内存，不会踩到别的进程或内核。MSP430 这类单片机没有 MMU，所有代码共用一个物理地址空间。

几 KB RAM · 微控制器

bare metal

没有操作系统：程序直接操作寄存器，一个 main() 加中断。MICRO 课上的 MSP430 就是这样。Linux 不是为只有几 KB 内存的微控制器设计的。

微控制器 · 需要多任务

FreeRTOS 等 microkernel

很小的实时内核，提供任务、调度、同步，但没有进程隔离和文件系统那一整套。

32 位 MPU + MMU + MB 级内存

Linux

完整的操作系统：进程、文件系统、网络协议栈、驱动。这门课用的 Raspberry Pi 属于这一类。没有 MMU 的 32 位芯片也能跑，靠 uClinux。

嵌入式系统 = 专用 + 在别的机器上开发。要不要放 Linux，看硬件够不够：32 位 CPU、有 MMU（否则 uClinux）、RAM 至少 8 MB、存储至少 4 MB。更小的芯片用 bare metal 或 FreeRTOS。

§2ARM：架构、寄存器、两套指令集 T1.3 · T1.4 · T1.5

为什么几乎每部手机里都有 ARM？ARM (Advanced RISC Machines): arquitectura RISC de 32/64 bits.

ARM (Advanced RISC Machines) 是 ARM Holdings 设计的 32/64 位 RISC——精简指令集架构。结构简单，所以功耗低：2005 年已有 98% 的手机至少用了一颗 ARM 处理器。要注意它的商业模式：ARM 自己不造芯片，只设计内核并授权给芯片厂商（Raspberry Pi 用的 Broadcom 芯片就是这样来的）。

架构特点

  1. load/store：只有 load/store 指令能访问内存，其余指令只操作内部寄存器。
  2. 内存对齐：数据要放在对齐的位置。
  3. 32 位模式：16 个同样的 32 位寄存器；64 位模式：31 个 64 位寄存器。
  4. RISC 指令集，定长 32 位。
  5. 32/64 位地址空间。
  6. 大多数指令一个周期执行完。
  7. 指令可以条件执行。
  8. 32 位 barrel shifter——桶形移位器。
  9. 有返回地址寄存器（link register）。

32 位模式的 16 个寄存器

  • R0–R12：通用寄存器。
  • R13 = SP：栈指针。
  • R14 = LR：link register——链接寄存器。BL 调用子程序时，把返回地址存在这里，不压栈。
  • R15 = PC：程序计数器，也是 32 位。
  • CPSR：当前程序状态寄存器，存条件标志、处理器模式，以及"现在是 ARM 还是 Thumb"。

处理器有几种模式：应用程序在用户模式运行；Supervisor（SVC）模式给操作系统内核用。进入 SVC 模式时，CPSR 会被备份到 SPSR，好在返回时恢复。§3 的系统调用就靠这个切换。

两套指令集：ARM 和 Thumb

默认的 ARM 指令是 32 位。从 ARMv4T 指令集开始，加了一套 16 位的 Thumb 指令集。芯片名里的 T（ARM7TDMI、ARM9TDMI……）就表示支持 Thumb。ARMv5TE 又改进了两种模式之间的切换。

Thumb 指令长度减半，好处是代码密度高、可执行文件小。代价是有些事做不了或要多花指令。下面是同一个 Thumb 指令怎样对应到 ARM 指令：

处理器内部其实只有一套指令集（ARM）。在 Thumb 状态下，专门的硬件把内存里取来的 16 位 Thumb 指令先展开成 32 位 ARM 指令再执行，这一步不花额外时间。

Thumb 的限制

  • 寄存器集合缩小：大多数指令只能用 R0–R7（"Lo"寄存器）；R8–R15（"Hi"）只有 MOV、ADD、CMP、BX 能用。
  • 有些指令要拆成两条，比如带链接的长跳转 BL 由两条 16 位指令组成。
  • 有些操作做不了：访问协处理器、访问状态寄存器。

省了多少

两个小函数分别编译（arm-linux-gcc -c 和加上 -mthumb），用 size 比较 text 段：

   text  filename    124  test.arm.o     96  test.thumb.o    -28  // 少 28 字节，约 22%

这是一个很小、不具代表性的例子；指令长度减半，但做同样的事 Thumb 常常要更多条指令，所以总体省不到一半。

ARM 和 Thumb 混用：interworking

为什么要混用？Thumb 代码有时需要做 Thumb 做不了的操作；关键代码需要完整的 ARM 指令；或者调用的库是按 ARM 编译的。GCC 提供一个透明的机制叫 interworking，靠的是 BX（以及 BLX）：跳转目标地址的 bit 0 决定状态——bit 0 = 0 进入（或留在）ARM，bit 0 = 1 进入 Thumb。下面一步一步看 Thumb 写的 main() 调用 ARM 写的 foo()：

在自己的系统里用 Thumb

  • 内核和用户空间可以各用各的：ARM 内核 + Thumb 程序没问题，内核和程序之间的 ABI 不变。
  • 用户空间可以全部 Thumb，连 libc 一起编（uClibc 对 Thumb 的支持似乎不太正确），也可以只有应用是 Thumb、glibc 保持 ARM。

编译选项

  • 生成 Thumb：-mthumb（Makefile 里写 CFLAGS += -mthumb）。
  • 工具链要支持 interworking：binutils 和 gcc 配置时加 --enable-interwork。
  • 生成可混用的代码：-mthumb-interwork。uClibc 还要在配置里打开 USE_BX。

浮点与 EABI

很多 ARM 芯片没有浮点单元。编译内核时就要决定：程序里的实数运算怎么办？两种仿真方式：

内核里仿真 · Linux 的常用做法

hard float

用户程序照样用浮点指令。芯片不认识这些指令，触发 "illegal instruction" 异常，由内核里的仿真器（NWFPE，或更快但不完整、不适合科学计算的 FastFPE）代为计算。慢：每条浮点指令都要异常处理和上下文切换。好处是有硬件时不用重新编译。

用户空间仿真 · 编译时决定

soft float

编译时加 -msoft-float，编译器直接生成调用软件浮点库的代码，不用浮点指令。

ARM10、ARM11 和 Cortex 系列有 VFP 浮点协处理器，可以真正用硬件算浮点。问题在于：按旧 ABI，hard float 和 soft float 编译的代码不能混在一起，一个程序和它所有的库必须选同一种。

ABI (Application Binary Interface)——应用二进制接口，是程序和操作系统（或另一个程序）之间二进制层面的约定。ARM 的新标准 EABI (Embedded ABI) 规定了文件格式、数据类型、寄存器用法、栈的组织和函数传参方式，好处是：可以混用 hard/soft float 代码，能用别的编译器生成的二进制，支持 Thumb。另外几处变化：

  • 结构体不再有最小对齐；函数的栈按 8 字节对齐（原来 4）；64 位整数按 8 字节对齐。
  • 系统调用号放在寄存器 r7。旧 ABI 把调用号编码在 SWI 指令里，内核要把这条指令当数据读回来解码，指令就混进了数据缓存。
  • 64 位参数对齐到偶数号寄存器。

支持情况：GCC 4.1.0 起支持 EABI，Linux kernel 2.6.16 起有 CONFIG_AEABI；CONFIG_OABI_COMPAT 让 EABI 内核还能跑旧 ABI 的二进制（只限非 Thumb）。反过来，EABI 的二进制放到不支持 EABI 的内核上不能运行。Raspberry Pi 的 32 位工具链前缀 arm-linux-gnueabihf- 里的 gnueabihf，意思就是 GNU + EABI + hard float（用 VFP 硬件）。

ARM 是授权出去的 RISC 架构：load/store、16 个 32 位寄存器、条件执行。Thumb 是 16 位的压缩编码，硬件展开成 ARM 执行；ARM 和 Thumb 之间用 bx 地址的 bit 0 切换。EABI 统一了调用约定，系统调用号放在 r7。

§3一层一层启动：嵌入式 Linux 的组成 T1.6 · T1.7

按下电源，到应用程序开始运行，中间有几段软件依次接力？Bootloader → kernel → root filesystem → aplicaciones.

要把 Linux 放进一个嵌入式系统，需要这几块软件：

  • bootloader (EN) / cargador de arranque (ES)——引导加载程序：做最基本的硬件初始化，把内核装进内存并启动它。
  • Linux kernel——内核：管理内存和进程，包含驱动、网络协议栈……
  • librería C (ES) / C library (EN)——C 库：内核和用户空间应用之间的接口，提供 POSIX 标准 API。实现有好几种：glibc、uClibc、eglibc、dietlibc、newlib 等。
  • 其他库和应用程序。
  • 另外还需要一套交叉编译工具链（§4），它不在板子上，在开发用的 PC 上。

Linux 把所有文件组织成一棵目录树。其中有一个特别的文件系统，root filesystem (EN) / sistema de ficheros raíz (ES)——根文件系统，挂载在 / 上。在嵌入式系统里，它装着系统的库、应用和数据。构建根文件系统是做一个嵌入式 Linux 的基本任务之一；内核通常和它分开存放。

bootloader 做什么

基本任务

  • 硬件的基本初始化。
  • 从 Flash、网络或其他非易失存储，把一个二进制程序（这里是内核）装进内存。
  • 执行它。

大多数 bootloader 还带一个简单的命令行，可以查看内存、加载文件、诊断硬件。

PC 和嵌入式不一样

x86 PC：主板上有 BIOS，复位后自动运行，做基本初始化，然后把磁盘第一个扇区里的小程序装进内存，由它再启动真正的引导程序（grub、lilo）。

嵌入式：和处理器、板子高度相关。有的板子有 NOR flash，CPU 复位后直接从里面取第一条指令，bootloader 就烧在那个位置；有的 CPU 在内部 ROM 里带一个小加载程序，自动从 NAND flash（或 SD 卡）装入一个小程序，这就是两级引导。bootloader 复位后立刻运行，所以连 DRAM 都要由它初始化。

最常用的开源 bootloader 是 U-Boot（Universal Bootloader，ARM 上用得最多，也支持 PPC、MIPS、x86 等），另外还有 RedBoot、uMon。下面以一块 OMAP 处理器的开发板（IGEP）从 SD 卡启动为例，看整个接力过程：

U-Boot 起来后，通过串口控制台可以看到它的提示符。常用命令：printenv / setenv / saveenv 查看、修改、保存环境变量（如 ipaddr、serverip、bootargs）；tftp 通过网络从 PC 上的 TFTP 服务器下载内核；bootm 地址 启动内存里的内核。U-Boot 加载的内核要先用 mkimage 加一个 U-Boot 专用的头（make uImage 会做这一步）。更新 Flash 里的 U-Boot 要小心：出错的话板子可能就"变砖"了，只能靠 JTAG 救回来。

用户空间和内核空间：系统调用

启动完成后，系统分成两个世界。应用程序跑在espacio de usuario (ES) / user space (EN)——用户空间，不能直接碰硬件；内核跑在espacio del kernel (ES) / kernel space (EN)——内核空间，掌管进程、内存、文件系统、设备和网络。两者之间唯一的正式通道是llamada al sistema (ES) / system call (EN)——系统调用接口，也就是操作系统的 API：

内核和用户空间之间的 ABI 向后兼容：用旧内核头文件编出来的程序，在新内核上能运行（只是用不到新功能）；用新头文件编的程序在旧内核上，只要没用新功能，也可能能跑。所以不必追最新的头文件，除非要用新功能。头文件用 make headers_install 从内核源码里导出。

bootloader（可能分两级）→ 内核 → 挂载 rootfs → /sbin/init → 应用。应用在用户空间，要用内核的服务只能经过系统调用：C 库把调用号放进 r7、参数放进 r0…，执行 SWI 进入 Supervisor 模式，内核查表执行后把结果放在 r0 返回。

§4交叉开发：在 PC 上为 ARM 编程 T1.8

PC 上的 gcc 编出来的程序，为什么拷到 ARM 板子上跑不起来？Toolchain nativa vs. toolchain cruzada.

Linux 工作站上自带的开发工具叫本地 toolchain——工具链：它生成的代码给它自己所在的机器用。嵌入式系统一般不能、也不值得用本地工具链：板子的内存和存储太紧，速度也比工作站慢得多。于是在一个平台（host——宿主机）上运行工具，生成另一个平台（target——目标机）的代码，这就是desarrollo cruzado (ES) / cross-development (EN)——交叉开发。

交叉工具链里有什么

这些组件都来自 GNU（1984 年开始开发的类 Unix 自由软件系统）：

组件作用
binutils生成和处理某个架构的二进制：as 汇编器、ld 链接器、ar/ranlib 做静态库（.a）、objdump/readelf/size/nm/strings 查看二进制、strip 去掉没用的部分减小体积
内核头文件也叫系统头文件：系统调用、常量、内核数据结构的定义（§3）
GCC编译器：C、C++、Ada、Fortran、Java、Objective-C……，能为 ARM、AVR、MIPS、PowerPC、x86 等很多架构生成代码
C/C++ 库glibc、uClibc 等。必须和工具链一起选定，GCC 才会为这个库生成代码
GDB（可选）调试器

工具名前面的前缀说明它为哪个目标生成代码：arm-linux-gcc、arm-linux-objdump，或者 Raspberry Pi 32 位系统用的 arm-linux-gnueabihf-gcc。PC 上原来的 gcc 不受影响，两套并存。

build、host、target：四种组合

做工具链时要分清三台机器：build——在哪台机器上构建工具链；host——工具链在哪台机器上运行，也就是做开发的机器；target——生成的程序在哪台机器上运行。三者异同组合出四种情况：

类型build · host · target说明
nativa · 本地A · A · A工作站和 PC 的通常情况，全在一台机器上
cruzada · 交叉A · A · B在同一台机器上做工具、用工具，但为另一个架构生成代码。嵌入式微处理器的常见情况
cruzada-nativaA · B · B在一个架构上做出工具，工具在目标架构上运行
canadiense · 加拿大式A · B · C三台都不同（名字来自当时加拿大有三个全国性大党）

host 和 target 怎么连

standalone

独立

target 上什么都有：bootloader、内核、文件系统，连本地开发工具都装在板子上，不需要 host。

linked

连线

host 是交叉开发平台，通过线缆（串口、网线）和 target 连着；target 上有 bootloader、内核、文件系统。这门课用的就是这种。

almacenamiento removible

可移动存储

target 上只有 bootloader；host 把第二级 bootloader、内核和文件系统写到存储卡上，再插到 target 上启动（§5 的 SD 卡就是这样）。

一轮"写—编—传—调"

把上面的东西串起来，就是每天的工作流程。这门课里 host 是装了交叉工具链和 Eclipse CDT 的 PC，target 是用网线连着的 Raspberry Pi：

用 CMake 告诉构建系统"这是交叉编译"

交叉编译时要指定编译器，并让构建系统只在 sysroot 里找库和头文件，而不去用 PC 自己的：

SET(CMAKE_SYSTEM_NAME Linux)SET(CMAKE_C_COMPILER   arm-linux-gnueabihf-gcc)SET(CMAKE_FIND_ROOT_PATH $ENV{HOME}/raspberry/rootfs)SET(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER) # 程序：用 host 的SET(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)  # 库：只在 sysroot 找SET(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)  # 头文件：只在 sysroot 找

sysroot 用 rsync -rl --delete-after --safe-links pi@板子IP:/{lib,usr} $HOME/raspberry/rootfs 从板子上同步过来。

共享目录：NFS 和 sshfs

  • NFS：在 Linux host 上把一个目录（例如 /exportado）写进 /etc/exports，开 NFS 服务，exportfs -a 生效；板子上在 /etc/fstab 里写一行 host的IP:/exportado /exportado nfs …，再 mount /exportado。
  • sshfs：通过 SSH 把远端目录挂载成本地目录。Windows 上用 sshfs-win（依赖 WinFsp）把板子的目录映射成一个盘符。
  • Windows 上的交叉工具链用 SysGCC 的 Raspberry 版；Eclipse 解压到同一个目录里。

交叉工具链 = binutils + 内核头文件 + GCC + C 库（+ GDB），在 host 上运行、为 target 生成代码。sysroot 是目标系统库和头文件的副本。程序编好后传到板上，用 gdbserver + gdb 远程调试。

§5Buildroot：一条命令做出整个系统 T1.9

工具链、内核、根文件系统、几百个软件包，一个个手工交叉编译要多久？Buildroot: un conjunto de makefiles que automatizan la construcción.

知道了需要哪些组件，实际怎样把一个嵌入式 Linux 做出来？有三条路：

distribución

用现成的发行版

Debian 等发行版有 ARM、MIPS、PowerPC 的二进制包，很快就能跑起来。但配置选项（soft/hard float、EABI/OABI……）是维护者定的，未必合你的需要；对系统集成（启动、依赖）没有控制；想打个补丁就得重新打包，没有自动化手段。

a mano

全部手工

每个组件自己编译、配置、安装。最灵活，但要自己弄清组件之间的依赖，交叉编译很繁琐，想加点东西或修个错，没有自动重建整个系统的办法。

sistema de construcción

用构建系统

自动完成下载、配置、编译、安装；可以系统地重建；方便加补丁和新功能。它认识大多数开源软件包，依赖关系和交叉编译的坑都已经处理好了。

Buildroot 就是这样一个构建系统：一组 makefile，自动完成"构建交叉工具链 + 构建嵌入式 Linux 系统"。它最初是为 uClibc 做的，曾经很长时间没人维护，2009 年 1 月起有了正式维护者（Peter Korsgaard），每 3 个月发布一个新版本。同类工具有 PTXdist（Pengutronix）、LTIB（Freescale，对 Freescale 的板子支持好）；思路不同的有 OpenEmbedded（更灵活也更复杂）和 Gentoo Embedded。

配置：make menuconfig

Buildroot 用内核同款的 Kconfig 配置系统，提供 menuconfig 式的文本菜单，选择结果保存在 .config 文件里：

菜单能选什么
Target架构（arm、mips、powerpc、i386、x86_64……）；变体（ARM7TDMI、ARM920T、Xscale、Cortex-A8……）；ABI（ARM 上选 EABI 或 OABI）
Build options用哪些工具、目录、要不要文档和调试符号、优化级别
Toolchain自己构建（限 uClibc）或用外部工具链；内核头文件版本、C 库版本、GCC 版本和语言（C++、Fortran……）、GDB（target 上的 gdbserver、target 上的 gdb、host 上的 cross-gdb）、IPv6/大文件/locale 等
Packages几百个软件包，依赖自动处理：busybox、bash、openssh、dropbear、lighttpd、tcpdump、iptables、sqlite、i2c-tools、Qt Embedded、python……
Filesystem · bootloader · kernel根文件系统格式（ext2、jffs2、ubifs、squashfs、cramfs、tar、cpio、initramfs……）；U-Boot；内核的版本、配置、补丁和映像格式（uImage、zImage、bzImage）

从零到一张能启动的 SD 卡

以一块 Cortex-A8 的 IGEP 板为例，完整流程是：

  1. 配置 Buildroot：解压，make menuconfig：架构 ARM、变体 Cortex-A8、ABI 选 EABI；打开 IPv6、宽字符、大文件、RPC；构建 target 上的 gdbserver 和 host 上的 gdb；打开 g++；根文件系统选 tar（gzip 压缩）；再选几个软件包。
  2. make。得到两样东西：根文件系统（应用、动态库、基本配置文件），在 output/images；交叉工具链（编译器、库、头文件），可执行文件在 output/staging/usr/bin。
  3. 用新工具链编内核：把工具链目录加进 PATH，arm-linux-gcc -v 确认能用；设 ARCH=arm、CROSS_COMPILE=arm-linux-，载入厂商的默认配置 make igep0020_defconfig（可以再 make menuconfig 修改），然后 make uImage、make modules、make modules_install。-j4 让多核并行编译。
  4. 编 bootloader：X-loader 和 U-Boot，同样用 CROSS_COMPILE=arm-linux-。
  5. 准备 SD 卡：用 dmesg 查出卡对应的设备（如 /dev/sdb），fdisk 分两个区：第一个小分区 FAT32、标记为可启动，放 bootloader 和内核；第二个用剩下的全部空间，ext3，放根文件系统。mkfs.vfat、mkfs.ext3 格式化后挂载。
  6. 复制：启动分区里先放 MLO（顺序重要，它要占第一个扇区），再放 u-boot.bin、uImage，以及用 mkimage 从 boot.cmd 生成的启动脚本；根分区里解压 rootfs.tar.gz、复制内核模块，改 etc/inittab 让登录终端开在串口上。
  7. 上电：依次看到 X-loader、U-Boot、内核、应用启动（§3 的 Escena 2）。第一次启动会慢一些，有些程序要做首次配置。

如果板子 NAND flash 里预装的 U-Boot 能用，可以简化：SD 卡上不放 X-loader 和 U-Boot，只放内核映像和启动配置，由板上的 U-Boot 读取。

Buildroot = 一组 makefile：make menuconfig 选架构、ABI、工具链、软件包、文件系统、内核，结果存在 .config；make 之后得到交叉工具链和根文件系统映像。

§6Raspberry Pi：课程的开发环境 T1.10

板子插上网线，PuTTY 能连上，Eclipse 却说超时，问题在哪？Configuración de la Raspberry Pi para desarrollo cruzado.

Raspberry Pi 是一台基于 ARM 微处理器的小电脑：有可编程的数字引脚和接传感器用的仪器总线，能读物理世界的信息、处理、再据此动作；能连 IP 网络；运行 Linux。用 C/C++ 编程时，课上用 wiringPi 库，它的写法和 Arduino 很像，Arduino 的程序容易移植过来。

要准备的东西

硬件

  • Raspberry Pi 3 或 4
  • micro SD 卡，至少 8 GB，以及 SD 转接卡
  • RJ45 网线
  • 有空闲网口的电脑，或者一台有空闲网口的路由器

软件（Windows host）

  • 交叉开发系统：SysGCC 的 Raspberry 工具链
  • Raspberry Pi Imager（烧录系统镜像）
  • PuTTY（SSH 终端）、Notepad++
  • Eclipse IDE for C/C++ Developers（CDT），解压到 SysGCC 所在目录

步骤

  1. 用 Imager 把 Raspberry Pi OS 镜像写进 SD 卡。在高级选项里打开 SSH，并设好主机名和用户（课上用主机名 raspberrypi.local）。不开 SSH，后面就没法远程登录。
  2. 网线把板子直接接到电脑，插卡上电。
  3. 在 Windows 上把无线网卡的连接共享出去（Internet Connection Sharing）：网络设置 → 更改适配器选项 → Wi-Fi 的属性 → "共享"页，勾选允许其他网络用户通过此连接上网。注意：要共享的是电脑上外网用的 Wi-Fi 接口，不是接板子的那个网口。共享后，Windows 在网口上用 192.168.137.1，并给板子分一个 192.168.137.x 的地址。
  4. 用 PuTTY 连 raspberrypi.local，用配置时设的账号登录。按课程配置页的步骤开启 root 账户，并允许它通过 SSH 登录（改 /etc/ssh/sshd_config）。
  5. ifconfig 查板子的 IPv4 地址；sudo raspi-config 打开 SPI 和 I2C 总线；把 wiringPi 的库文件装好。
  6. 在 Eclipse 里配置交叉工具链和远程连接（§4 的流程）。

连接出错：只有 IPv6，没有 IPv4

症状

PuTTY 能登录，ping raspberrypi.local 也有回应，但 Eclipse 打开连接或启动程序时报 Session.connect: java.net.ConnectException: Connection timed out。原因：Windows 的 DHCP 不一定可靠，有时只给板子分到了 IPv6 地址，没有 IPv4；PuTTY 和 ping 走 IPv6 能通，Eclipse 需要 IPv4。

两种解决办法

  1. 把板子接到家里的路由器上，由路由器分配 IPv4。
  2. 给板子配一个备用的固定 IPv4：DHCP 失败时用 192.168.137.2/24，网关 192.168.137.1（就是共享连接的 Windows 网口）。
    • Bookworm 之前的系统：在 /etc/dhcpcd.conf 末尾加一个 static 配置，并写上 fallback，重启。
    • Bookworm 起：用 nmcli 建两个连接，DHCP 的优先级 1、固定 IP 的优先级 0：先试 DHCP，失败了用固定 IP。之后把 Windows 的共享关掉再打开一次。

用固定 IP 之后，可能就不能再用 raspberrypi.local 这个名字访问了，要直接用 192.168.137.2。如果板子通过 Windows 上不了外网，在 /etc/resolv.conf 里加 nameserver 8.8.8.8。

板子的 IP 是多少：arp -a

在 Windows 的命令行里运行 arp -a，看 192.168.137.1 那个接口下面的条目：

Interfaz: 192.168.137.1 --- 0x11  192.168.137.128   b8-27-eb-2d-bf-a5  192.168.137.205   b8-27-eb-2d-bf-a5  192.168.137.255   ff-ff-ff-ff-ff-ff  # 广播

两条地址对应同一个 MAC：板子拔插过一次，Windows 先后给了两个地址。ping 一下，看哪个是现在有效的。

三种引脚编号

Raspberry Pi 的 40 针排针上，同一个引脚有三个号码，最容易出错：

  • Header pin（物理编号）：排针上的位置，1–40，奇数一排、偶数一排。
  • BCM GPIO：芯片（Broadcom）自己的 GPIO 编号，如 GPIO17。
  • wiringPi 编号：wiringPi 库自己的一套，0、1、2……

点下面排针上的任一引脚，看它的三种编号，以及在三种初始化方式下 pinMode() 该写哪个数：

#include <wiringPi.h> wiringPiSetup();          // 用 wiringPi 编号pinMode(4, OUTPUT);        // wiringPi 4 = BCM GPIO23 = header 16 // 或者：wiringPiSetupPhys();      // 用排针上的物理编号pinMode(16, OUTPUT);       // 同一个引脚digitalWrite(16, HIGH);   // 输出高电平；读输入用 digitalRead()

初始化函数决定了后面所有函数里的引脚号按哪套编号解释。写错一套，程序照样编译通过，只是动的是另一个引脚。

其余的外设

I2C · SPI

两条总线

I2C 只用两根线：数据 SDA（header 3）和时钟 SCL（header 5），板上已有 1.8 kΩ 上拉电阻，不用再接，因此这两脚也不适合当普通 GPIO。先用 raspi-config 打开，i2cdetect 检查总线和设备地址。SPI 用三根公共线（MOSI、MISO、SCLK）加每个设备一根片选线（CE0、CE1）。

entradas analógicas

没有模拟输入

Raspberry Pi 本身没有 ADC。要读模拟量，就外接一个 SPI 或 I2C 的转换器，比如 8 通道 10 位的 MCP3008（wiringPi 直接支持），或 16 位的 ADS1115。

PWM

"模拟输出"

输出是 0–3.3 V 的方波，改变脉宽（占空比）就改变了平均值。pwmWrite(引脚, 值) 的值 0–1023 对应占空比 0–100%。硬件 PWM 只有两路，其余引脚上的软件 PWM 频率低得多。

fPWM = 19.2 MHz ÷ divisor　·　默认 divisor = 32 → 600 kHz　·　用 pwmSetClock(divisor) 修改
为什么 Linux 上翻转引脚没那么快

程序里用 sleep() / usleep() 等待时，进程把 CPU 让给系统，什么时候再轮到它，取决于调度器的时间片。所以用这种方式翻转引脚，最高速度受调度器限制。这正是 Linux 和 MICRO 课上的 bare metal 的区别，也是后面几章（线程、定时器、实时信号）要解决的问题。

镜像里要打开 SSH；直连电脑时共享的是 Wi-Fi 接口，板子在 192.168.137.x。Eclipse 连不上而 PuTTY 能连，多半是没有 IPv4，用路由器或备用固定 IP 解决。引脚号先认清是哪套编号：wiringPiSetup() 用 wiringPi 号，wiringPiSetupPhys() 用排针号。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01下面哪个硬件不适合跑标准 Linux？

D。Linux 至少要 32 位 CPU、8 MB RAM、4 MB 存储；只有几十 KB 内存的微控制器用 bare metal 或 FreeRTOS（§1）。

02ARM 是 load/store 架构，意思是？

B。运算类指令只碰内部寄存器，数据进出内存靠专门的 load/store（§2）。

03关于 Thumb 指令集，哪一句是错的？

C。访问协处理器和状态寄存器正是 Thumb 做不了的事，需要时要切回 ARM（§2）。

04Thumb 代码执行 bx r3，r3 = 0x00009001。之后处理器？

A。bit 0 = 1 表示进入 Thumb，bit 0 本身不进 PC，所以从 0x9000 开始执行（§2 Escena 1）。

05一块没有浮点单元的 ARM 板，内核用 hard float 仿真。程序里每执行一条浮点指令会发生什么？

D。A 是 soft float（-msoft-float）。hard float 靠异常进内核仿真，所以慢（§2）。

06在 ARM EABI 下，系统调用号放在哪里？

B。A 是旧 ABI 的做法，内核要把指令当数据读回来解码。r0 放第一个参数和返回值（§2、§3）。

07执行 SWI 指令那一刻，不会发生的是？

C。errno 是系统调用返回后、出错时由 C 库在用户空间设置的（§3 Escena 3）。

08嵌入式 Linux 从 SD 卡启动的正确顺序是？

A。每一级只负责找到并启动下一级；init 是 rootfs 上的程序，所以必须先挂载 rootfs（§3 Escena 2）。

09在 x86 PC 上构建了一套工具链，它也在这台 PC 上运行，生成 ARM 代码。这是哪种构建？

C。build = host = x86，target = ARM。这是嵌入式微处理器最常见的情况（§4）。

10为什么要把 Raspberry Pi 上的 /lib 和 /usr 同步到 PC 上的一个目录？

B。这个目录就是 sysroot；PC 的 /usr/lib 是 x86 的库，链接进 ARM 程序没用（§4）。

11Buildroot 执行 make 之后，主要得到什么？

D。.config 是 make menuconfig 的产物；make 生成工具链（staging）和 rootfs（images）。教程里内核和 bootloader 是之后用这套工具链另外编的（§5）。

12直连电脑的 Raspberry Pi：PuTTY 能登录，Eclipse 连接却超时。最可能的原因和办法是？

A。没开 SSH 的话 PuTTY 也连不上；Eclipse 需要 IPv4（§6）。
