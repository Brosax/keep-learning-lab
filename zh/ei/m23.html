§1Cloud 与 fog：数据在哪里处理 2.3.1

智能环境用到的网络五花八门，取决于速度、移动性、覆盖、频谱效率、是否需要牌照等（基本概念在 M11 第 8 节复习过）。今天的范式是一个基于 IP 的全球网络：一切都连起来（Internet of Everything (EN)——万物互联），送进 cloud computing (EN)——云计算 里，用 deep learning 对 big data 做智能处理。几乎所有拓扑都靠 pasarela (ES) / gateway (EN)——网关 把设备接到云。网关分两种：

Pasarela sencilla

只负责把数据送上云

例：一个 Wi-Fi 接入点，只做 IP 路由，把 Ethernet / Wi-Fi 转成 ADSL 等固定线路。要求不高的 IoT 应用（简单、低带宽、能容忍延迟）也属于这一类：把很多设备的数据汇总送上云，在云里分析和决策。

Pasarela + fog computing

网关自己会处理、会决策

例：自动驾驶汽车的应用，需要极低的延迟和非常可靠、安全的协议，等不起数据去云里绕一圈。

把这幅全景画出来，就是下面这张图：几乎每条路都经过某种网关才到云。

图里能认出四种“中转站”：

定义 · 2.3.1

fog computing (EN)——雾计算（也叫 edge computing）：把 cloud 延伸到离“物”更近的地方。在网络边缘、靠近数据产生处分析最紧急的数据，按策略在毫秒级做出反应，只把挑选过的数据送到云里做历史分析和长期存储。

cloud computing：数据集中送到数据中心（云）处理，擅长大数据分析、长期存储和全局视图；但把所有数据都从网络边缘搬进数据中心，会增加延迟，成千上万台设备的流量也很快会超出带宽。

为什么需要 fog？IoT 每天产生超过 2 exabytes 的数据；一座海上钻井平台每周产生 500 GB，一架商用喷气机每飞 30 分钟产生 10 TB，全部送上云既不现实也没必要。还有些机器说的是工业协议而不是 IP，送云之前得先翻译成 IP；有些数据受法规和隐私限制，不能存到外面。

fog 节点把云延伸到网络边缘，从设备到云分成几层。点击每一层：

越往上：反应越慢、数据存得越久、覆盖越广。

Cloud · 云

响应时间：几分钟、几天、几周。典型应用：big data analytics、图形化 dashboard。数据保存：几个月到几年。地理覆盖：全球。

它接收并汇总许多 fog 节点发来的数据摘要，结合其他来源的数据做分析、获得商业洞察，还可以据此给 fog 节点下发新的应用规则。

Fog aggregation node · 雾汇聚节点

响应时间：几秒到几分钟。典型应用：可视化、简单分析。数据保存：短期，可能几小时、几天或几周。覆盖：比单个 fog 节点更大。

Smart Grid 的例子：每个变电站可以有自己的汇聚节点，报告下游每条 feeder 和 lateral 的运行状态。

Fog node · 最靠近设备的雾节点

响应时间：毫秒到亚秒。典型应用：M2M 通信、haptics（用触觉控制技术，包括远程医疗和培训；要有真实感，反馈必须在 1 ms 以内）。数据保存：transient（暂存，常为 1–2 小时）。覆盖：非常局部，例如一个街区。

任何有计算、存储和网络连接能力的设备都可以当 fog 节点：工业控制器、交换机、路由器、嵌入式服务器、视频监控摄像头。它用任何协议实时接收设备的数据，并定期把摘要发给云。

Dispositivos IoT · 设备

产生数据、执行动作的“物”：机器上的温度传感器、管道上的压力传感器、阀门、列车的刹车……很多是用工业协议连到控制器的机器，不是 IP 设备。它们持续不断地产生数据，而且常常要求非常快的分析。

例如：化工罐的温度逼近上限时，必须几乎立刻纠正；等读数传到云里再分析，这一批可能已经坏了。

什么时候考虑 fog
  • 数据在极端边缘采集：车辆、船舶、工厂车间、公路、铁路……
  • 大范围内有成千上万、甚至数百万个“物”在产生数据。
  • 必须在 1 秒以内分析数据并采取行动。

§2三种 WSN：固定、移动、个人 2.3.2

WSN 最大的优点：部署非常简单、便宜，省掉了布线的成本。按移动性和覆盖范围，WSN 分成三类。切换看看：

WSN fijas · 固定 WSN

  • 覆盖：一个 WLAN 的范围，再加一点 WPAN。
  • 预先确定：传感器数量、覆盖范围、拓扑和数据传输通常事先就定好了。
  • 拓扑：estrella（星型，用于集中式应用）、árbol（树型，用于数据采集）、mallada（网状，能容忍链路和节点失效）。下图画成 Star、Cluster Tree、Mesh 三种，节点分三种角色：Coordinator（协调器）、Router（路由节点）、End-Device（终端设备）。
  • 技术：Zigbee、6LoWPAN、WiFi，选哪个取决于节点的要求。
  • 一定有 pasarela，用来接入服务器或其他网络。
  • 应用：远程监控、销售点、工业设施、智能建筑。

Zigbee Alliance 在 2021 年 5 月改名为 CSA（Connectivity Standards Alliance）。

WSN móviles · 移动 WSN

  • 覆盖：非常大；连接是 ad hoc（临时建立）的。
  • 例子：一辆在旅途中的汽车，想发现附近的加油站并获取它们的信息。
  • 技术：典型的 M2M 技术，例如蜂窝网（2G、3G、LTE-M、NB-IoT……）或 white spaces（§3）。下图这一栏写的是 M2M、3G 和 TV（white spaces 用的是电视频段），配图是一座大楼、自动售货机、ATM、电表、货车围着一个基站。
  • 也可以算上 LPWAN (Low Power Wide Area Network)——低功耗广域网：LoRa、Sigfox、HaLow、White-Fi。后两者是 WiFi 标准的版本，分别是 802.11ah 和 802.11af。

WSN personales · 个人 WSN

  • 覆盖：非常短，是 WPAN 和 WBAN（体域网）的范围。
  • 用途：连接个人使用的设备：智能手机、平板 ↔ 可穿戴设备（手表、手环、眼镜……）。
  • 技术：Bluetooth、NFC、WiFi Direct；下图还多列了 BLE (Bluetooth Low Energy) 和 WiGig。

记忆口诀：固定看拓扑，移动看覆盖，个人看身体。

§3White space：当地没人用的广播频率 2.3.3

White spaces 是移动 WSN 可以用的 M2M 技术之一（§2）；White-Fi（IEEE 802.11af）就是利用它的 WiFi 版本。

定义 · 2.3.3

espacio blanco (ES) / white space (EN)——空白频谱：分配给 radiodifusión（广播）服务、但在当地没有被使用的频率：servicios de radiodifusión que no se usan localmente。

回到 §2 那张 WSN 类型图：móviles 一栏下方有一张 White Spaces Network 小图（点开大图看得更清楚），标的频段是 TV，并画出了它怎么运作：

  1. 电视塔旁的 Fixed Device Master（固定主设备）经 Internet 做 Device Location Registration（登记自己的位置）；
  2. 从 Geo Location Database（地理位置数据库）拿回 Channels Allowed：这个位置允许用哪些频道；
  3. 再把 Available Channels 告诉客户端，双方建立 Data Link。客户端有两类：FD Client（Fixed Device，固定设备，图里标注必须装室外天线）和 P/P Client（Personal/Portable，个人便携设备）；固定客户端还要做 Fixed Client Registration。

在那张小图里：左边电视塔旁是 Fixed Device Master，底部的 INTERNET 线上是两步登记和查库，右边房子上是 FD Client 和 P/P Client。

也就是说，“当地哪些频道空闲”不是设备自己猜的，而是按位置查数据库得到的。这些频道通常是 VHF/UHF 电视频段里某地没有电视台使用的频道；频率较低，传播远、穿墙好。切换两个地区看看：

§4恶劣的无线环境与 MAC 层 2.3.4

固定和个人 WSN 的无线通信工作在一个“hostil”（恶劣）的环境里：到处是噪声、干扰和不想要的衰减。要处理的问题有这些（下图把它们画成从 WSN 伸出的六个分支）：

Frecuencia

挤在 ISM 频段

通常用 bandas ISM (Industrial, Scientific and Medical)——工业、科学、医疗频段：433 MHz、868 MHz、915 MHz、2,4 GHz。免许可，只要遵守发射功率限制，谁都能用，所以要和其他网络、设备竞争。

Medio

共享的无线介质

各种各样的设备共用同一个介质，会互相干扰，所以需要介质访问控制（MAC，见下）。

Transmisión

只在必要时发送

发射模块要保证最小覆盖，并且只在必要时发送，以降低功耗、延长续航。经典做法是 ciclo de trabajo (ES) / duty cycle (EN)——占空比：节点大部分时间“睡着”（功耗可忽略），按间隔“醒来”收发数据。

Red

路由与可靠性

要有 encaminamiento（路由，§5）机制、拥塞控制，以及保证数据可靠的机制。下图把这些归为 Requisitos：MAC、Routing、Controles de congestión、Seguridad（安全）、Fiabilidad（可靠性）……

Pasarela

接到其他网络

加一个网关，把 WSN 接到其他网络（例如 Internet），方便远程访问、控制和配置。图中：Sensor Node → Sink Node（汇聚节点，即接入 Internet 的网关）→ Internet → User。

Hardware

又小又省

以上一切都要用简单（escalable、bajo coste、bajo consumo）的硬件完成。图中单列一项 Alimentación autónoma（自主供电）：电池、energy harvesting (EN)——能量收集、低占空比（ciclos de trabajo reducidos）。

定义 · 2.3.4

nivel MAC (ES) / Media Access Control layer (EN)——介质访问控制层：OSI 模型中数据链路层（nivel de enlace）的一个子层。在 WSN 里，无线电介质被各种各样的设备共享，它们可能互相干扰，所以需要 MAC 来控制对这个共享介质的访问。

整个数据链路层的职责可以概括为：数据流复用、帧检测、介质访问和差错控制，保证点到点和点到多点的可靠连接。

真实的 WSN 标准里，MAC 是怎么做的？

标准 / 做法MAC 层要点
IEEE 802.15.4为低速率无线个域网定义物理层和 MAC 层，是 WSN 最常用的标准之一，ZigBee 和 6LoWPAN 都建在它上面。信道接入用 CSMA-CA；速率 250 / 40 / 20 kbps；2,4 GHz 有 16 个信道，915 MHz 有 10 个，868 MHz 有 1 个。
IEEE 802.15.4e802.15.4-2006 的 MAC 修订版，关键技术是 channel hopping（跳信道），大大增强对噪声、丢包和持续多径衰落的抵抗力。6LoWPAN 的 MAC 就用它。
WirelessHART面向工业过程自动化的网状网络；在数据链路层用 TDMA 来仲裁和协调设备间的通信。
duty cycling MAC让无线电尽量关着。实验表明，CoAP 跑在支持 radio duty cycling 的 MAC 上，能效最高可达不做 duty cycling 时的 26 倍。

Libelium 的节点也靠 duty cycle 省电：平时处于 latencia（休眠）状态，周期性的闹钟一响，全网同时醒来，互相通信，把数据送到收集点。他们把这个机制叫作“el latir de la red”（网络的心跳）。

§5路由与多跳 2.3.5

定义 · 2.3.5

encaminamiento (ES) / routing (EN)——路由：把信息从源节点（nodo fuente）送到目的节点（nodo destino）的机制。它和拥塞控制、保证数据可靠性的机制一样，是 WSN 必须解决的问题之一（§4）。

在网状（mallada）网络里，路由靠 comunicación multisalto (ES) / multi-hop (EN)——多跳通信：节点把信息发给离它最近的节点，这个节点再转发给另一个邻近节点，如此逐跳传下去，直到目的节点。每一跳距离都很短，所以发射功率和功耗都能大大降低。

Flat

平面拓扑

传感节点同时充当路由器，经多跳把数据送到 sink（汇聚节点，可接入 Internet 等基础设施网络）。

Clustered

分层（分簇）拓扑

由能力更强的固定或移动中继（cluster head）收集并转发传感数据到 sink。

Diseño

网络层要考虑

能效、以数据为中心的通信、数据聚合等。

网状网络能用多跳扩大覆盖、保持低发射功率，并有多条路径提高可靠性；代价是设计更复杂、经过多跳的延迟更长。mota（§6）还会定期自动组织、查看可用的通信路径，所以可以把它们挪到别处去监测另一片区域。

动手试试：点一个 mota 当源节点，看它的数据怎样逐跳到达 pasarela；再让路上的节点故障，看网络怎么绕路。

WSN 接入 IP 之后的路由：RPL

IETF 的 RoLL 工作组评估了 OSPF、IS-IS、AODV、OLSR 等已有路由协议，结论是：没有一个能在 LLN (Low-power and Lossy Network)——低功耗有损网络 的特殊条件下表现令人满意。于是制定了 RPL (IPv6 Routing Protocol for LLNs)。

  • 最主要的流量是 multipoint-to-point：很多节点 → 少数几个连接 Internet 的 edge router。RPL 为此建一个以目的地为根的 DODAG（destination oriented directed acyclic graph，面向目的地的有向无环图）来路由。
  • 每个节点有一个 rank，表示它在 DODAG 里的位置。除了 preferred parent，还保留几个备选父节点（spatial diversity），链路坏了可以马上切换。
  • 用 Trickle 算法传播路由状态：有变化时反应快，稳定后逐渐少发；用 ETX（估计传输次数）等动态链路指标。

§6Mota：像尘埃一样的传感节点 2.3.6

定义 · 2.3.6

mota (ES) / mote (EN)——传感节点（“微尘”）：WSN 里的小型电子设备，通过传感器接触外部世界。名字来自英语 mote，即“mota de polvo”（一粒尘埃），一个词同时表达两个核心概念：尺寸很小，可以放在任何地方。

  • 能放在任何地方，一靠自主供电：用电池（类似手机电池），需要时还能用太阳能板充电；
  • 二靠低功耗无线协议（如 ZigBee）：从休眠状态醒来，完成必要的传输，再迅速回到最低功耗状态。

多个 mota 能组成网状网络，把采集的信息逐跳转发到控制点；它们会定期自动组织通信路径。

休眠时的电流可以低到几微安，不充电也能工作好几年，加一块小太阳能板甚至能不间断运行，所以可以挂在树冠上探测森林火灾，或者放在河岸边监测洪水。

拆开一个 mota：点击每个模块。

Sensores · 传感器

对温度、压力、湿度等物理条件的变化产生可测量响应信号的硬件。连续的模拟信号经 ADC（模数转换器）数字化后交给处理器。因为节点靠有限的电源工作，传感器也必须小、功耗极低。一个节点可以集成或外接一种或几种传感器。

Procesador embebido · 嵌入式处理器

调度任务、处理数据、控制其他硬件组件。可选 microcontrolador（MCU）、DSP、FPGA 或 ASIC，其中 MCU 用得最多：容易连接其他设备，而且便宜。

例：TI（原 Chipcon）的 CC2531 开发板用 8051 MCU；Crossbow 的 Mica2 Mote 用 ATMega128L。

Transceptor · 无线收发器

负责节点的无线通信。介质可以是 RF、激光或红外，大多数 WSN 应用适合用 RF。收发器的工作状态有 Transmit、Receive、Idle、Sleep 四种。

Mica2 Mote 用 RFM TR1000 和 Chipcon CC1000 两种射频芯片，室外传输距离约 150 m。

Memoria · 存储器

包括 MCU 片内的 flash 和 RAM，以及外部 flash。

例：Mica2 上的 ATMega128L 有 128 KB flash 程序存储器和 4 KB 静态 RAM；还可以外接一片 4 Mbit 的串行 flash。

Energía · 电源

感知、通信、数据处理都要耗电，其中通信比感知和处理耗得多。电能存在电池或电容里，电池是主要来源（Mica2 Mote 用 2 节 AA 电池）。电池容量有限，所以尽量降低功耗始终是 WSN 运行的关键；energy harvesting 把太阳能、风能等环境能量转成电能，目标是彻底改变节点的供电方式。

§7TCP/IP 与 IPSO：让 WSN 说 IP 2.3.7

今天常把 WSN 的协议和 Internet 集成起来，以利用它的性能、可扩展性和互操作性，这就是 Internet de las Cosas。可是 IP 网络当初并不是为此设计的：对 WSN 来说它太耗电，也没有针对丢包严重的无线介质做优化。于是有了新的标准和协议：

  • 6LoWPAN (IPv6 over Low-power Wireless Personal Area Networks)——低功耗无线个域网上的 IPv6：面向 LLN、使用 IPv6 包的协议；
  • 物理层和 MAC 用新版 IEEE 802.15.4，更能抵抗噪声、丢包和衰落（物理层 802.15.4-2006，MAC 802.15.4e）；
  • 应用层（相当于 HTTP）有 CoAP (Constrained Application Protocol)——受限应用协议，轻得多、功耗更低。

合起来就是 IPSO (IP for Smart Objects)——智能物体的 IP 协议栈，也写作 IP Smart Objects Protocol suite；推广它的行业组织叫 IPSO Alliance。点击每一层，看看为什么要换：

Aplicación · HTTP → CoAP

CoAP 由 IETF 的 CoRE 工作组定义，是一个基于 REST 的 web 传输协议：保留了 HTTP 的若干功能，但为 IoT 设备有限的处理能力和能耗重新设计。它像 HTTP 一样用 URI 标识资源，用 GET、PUT、POST、DELETE 等方法操作资源，但“不只是 HTTP 的简单压缩”。

一项在 Contiki 系统上的对比实验：请求同一资源，CoAP 每次事务 154 字节，HTTP 1451 字节；功耗 0,774 mW 对 1,333 mW，CoAP 少约 42%。CoAP 还有 observe 功能：客户端登记一次就能收到资源的更新，不必像 HTTP 那样频繁轮询。

Transporte · TCP/UDP → UDP

CoAP 建在 UDP 上，因为它需要的最低限度的可靠性由 CoAP 自己的事务层提供。事务层有四类消息：confirmable（需要 ACK）、non-confirmable（不需要 ACK）、acknowledgement（对 confirmable 消息的 ACK）、reset（收到了 confirmable 消息，但缺少处理它的上下文）。

出于性能考虑，IoT 的传输层常用 UDP。

Red · IPv4/IPv6 → 6LoWPAN

6LoWPAN 让 IPv6 包能在低功耗有损个域网（LLN）上传输。难点在于 802.15.4 的帧（MTU）只有 127 字节，而 Ethernet 和 WiFi 是 1500 字节，IPv6 又要求链路 MTU 不少于 1280 字节。所以 6LoWPAN 定义了：

  • 链路层的分片与重组（分片头只有 4–5 字节）；
  • 不需要每条流保存状态的头部压缩：去掉链路层、网络层、传输层之间的冗余信息，并假设常见字段取常用值；
  • 优化的邻居发现，尽量少用 multicast。

路由不归 6LoWPAN 管，由 RoLL 工作组的 RPL 负责（§5）。

Enlace · 802.3 / 802.11 → IEEE 802.15.4e

6LoWPAN 的物理层是 IEEE 802.15.4-2006，面向低功耗、低速率（250 kbit/s）的 LLN；MAC 是修订版 802.15.4e，用来更好地支持工业市场。它的关键技术是 channel hopping（跳信道），大大增强了对噪声、丢包和持续多径衰落的抵抗力。

§8IMT-2020：5G 的三类使用场景 2.3.8

5G 不是被当作 4G 的演进，而是一场必要的革命：用户不断增加，应用越来越苛刻，IoT 呈指数增长。ITU (International Telecommunication Union)——国际电信联盟 在 IMT 2020 的建议（ITU-R M.2083-0，2015 年 9 月）中，把 5G 移动网络的服务分成三类 escenarios de uso (ES) / usage scenarios (EN)——使用场景：

eMBB

Enhanced Mobile Broadband

增强移动宽带：对带宽要求很高的服务，例如高清视频、虚拟现实和增强现实。

uRLLC

Ultra-reliable and Low-latency Communications

超高可靠低延迟通信：自动驾驶和辅助驾驶、远程管理。

mMTC

Massive Machine Type Communications

海量机器类通信：大规模 IoT。

为此要发展新技术，实现更大容量、更高速度、低延迟、海量设备连接、更低成本和 QoE（Quality of Experience，体验质量）。其中最突出的有：毫米波（ondas milimétricas）、massive MIMO（大规模多天线）、由微型小区组成的密集网络、full duplex、beamforming（波束成形）。

把三类场景画成一个三角形：三个角是三类场景，三条边是它们之间的权衡维度，应用放在离它最需要的那个角最近的地方。注意图里的叫法：uRLLC 那个角写作 Critical machine type communication。点击三个角：

Massive Broadband · eMBB

这个角的指标：>10 Gbps 峰值速率；任何需要时都有 100 Mbps；流量是现在的 10 000 倍。

靠近这个角的应用：Capacity for everyone、3D video / 4K screens、Work in the cloud。VR gaming、Industry 4.0 在通往 Critical MTC 的那条边上（既要带宽也要低延迟）；Smart city cameras 在通往 Massive MTC 的那条边上。

IMT-2020 的典型例子：高清视频、虚拟现实和增强现实。

Massive machine type communication · mMTC

这个角的指标：设备数是现在的 10–100 倍；M2M 成本极低；电池能用 10 年。

靠近这个角的应用：Sensor NW（传感器网络）；Smart city cameras 在它和 Massive Broadband 之间。

IMT-2020 的典型例子：IoT masiva。

Critical machine type communication · uRLLC

这个角的指标：Ultra reliability（超高可靠）；无线延迟 <1 ms。

靠近这个角的应用：Remote control of robot、Autonomous driving；Mission critical broadcast 在它和 Massive MTC 之间的底边上。

IMT-2020 的典型例子：自动驾驶和辅助驾驶、远程管理。

练一练：先点一个应用，再点它所属的使用场景。

注意

有些资料的三角图把 Industry 4.0 放在 Massive Broadband 和 Critical MTC 之间的边上（VR gaming 也在这条边上）；也有资料把“自动化工厂”归为 mMTC。所以“工厂”类应用要看题目强调的是“大量机器”（mMTC）还是“控制要快、要可靠”（uRLLC）。

§9Network slicing、SDN 与 NFV 2.3.9

三个词常一起出现，但说的是三件不同的事。切换看看：

Network slicing · 网络切片

5G 用 network slicing (EN)——网络切片 把一张物理网络划分成多张虚拟网络（slices）。每个 slice 有自己的需求、特性和服务类型，而且彼此逻辑隔离，互不干扰。一大优点：部署一张（虚拟）网络只需要很短的时间。

打个比方：如果全部带宽是一条信息高速公路，network slicing 就是划出能力不同、按流量类型优化的车道，为不同的流量保证不同的服务质量。

Slice 1 · Mobile Broadband

用户经 5G mmWave、WiFi、LTE 接入；这个切片有自己的 C-Plane 和自己的 U-Plane。图这一层画着用户的手机、笔记本，C-Plane 里是 Mobility Management 和云，U-Plane 里是路由器和服务器。

对应 §8 的 eMBB。

Slice 2 · C2X-Automotive

车与车之间的 D2D 通信、Safety、Autonomous Cars，旁边是 Mobile Edge Cloud（移动边缘云）。图这一层还画着 Intelligent Control（红绿灯）、Opportunistic D2D Communication 的车辆、公交车和基站。

对应 §8 的 uRLLC。把计算放到靠近道路的 edge cloud，思路和 §1 的 fog computing 相同。

Slice 3 · Massive IoT

eHealth、CCTV、meters、energy 这类海量设备；这个切片也有自己的 U-plane 和 C-plane。图这一层画着 Home Management、eHealth、CCTV、drones、meters、sensors、energy，以及 App-Server。

对应 §8 的 mMTC。

Other Slices · Slice 4 … Slice n

需要新的服务类型时，再切一张新的虚拟网络；部署一张（虚拟）网络只需要很短的时间。

从图里看三者的关系

注意 Slice 1 和 Slice 3 里都画着各自的 C-Plane 和 U-Plane：控制平面和用户（数据）平面分开，这正是 SDN 的做法；图里每个切片的路由器、服务器、App-Server 都是“自己的”，在同一套物理设备上靠软件实现，这是 NFV 的作用。所以说 slicing“se basa en SDN y NFV”。

SDN · 软件定义网络

SDN (Software-Defined Networking)——软件定义网络：把控制平面（网络管理和维护的流量）和数据平面（发往各种服务的流量）解耦，让控制可以编程。好处：便于扩展、更灵活，也便于网络虚拟化。

NFV · 网络功能虚拟化

NFV (Network Function Virtualization)——网络功能虚拟化：把硬件设备提供的服务（路由器、负载均衡器、防火墙……）抽象出来，用软件实现。这样的网络更灵活、更省钱。

区分 · 2.3.9
  • Network slicing 切的是网络：一张物理网络 → 多张逻辑隔离的虚拟网络。它是 5G 的技术，建立在 SDN 和 NFV 之上。
  • SDN 分开的是平面：控制平面和数据平面解耦，控制可编程。
  • NFV 虚拟化的是功能：硬件设备提供的服务 → 软件。

口诀：slicing 切网，SDN 分平面，NFV 去硬件。

§106G：下一步 了解即可

移动网络的演进：先是连接人，然后变成连接任何“物”的全球传感器网络，再变得智能。下一步是 6G：它不再是“智能的传感器网络”，而是“传感化的网络智能”（una inteligencia en red sensorizada）。6G 想把空间、海上、地面的固定和移动技术结合起来，覆盖地球上的每一个点，各项特性都远超 5G：

指标6G 目标
Peak Rate · 峰值速率1 Tbit/s
Experienced Rate · 用户体验速率10–100 Gbit/s
Network Capacity · 网络容量5G 的 1000 倍
Air Interface Latency · 空口延迟0.1 ms
Air Interface Jitter · 空口抖动±0.1 µs
Reliability · 可靠性99.99999%
Device Density · 设备密度1000 万 / km²
Energy Efficiency · 能效5G 的 100 倍，总能耗 < 5G
Sensing Battery Life · 传感电池寿命20 年
Sensing / Position Accuracy · 感知定位精度室外 50 cm，室内 1 cm
Sensing / Imaging Resolution · 感知成像分辨率1–3 mm
Network Coverage · 覆盖10 dB+

和 §8 的 5G 指标对比：延迟 <1 ms → 0.1 ms，峰值 >10 Gbps → 1 Tbit/s，电池 10 年 → 20 年。

延伸阅读：5G 围绕 eMBB、URLLC、mMTC 三根支柱，6G 要超越它们；数据速率要从现在的个位数 Gbps 提升到数百 Gbps，甚至 1000 Gbps；还要能按某个区域的需要，动态地即时建立 network slices。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01最紧急（time-sensitive）的 IoT 数据应该在哪里分析？

C。最紧急的数据在最靠近“物”的 fog 节点上分析，毫秒级响应；能等几秒到几分钟的交给汇聚节点；不着急的送云做历史分析（§1）。

02fog 节点上的 IoT 数据通常保存多久？

A。fog 节点提供 transient storage（暂存），常为 1–2 小时。几个月到几年是 cloud（§1）。

03一辆在旅途中的汽车想发现附近的加油站并获取它们的信息。这属于哪类 WSN？

D。这是 WSN móviles 的例子：覆盖范围很大，连接是 ad hoc 的，用蜂窝网、white spaces、LPWAN 等（§2）。星型是拓扑，不是这三类之一。

04关于 white space，哪一项是正确的定义？

B。定义：servicios de radiodifusión que no se usan localmente。White-Fi（802.11af）就利用它（§3）。

05WSN 中的 MAC 层是什么？

A。MAC 是 nivel de enlace 的子层；无线介质被许多设备共享、会互相干扰，所以要控制访问（§4）。B 是路由，C 是 CoAP，D 是 pasarela。

06网状 WSN 使用多跳通信（multisalto），主要好处是什么？

C。逐跳转发到目的节点，能大大降低发射功率和功耗。代价是网状网络更复杂，经过多跳的延迟更长（§5）。

07“mote” 这个名字想表达什么？

D。一个词同时表达尺寸小和可以放在任何地方这两个核心概念（§6）。

08在 IPSO 协议栈里，网络层用的是什么？

B。IPSO：应用层 CoAP，传输层 UDP，网络层 6LoWPAN，链路层 IEEE 802.15.4e（§7 的协议栈图）。

09在 §7 提到的 Contiki 对比实验里，请求同一资源时，CoAP 和 HTTP 相比怎样？

A。功耗 0,774 mW 对 1,333 mW（§7）。“26 倍”是 CoAP 跑在 duty cycling MAC 上带来的能效提升，不是这个实验（§4）。

10远程机器人手术、自动驾驶车辆之间的 V2V 通信，属于 IMT-2020 的哪个使用场景？

C。它们要求超高可靠和超低延迟；§8 里 uRLLC 的例子是自动/辅助驾驶和远程管理。network slicing 是一种技术，不是使用场景（§8）。

11“把控制平面和数据平面解耦，让控制可以编程”，说的是哪一个？

B。SDN。NFV 是把路由器、防火墙等硬件提供的功能用软件实现；network slicing 是把物理网络切成多张隔离的虚拟网络（§9）。

12network slicing 建立在什么之上？

D。network slicing se basa en SDN y NFV（§9）。
