§0引脚就是一个地址

CPU 只会读写内存。它怎么"看见"按钮、怎么"点亮"LED？¿Cómo intercambia el micro información con el exterior?

端口的用途分成两类：entrada digital (ES) / digital input (EN)——数字输入，用来读外部器件产生的数字信号（按钮、键盘……）；salida digital (ES) / digital output (EN)——数字输出，用来产生控制外部器件的信号（LED、继电器……）。两者在 CPU 看来是一回事：

一个陷阱

下面这张图来自另一种单片机 PIC，画了四种典型外设。注意它的方向寄存器约定是 0 = Output、1 = Input（PIC 的 TRIS），和 MSP430 的 PxDIR（0 = 输入、1 = 输出）正好相反，别记混。

§1八个端口，一张地址表 M14.1 · M14.2

F5529 有多少根引脚可以当 E/S 用？它们的寄存器放在哪里？Puertos P1–P8 y registros asociados.

F5529 的端口有这些特点：

  • 最多 8 个端口 P1–P8，每个 8 个引脚，只有 P8 是 3 个。
  • 每个引脚可以单独设成输入或输出，单独接上拉/下拉电阻，互不影响。
  • 只有 P1、P2 的引脚能在电平变化时产生中断。
  • 每个引脚还被别的外设共用，要选择它到底做什么（§2 的 PxSEL）。
  • 可以限制每个引脚的驱动电流，降低功耗（§4 的 PxDS）。
P1DIR = 0x0200（PA 基地址）+ 04h（偏移）= 0x0204

P2 的寄存器偏移比 P1 多 1（P2DIR = 05h）。

下面是一个端口的全部寄存器。前六个每个端口都有，后四个只有 P1、P2 有。第一次见到的名字：registro de dirección (ES) / direction register (EN)——方向寄存器 PxDIR，registro de entrada / salida (ES) / input / output register (EN)——输入、输出寄存器 PxIN、PxOUT。

PUC 复位后，端口寄存器全部清 0，只有 PxOUT 和 P1IES、P2IES 处于不确定状态。所以要用到的寄存器都要自己配置好，不能指望默认值碰巧合适。

对照

注意：有些资料说 PxIN 复位后为 0；按 TI 手册，PxIN 没有复位值，它只反映引脚上的电平。另外，F5529 还有一个只有 4 位的 PJ（PJ.0–PJ.3，和 JTAG 共用，基地址 0x0320），这里不展开。PxIV 没有字端口版本：不存在 PAIV。P4 引脚的外设功能还可以重新映射（Port Map Control），这里不展开。

中断相关的四个寄存器在 M21 讲

PxIE、PxIES、PxIFG、PxIV 和中断条件，都放在中断那一章：事件链见 M21 §1，用 PxIFG 或 PxIV 判断中断源见 M21 §7。这一章只用"轮询"，不开中断。

P1–P8（P8 只有 3 位）两两组成 PA–PD；寄存器地址 = 基地址 + 偏移；PUC 后只有 PxOUT 和 P1IES/P2IES 不确定。

§2一个引脚是一台小机器 M14.3

同一根引脚，怎么既能当输入、又能当输出，还能交给定时器？Esquema de bloques / registros de un puerto E/S digital.

先看整个端口（8 位）。中间是 Buffer de E/S；PxDIR 决定每一位的方向；PxSEL 决定每一位接 PxIN / PxOUT，还是接外设模块（MODULO/S，输入、输出各一组）；PxREN 的内部电阻在 buffer 和引脚 Px.0–Px.7 之间；PxIE、PxIFG 只有 P1、P2 有，由它们发出中断请求 IRQ：

下面只取其中一位，一块一块搭起来：

逐个寄存器看：

  • PxDIR：bit = 0 → 输入，1 → 输出。
  • PxOUT：输出引脚上产生低 / 高电平。没有设成输出的引脚，不受 PxOUT 写入的影响。
  • PxIN：读引脚上的电平。它是只读的，写它会被忽略，只会增加电流消耗。识别 0 / 1 的电压和芯片、电源电压有关：大致低于 1 V 读成 0，高于 2 V 读成 1。
  • PxSEL：bit = 0 → 普通 E/S，1 → funcionalidad adicional (ES) / peripheral function (EN)——外设功能。外设越来越多，不可能每个都有专用引脚，于是采用multiplexación (ES) / multiplexing (EN)——引脚复用。PUC 后 PxSEL 全为 0，所有引脚一开始都是普通 E/S。

例：P2.4 交给 Timer_A2

P2SEL.4 = 1 时由方向决定接哪一路：DIR = 0 → TA2.CCI1A（输入），DIR = 1 → TA2.1（输出）。

P2SEL |= BIT4;    // P2.4 交给外设P2DIR &= ~BIT4;   // 输入 → TA2.CCI1A// P2DIR |= BIT4;  // 输出 → TA2.1

P1 每个引脚的另一个身份

P1SEL.x = 1 时：

P1.0 TA0CLK / ACLK · P1.1 TA0.0 · P1.2 TA0.1 · P1.3 TA0.2 · P1.4 TA0.3 · P1.5 TA0.4 · P1.6 TA1CLK / CBOUT · P1.7 TA1.0

同一个引脚可能有两种外设功能，由 PxDIR 区分（例如 P1.0：DIR = 0 是 TA0CLK 输入，DIR = 1 是 ACLK 输出）。

细节

PxSEL = 1 不会自动设置方向，外设需要什么方向，要自己设 PxDIR。另外，P1、P2 的某一位 PxSEL = 1 时，这个引脚的中断功能被关掉。施密特输入的阈值（VCC = 3 V）：上升阈值 VIT+ 1.50–2.10 V，下降阈值 VIT− 0.75–1.65 V，迟滞 0.4–1.0 V（完整的电气特性表在 §4）。有些资料说的“低于 1 V 读 0、高于 2 V 读 1”是简化说法；上面这组是数据手册给的准确阈值。

PxDIR 决定 driver 接不接通，PxOUT 提供输出值，PxIN 永远只读地反映引脚，PxSEL 把引脚交给外设。

§3上拉还是下拉 M14.4

按钮没按的时候，引脚上到底是什么电平？Resistencias de pull-up / pull-down.

每个引脚都有一个内部电阻，用 PxREN 打开；打开之后，用 PxOUT 的同一位选择方向：1 → pull-up (ES/EN)——上拉，0 → pull-down (ES/EN)——下拉。为什么需要它？

PxDIR、PxREN、PxOUT 的组合可以总结成一张表：

PxDIRPxRENPxOUT配置
00x输入（没有电阻）
010输入 + pull-down
011输入 + pull-up
1xx输出（PxREN 不起作用）

同一个 PxOUT 位，输出时是输出值，输入且 REN = 1 时是上拉 / 下拉的选择。例（假设电阻已经打开）：

修改 P1DIR、P2DIR、P1OUT、P2OUT、P1IES、P2IES（还有 PxREN）可能把对应的 PxIFG 置 1，所以改完这些寄存器后建议把 flag 清 0。只用轮询时 flag 没有影响，用中断时就很重要了（M21 §5）。

输入引脚不能浮空：PxREN.y = 1 接上内部电阻，PxOUT.y 选上拉（1）或下拉（0）；接 GND 的按钮配上拉，没按读 1、按下读 0。

§4LED 要串多大的电阻 M14.5

引脚输出 3.5 V，LED 只需要 2 V。多出来的 1.5 V 去哪？Características eléctricas y corriente de ataque.

接什么器件、怎么接，取决于引脚的características eléctricas (ES) / electrical characteristics (EN)——电气特性：输出高电平时的电压 VOH、能提供的最大电流 IOH、内部电阻值等。E/S 引脚的电气特性有三张表：施密特输入（阈值、RPull，见 §2、§3）和两种驱动强度下的输出（见下文 PxDS）。例 B 用它们算 LED 的限流电阻：

V_OH = I_D·R + V_D → R = (V_OH − V_D) / I_D = (3.5 − 2) V / 5 mA = 300 Ω

电阻越小电流越大，LED 越亮，但 ID 不能超过 IOH 的上限。

驱动强度：PxDS

每个引脚能提供 / 吸收的最大电流可以单独选，这叫 corriente de ataque (ES) / drive strength (EN)——驱动强度，用 PxDS 设置：bit = 0 → 降低（reducida），1 → 最大（máxima）。要驱动耗电大的器件时用最大；降低驱动则能减少功耗和电磁干扰（EMI）。

两种驱动强度下保证的输出电流，VCC = 3 V 的部分如下：

保证的输出电压降低驱动
PxDS.y = 0		最大驱动
PxDS.y = 1		所有输出合计
VOH ≥ VCC − 0.25 VIOH = −2 mA−5 mA≤ ±48 mA
VOH ≥ VCC − 0.60 VIOH = −6 mA−15 mA≤ ±100 mA
VOL ≤ VSS + 0.25 VIOL = 2 mA5 mA≤ ±48 mA
VOL ≤ VSS + 0.60 VIOL = 6 mA15 mA≤ ±100 mA

VCC = 3 V。负号表示电流从引脚流出。电流越大，输出电压离 VCC / VSS 越远；最后一列是所有引脚电流加起来的上限，超过它就不再保证这一行的电压。VCC = 1.8 V 时同样的两行只允许更小的电流（降低驱动 −1 / −3 mA，最大驱动 −3 / −10 mA）。

6 mA 从哪来

例 B 的 IOHmax = 6 mA 就是上表"降低驱动、VOH ≥ VCC − 0.60 V"那一格；换成最大驱动，同样的压降允许 15 mA。PxDS 复位后为 0，默认就是降低驱动（降低驱动可以减小 EMI）。

例子 C、D：LED 矩阵和矩阵键盘

最后两个例子：LED 矩阵和矩阵键盘。两者的共同点：把器件排成行和列，用"行数 + 列数"根引脚代替"行数 × 列数"根。

VOH = ID·R + VD：电阻承担 VOH 和 VD 的差，电流不能超过 IOH；PxDS 默认降低驱动。

§5在 CCS 里写寄存器 M14.6 · M14.8

P1DIR 只是一个名字。编译器怎么知道它在哪？又怎样只改其中一位？Etiquetas, fichero de cabecera y configuración de registros.

从这段代码开始（Codigo1）：按住 S2（P1.1，右边的按钮），红色 LED1（P1.0）亮；松开就灭。

#include <msp430f5529.h>int main(void){    WDTCTL = WDTPW + WDTHOLD;   // Detiene el watchdog    P1DIR |= BIT0;              // P1.0 (LED) como salida digital    P1REN |= BIT1;              // Resistencia de pull-up    P1OUT |= BIT1;              // en P1.1 (pulsador derecho)     while (1)    {        if (P1IN & BIT1)         // Testea P1.1: si está a 1 (liberado)            P1OUT &= ~BIT0;      // pon bit P1.0 a 0 (apaga LED)        else                     // y si no (pulsado),            P1OUT |= BIT0;       // pon bit P1.0 a 1 (enciende LED)    }}

在 Project Explorer 里双击工程名，让它显示 [Active - Debug]；把 main.c 换成上面的代码，Save All。

然后 Project → Build All 编译，Run → Debug 下载并进入调试视图，Run → Resume（F8）运行，Run → Terminate（Ctrl+F2）停止、回到编辑视图。

除了第一行停 watchdog（原因见 M21 §2），其余每一行都在操作端口。等号左边的 P1DIR、P1REN、P1OUT、P1IN 叫 etiqueta (ES) / label (EN)——标签：它们代表寄存器在内存映射里的位置。在 CCS 里对标签点右键 → Open Declaration（F3），会打开 fichero de cabecera (ES) / header file (EN)——头文件 msp430f5529.h。

头文件里的几行（摘录）：

#define PADIR_       0x0204      /* Port A Direction */sfrb(PADIR_L, PADIR_);              // 字节：0x0204sfrb(PADIR_H, PADIR_+1);            // 字节：0x0205sfrw(PADIR,   PADIR_);              // 字：0x0204–0x0205 #define P1DIR        (PADIR_L)   /* Port 1 Direction */#define P1OUT        (PAOUT_L)   /* Port 1 Output */#define P1IV_        0x020E      /* Port 1 Interrupt Vector Word */#define P1IV_P1IFG2  (0x0006)    /* P1IV P1IFG.2 */ #define BIT0         (0x0001)#define BIT7         (0x0080)#define BITF         (0x8000)

sfrb / sfrw 把一个名字声明成某个地址上的字节 / 字。

  • 标签分两层：P1DIR 定义成 PADIR_L，PADIR_L 是地址 PADIR_ = 0x0204 上的字节（§1）。P2DIR 是 PADIR_H，在 0x0205；PADIR 是同一地址的字。P1IV 例外，它自己就是一个字寄存器（0x020E），它的取值也有标签：P1IV_P1IFG2 = 6，正是 (2+1)·2。
  • BITx——位掩码也在头文件开头：BIT0 = 0x0001（0000 0001），BIT1 = 0x0002……BIT7 = 0x0080；一直定义到 BITF = 0x8000，给 16 位寄存器用。端口是 8 位，只用 BIT0–BIT7。
  • 所以 P1DIR |= BIT0; 完全可以写成 *(int *)0x204 |= 0x01;，只是可读性差得多。标签让人不用记地址和位的位置，而且同一家族的型号用同样的名字，代码更容易移植。标签真正省事的地方在后面：在 TA0CTL 这类寄存器里，一个标签可以代表几位的组合，例如 MC_1 = 0x0010（MC1 MC0 = 01，"Up to CCR0" 模式）。定时器见 M31。
  • 每个型号有自己的头文件。熟练以后可以改写 #include <msp430.h>，编译器按工程设置选对应文件；但这样 CCS 的索引就找不到定义了。如果出现 "Could not find symbol … in Index"，在工程上右键 → Index → Rebuild，再 Build All。
*(int *)0x204 的细节

MSP430 上 int 是 16 位，所以这句其实是对字寄存器 PADIR（0x0204 = P1DIR，0x0205 = P2DIR）做一次字访问。OR 上 0x0001 只改 bit0，P2DIR 那个字节保持不变，所以结果和 P1DIR |= BIT0 一样。头文件里的 P1DIR 是按字节声明的（上面的 sfrb），严格对应的写法是 *(volatile unsigned char *)0x0204 |= 0x01;。

改寄存器有三种写法。看它们怎样作用在 P1DIR 的 8 个位上：

|= → x_i OR m_i　·　&= ~ → x_i AND NOT m_i　·　^= → x_i XOR m_i

逐位看：掩码 m 里为 1 的位被置 1、清 0 或取反；为 0 的位原样保留。^=（异或，把位取反）在 M21 的 RTI 里会用到。

自己试：选掩码的位和运算，看结果；按"执行"把结果写回寄存器，再接着改。

标签和 BITx 来自 msp430f5529.h；改一个位用 |=（置 1）或 &= ~（清 0），只有在配置整个寄存器时才用 =。

§6测试一个位，再看着它变 M14.7 · M14.8

if (P1IN & BIT1) 到底在问什么？Evaluación de bits de un registro.

读寄存器也可以只看其中一位。P1IN & BIT1 是 P1IN（XXXX XXXX）和 0000 0010 的按位 AND：除了 bit1 全部变成 0。结果是 0 → 假；不是 0 → 真。所以它问的是"P1.1 是不是 1"。

  • 整个寄存器是不是 0：if (P1IV)。两个寄存器都不是 0：if (P1IV && P2IV)。
  • 两个位同时为 1：if ((P1IN & BIT1) && (P1IN & BIT0))——每个位单独测，再用逻辑与 && 连起来。
  • 要特别小心两个错误写法：P1IN & (BIT1 || BIT0) 和 P1IN & (BIT1 & BIT0)。后者里的 BIT1 & BIT0 按定义永远是 0，条件永远为假。

把四种写法放进同一张表，P1IN 的其他位假设为 0：

01假真真假

只有第一列是"两个位都为 1"。| 版本是"任一位为 1"；|| 版本实际上只看 bit0；& 版本永远为假。

关于 BIT1 || BIT0

有些资料说这种写法"只要任意一位为 1 条件就成立"——这描述的其实是按位或 |。按 C 语言的规则，|| 是逻辑或，BIT1 || BIT0 的值是 1，也就是 BIT0，所以 P1IN & (BIT1 || BIT0) 只测 bit0（上表第五列）。两种理解下它都不是"两个位都为 1"，结论不变：不要把 || 放进掩码里。

volatile 和调试

把 Codigo1 改成 Codigo2：数 S2 被松开的次数 cnt，超过 10 次就 break 跳出循环，停在最后的 while(1);。两个变量这样声明：

volatile static uint16_t cnt = 0;volatile static uint8_t  on  = 0;

volatile——易变，告诉编译器这个变量可能在程序看不到的地方被改（硬件、中断、调试器），每次都必须真的去内存里读写，不能优化掉。端口寄存器（例如 PxIN 由硬件改变）在头文件里也是这样声明的。

控制执行

  • Step Over（F6）：执行一行 C 代码，同时在 Registers 窗口里看 P1 的寄存器变化。配置刚执行完时（下面第一张截图），P1IN.1 = 1：S2 没按；P1IN.0 = 0：LED 灭。
  • Run to Line（Ctrl+R）：连续运行到光标所在行。有些行只在特定条件下才执行。
  • Resume（F8）：继续运行。
  • Move to Line：直接把执行点挪到某行，不管程序逻辑——有用，但有风险。

观察和修改

  • Registers：在窗口里直接改 P1OUT，把 P1OUT0 改成 1，LED1 立刻亮。展开 P1OUT 可以逐位改；只改 P1OUT0，P1OUT1 要保持 1——它管着 P1.1 的上拉（§3）。下面 Registers 的截图里 P1OUT = 0x01、P1OUT1 = 0，和这一点不符。
  • Variables：局部变量 cnt（unsigned int）、on（unsigned char），可以改值；右键 Number Format 换显示格式（on 换成 Decimal）。
  • Expressions：可以加全局变量和由变量组成的表达式。
  • Memory Browser（显示格式可选，例如 16-Bit Hex - TI Style，也能在这里直接改值）：输入变量的地址（Variables 的 Location 列，截图里是 0x0043FC），默认十六进制显示。

测一个位用 &，几个条件之间用 &&；掩码里只用 | 组合位，不用 || 和 &。

§7轮询：一直问，直到它说"好了" M14.9

CPU 想知道按钮什么时候被按下，最直接的办法是什么？Gestión por sondeo (polling) · espera activa.

gestión por sondeo (ES) / polling (EN)——轮询，就是用读端口状态的指令（比如 if (P1IN & BIT1)）同步地、反复地去采样外部器件的状态。需要和外界通信时，CPU 一直执行一个查询循环，直到器件表示"准备好了"或"事件发生了"，再交换数据或执行动作。最"纯粹"的实现里，CPU 除了查询什么也不做，所以也叫 espera activa (ES) / busy waiting (EN)——忙等。一般步骤：

  1. CPU 不断查询"事件 / 通信指示"引脚的状态，直到它被激活。
  2. A. 如果是事件通知：执行对应的动作，等引脚恢复，再开始新一轮查询。
  3. B. 如果是通信通知：输入时从输入寄存器读数据，输出时把数据写到输出寄存器；引脚恢复后，输出要把数据撤掉。
  4. 重新开始等待下一次激活。

第一个例子 Codigo3 把这个结构写得最直白：两个"空"的 while，一个等按下，一个等松开。

轮询有三种方案：polling de un evento（查"事件引脚"→ 激活了就执行动作）、polling para lectura de dato（查"数据到达引脚"→ 读输入端口）、polling para entrega de dato（查"数据请求引脚"→ 写输出端口 → 再查，直到引脚撤销 → 撤下数据）。三种方案画成流程图如下：每张图里"没激活"都回到查询框。

ventaja

为什么还在用

实现简单，非常基础、便宜的 micro 也能做。对只做一件事的单任务应用（系统除了和外界交互不干别的），轮询常常就够了。

desventaja

代价

能耗高：光是执行查询指令，CPU 就必须一直处于活动状态。CPU 被锁在等待循环里，没法同时做别的事。

下一个模块是一种更有效的硬件办法——中断。CPU 不必再一直问，事件发生时由硬件通知它：见 M21 Interrupciones。

轮询 = CPU 在循环里反复读通知引脚，等到事件再做事、读数据或写数据；简单便宜，但 CPU 一直忙等，耗能、也做不了别的。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01关于 MSP430F5529 的 E/S 端口，哪一句对？

B。8 个端口，P8 只有 3 位；每个引脚可以单独设方向；P1/P2、P3/P4… 组成 PA、PB…（§1）。

02PUC 复位之后哪一个寄存器的内容是不确定的？

C。端口寄存器复位后都清 0，只有 PxOUT 和 P1IES、P2IES 不确定（§1）。

03执行 P2DIR = 0x0F; 之后，哪些引脚是输出？

D。0x0F = 0000 1111，PxDIR 里为 1 的位是输出：bit0–bit3（§2）。

04关于 PxIN，哪一句对？

B。PxIN 只读（§2）。方向看 PxDIR，上拉 / 下拉看 PxOUT（§2、§3）。

05要把一个引脚配置成"带上拉电阻的输入"，PxDIR.y、PxREN.y、PxOUT.y 应该是？

A。按 §3 的组合表：0 1 1 = 输入 + pull-up；0 1 0 是 pull-down；DIR = 1 是输出；REN = 0 没有电阻（§3）。

06P2SEL |= BIT4; 意味着什么？

C。PxSEL = 1 选外设功能，但不会自动设置方向；§2 的例子用 P2DIR.4 = 0 把 P2.4 当作 TA2 的捕获输入 CCI1A（§2）。

07VOH = 3.3 V，LED 压降 VD = 2.1 V，想要 ID = 4 mA。限流电阻 R = ?

B。R = (VOH − VD) / ID = 1.2 V / 4 mA = 300 Ω。825 Ω 忘了减 VD；0.3 Ω 把 mA 当成了 A（§4）。

08P1DIR 原来是 0x03，执行 P1DIR |= BIT6; 之后是？

B。0000 0011 | 0100 0000 = 0100 0011。0x40 是用了 = 的结果（§5）。

09要把 P1DIR 的 bit5 和 bit0 清 0，其他位不变，应该写？

B。A 会把其他位全部置 1；C 也一样；D 反过来，只保留 bit5、bit0（§5）。

10条件"P1IN 的 bit1 和 bit0 都是 1"应该写成？

A。B 里 BIT1 & BIT0 = 0，永远为假；C 只要任一位为 1 就成立；D 永远不为 0（§6）。

11为什么在程序里写 P1DIR，编译器就知道要改哪个地址？

D。标签定义在头文件里，P1DIR 最终对应 0x0204（§5）。

12轮询也叫 espera activa（busy waiting）。它的主要缺点是？

C。轮询不需要中断，任何端口都能用，也能写数据（Codigo5）；代价是 CPU 被占住（§7）。
