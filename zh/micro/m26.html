Modos de bajo consumo

低功耗模式：让 CPU 尽可能久地睡着

10 个要点 阅读约 20 分钟

M21 让 CPU 不必盯着按钮；这一章更进一步：既然不用盯着，干脆让它睡觉。modo de bajo consumo (ES) / low-power mode (EN)——低功耗模式，就是有选择地关掉时钟，甚至关掉 core 的电源。开关就在状态寄存器 SR 里，叫醒它的只有中断，而叫醒之后回到哪个模式，取决于栈里那份 SR 的副本。最后用三次实测，把"省电"换算成纽扣电池能用多少天。

§0功能一样，耗电差很多

两段程序都是"按一下 S2，LED1 翻转一次"。为什么一个能用几天，另一个能用几年？¿Dónde se va la energía mientras la CPU espera?

低功耗模式 = 有选择地关掉时钟信号和振荡器（LPMx.5 还关掉 core 的电源）。编号越大越省电，但醒来越慢：CPU 一停就不能执行代码，只能等中断叫醒。

§1SR 里的四个开关 M26.1 · M26.2

让 CPU 睡觉，不需要专门的"睡眠指令"，只要往一个熟悉的寄存器里写几个 1。是哪个寄存器？Los modos LPM0–LPM4 se controlan con los bits SCG1, SCG0, OSCOFF y CPUOFF del SR.

5xx 家族定义了 8 种 modo de operación (ES) / operating mode (EN)——工作模式：1 个 modo activo (ES) / active mode, AM (EN)——活动模式，加 7 个低功耗模式 LPM0、LPM1、LPM2、LPM3、LPM4、LPM3.5、LPM4.5。不是每个型号都全有：F5529 实现了其中 7 种，唯独没有 LPM3.5。

四个位的每种合法组合对应一个模式（下表）。记住规律：CPUOFF 永远是 1（所有 LPM 都停 CPU）；SCG0 = 1 的模式 FLL 停；SCG1 = 1 的模式（LPM2–4）SMCLK 停；OSCOFF 只有 LPM4 才置 1。

§2每个模式关掉什么 M26.3

LPM 的编号每加一，又多关掉了什么？哪些东西还醒着、还能叫醒 CPU？¿Qué consecuencias tiene cada modo de operación?

低功耗模块和时钟模块（M24）是绑在一起的：SR 的四个位直接控制振荡器的开关和时钟信号的使能逻辑（§1 的 UCS 表）。选一个模式，看 SR 怎么变、哪些时钟域熄灭、电流掉到多少：

按关掉的东西，这些模式可以分成几组，越往下越省电：

CPUOFF · (+SCG0)

LPM0 和 LPM1

都停 CPU 和 MCLK，SMCLK、ACLK 照常。区别是 LPM1 多关了 FLL（SCG0）。如果 DCO 本来就没在用，LPM0 也会关掉 FLL，两者电流一样。

SCG1 · CPUOFF · (+SCG0)

LPM2 和 LPM3

关掉同样的时钟：MCLK、SMCLK 和 FLL，只留 ACLK。LPM2 的 SCG0 = 0，FLL 的积分器没断电，醒来后 DCO 稳定得更快，代价是电流稍大。

四位全 1 · (+PMMREGOFF)

LPM4 和 LPM4.5

CPU 和所有时钟全停，只有外部事件（例如端口中断）能叫醒。LPM4.5 再把 core 的电源也断掉，RAM 和寄存器内容丢失（§6）。

醒来之后，振荡器呢？

LPM 能关掉 ACLK、MCLK、SMCLK 和 DCO。其余的振荡器：REFO 和 VLO 只要不是任何时钟的源就自动关掉；XT1、XT2 由 XT1OFF、XT2OFF 控制，用作时钟源时要考虑振荡器故障（M24）。

§3睡下去，被叫醒 M26.4

CPU 睡着了，就不能执行任何代码。那谁来把它叫醒？醒来以后，它又怎么知道该回去接着睡？Entrada: bits del SR · Despertar: solo con una interrupción · Salida: la RTI decide.

整个过程可以总结成三句话：

  • 进入（entrada）：把 SR 的 SCG1、SCG0、OSCOFF、CPUOFF 中若干位置 1。
  • 唤醒（despertar）：只能靠中断（包括 NMI），去执行 RTI。所以睡之前，至少要有一个外设开着、使能了中断。
  • 退出（salida）：在 RTI 里决定。不动栈里的 SR → RETI 后回到原来的模式；改了栈里的 SR → RETI 后进入新模式（§4）。

下面用示例程序 LPM_b（§5）走一遍：main 进入 LPM3，S2 叫醒 CPU，RTI 翻转 LED1，然后接着睡。注意中间 SR 和栈的变化。

RTI 入口：SR ← SR ∧ SCG0　　RETI：SR ← @SP+

∧ SCG0 表示只留下 SCG0 这一位；@SP+ 表示从栈顶弹出那份副本。进入 RTI 时 CPUOFF、SCG1、OSCOFF 自动清零。FLL 关着时，DCO 按当时的 DCO、MOD 设置继续振荡，不再稳频，频率会随电压和温度漂移；如果希望 RTI 用经 FLL 稳频的 DCO 运行，可以在 RTI 里自己把 SCG0 清掉。

低功耗位和 PC 一起存在栈里。RTI 什么都不改，RETI 就原样恢复：从哪个模式来，回哪个模式去。

§4改写栈里的 SR M26.5

如果工作太多，不想塞在 RTI 里，而是要回到 main 去做，RTI 该怎么"放 CPU 一马"？Para cambiar de modo, se modifican los bits del SR almacenado en la pila.

在 RTI 里改 CPU 当前的 SR 没用：它此刻本来就是醒着的（0x0040），RETI 一弹栈就被覆盖了。要改的是栈里那份副本。示例程序 LPM_c 正是这样做的：

四个内建函数（función intrínseca (ES) / intrinsic (EN)——编译器内建函数）的分工：

函数改哪个 SR做什么
__bis_SR_register(bits)CPU 当前的 SR把 bits 置 1：开 GIE、进入低功耗模式
__bic_SR_register(bits)CPU 当前的 SR把 bits 清 0
__bis_SR_register_on_exit(bits)栈里的副本（在 RTI 里用）置 1：RETI 后切到更深的模式
__bic_SR_register_on_exit(bits)栈里的副本（在 RTI 里用）清 0：RETI 后醒着回到 main，或换到较浅的模式

其余写法只是它们的"标签"。intrinsics.h 定义了 __low_power_mode_0() … _4() = __bis_SR_register(0x18 … 0xF8) 和 __low_power_mode_off_on_exit() = __bic_SR_register_on_exit(0xF0)；msp430f5529.h 定义了 LPMx = __bis_SR_register(LPMx_bits) 和 LPMx_EXIT = __bic_SR_register_on_exit(LPMx_bits)：

所以进入 LPM3 的三种写法 __low_power_mode_3()、LPM3、__bis_SR_register(LPM3_bits) 并不完全一样：第一种写 0xD8，连 GIE 一起置 1；后两种只写 0xD0，GIE 保持原样。LPM_b 前面已经开了 GIE，三种效果相同；如果 GIE 还是 0，用后两种睡下去，可屏蔽中断都叫不醒它。退出也有两种，区别在于清哪些位：

__bic_SR_register_on_exit(LPM3_bits);   // 只清 SCG1、SCG0、CPUOFF = 0xD0//LPM3_EXIT;                            同一件事（msp430f5529.h）                                        // 来自 LPM3 时效果相同；OSCOFF 不碰

LPM_c.c 里写的是 _low_power_mode_off_on_exit()（一个下划线），intrinsics.h 里的宏是 __low_power_mode_off_on_exit()（两个下划线，见上面的头文件截图）。Escena 4 第 2 步就是这条指令：一个下划线的写法同样编译成 BIC.W #0x00F0, 0(SP)，两种写法在 CCS 里效果相同。

§5LPM_a、LPM_b、LPM_c M26.6 · M26.7

同一个功能，三种写法。哪一种最省电？哪一种在中断多、任务重的时候最好扩展？Tres códigos con la misma función: conmutar LED1 al pulsar S2.

三个文件的开头完全一样（ESQUEMA: ACLK = REFOCLK = 32 kHz, MCLK = SMCLK = DCODIVCLK = 1 MHz）：

WDTCTL = WDTPW + WDTHOLD;              // 停 watchdogconfig_puertos_LPM();                 // 省电的端口配置（本节下半）P1DIR |= BIT0;  P1OUT &= ~BIT0;        // LED1 输出、熄灭P1DIR &= ~BIT1; P1REN |= BIT1; P1OUT |= BIT1;   // S2 输入、上拉P1IE |= BIT1; P1IES |= BIT1; P1IFG &= ~BIT1;   // 下降沿中断，先清 flag__bis_SR_register(GIE);              // 总中断使能

用调试器运行 LPM_b（或在 LPM_c 里试着改去 LPM4）时，可能碰到勘误表的 EEM13：在低功耗模式里来了中断、执行完又回到低功耗模式时出现。没有解决办法，但只影响调试，独立运行时正常。

省电的端口配置 M26.7

三个版本在配置 LED 和按钮之前，都先调用 config_puertos_LPM()。CPU 睡了，引脚和板上其他电路可还在耗电：

void config_puertos_LPM(void) {    P1DIR = 0xFF;  P1OUT = 0x00;         // 全部设为输出、全部低电平    P2DIR = 0xFF;  P2OUT = 0x00;    …                                  // P3 … P8 同样    PJDIR = 0xFF;  PJOUT = 0x00;         // PJ 和 JTAG 共用，也不能悬空    USBKEYPID = 0x9628;                // 钥匙：解锁 USB 配置寄存器    USBPWRCTL &= ~VUSBEN;              // 关 3.3 V LDO    USBPWRCTL &= ~SLDOEN;              // 关 1.8 V LDO    USBKEYPID = 0x0000;                // 写任何别的值：重新上锁}

未用的引脚：输出低

悬空的输入会耗电。建议的做法：未用引脚设为 I/O 功能、输出方向、板上不连接；或者打开 PxREN 的上拉/下拉，同样能避免悬空。复位后 PJ 是高阻输入，又和 JTAG 共用，在调试环境里悬空不容易被发现。

USB 稳压器：先解锁再关

USB 的配置寄存器（包括 USBPWRCTL）被锁着。往 USBKEYPID 写 0x9628 才能改，写别的值就重新上锁。VUSBEN 管 3.3 V LDO，SLDOEN 管 1.8 V LDO。

补充：1.8 V LDO 默认由 SLDOAON 按 VBUS 有没有电自动开关，完全关掉要连 SLDOAON 一起清。上面的函数只清了 SLDOEN，这里照示例代码记。

低功耗不只是写 SR：先让所有用不到的东西（悬空引脚、USB 稳压器、不用的外设）安静下来，再让 CPU 睡。

§6LPM4.5：连 core 一起断电 M26.8

时钟全停了还不够省？那就把 core 的电源也拔掉。代价是什么？LPMx.5: se desconecta el regulador del PMM y con él la alimentación del core.

PMM (Power Management Module)——电源管理模块，负责给 core（CPU 和存储器）和外设供电。core 的电压 VCORE 由 PMM 里的 LDO 稳压器产生。LPMx.5 的做法是：在 LPM4 的四个位之外，再置 PMMREGOFF = 1，把这个稳压器关掉。

什么时候值得用 LPM4.5

醒来要重建 VCORE、跑完 boot code，再从头初始化，所以唤醒时间比其他模式长得多（约 2–3 ms；LPM2–4 回到活动模式只要几 µs 到约 150 µs）。建议只用于很少发生、对响应时间不敏感的事件。

core 电压等级与 MCLK

core 需要的最低电压取决于 MCLK 的频率。PMM 上电后处于等级 0（PMMCOREV = 0，Estado por defecto (ES)——默认状态），此时厂家只保证 MCLK 最高 8 MHz；要更高的频率，先提高 core 电压等级，而且电源电压 VCC 也要够高（下表）。§8 的三次测量都注明"3 V、PMMCOREV = 0"。

PMMCOREV0（默认）123
MCLK 最高8 MHz12 MHz20 MHz25 MHz
VCC 至少1.8 V2.0 V2.2 V2.4 V

VCC 上限都是 3.6 V。等级越高、频率越高，电流也越大：活动模式 25 MHz 要 PMMCOREV = 3，典型 10.1 mA。

进入 LPMx.5 前还要：所有引脚设为通用 I/O、不能有悬空输入（正是 §5 的 config_puertos_LPM 做的事）；对应的唤醒 flag 必须先清掉，否则醒不过来。另外，只要 XT1OFF = 0 或 XT2OFF = 0（晶振开着），LPMx.5 请求就被忽略，芯片根本不进入 LPMx.5（§7 末尾）。

§7外设要时钟 M26.9

LPM3 关掉了 SMCLK，可是有个定时器正用着 SMCLK 计时。它会停下来吗？Periféricos y modos de bajo consumo: la petición de reloj.

外设被使能、并选了某个时钟后，会自动向时钟模块 UCS 发出 petición de reloj (ES) / clock request (EN)——时钟请求。默认情况下请求总会被满足：即使这个时钟被低功耗模式关了，也会为这个外设重新打开。SR 里的低功耗位保持原样，只是对被请求的这个时钟不起作用。

这个默认行为由 UCSCTL8 的三个位控制，复位后都是 1：

位名字= 1（复位默认）= 0
0ACLKREQEN外设请求 ACLK 就能拿到时钟严格按低功耗模式开关，请求无效
1MCLKREQEN外设请求 MCLK 就能拿到
2SMCLKREQEN外设请求 SMCLK 就能拿到（还受 UCSCTL6 的 SMCLKOFF 影响）

UCSCTL8 还有位 3 MODOSCREQEN（MODOSC 的条件请求，复位为 0）；位 10–8 保留，必须写 1。所以 UCSCTL8 的复位值是 0x0707。

请求开、关两种情况下，各时钟在每个模式里的状态如下（SMCLK 按 SMCLKOFF = 0；SMCLKOFF = 1 时，只有请求能让 SMCLK 继续）：

模式ACLK · REQEN = 0 / 1MCLK · REQEN = 0 / 1SMCLK · REQEN = 0 / 1
AM开 / 开开 / 开开 / 开
LPM0、LPM1开 / 开关 / 开开 / 开
LPM2、LPM3开 / 开关 / 开关 / 开
LPM4关 / 开关 / 开关 / 开
LPM3.5、LPM4.5关 / 关关 / 关关 / 关
两个陷阱

① 请求被满足时，芯片虽然"在 LPM3 里"，电流却可能高于 §2 电流表里这个模式的值。② 如果被请求时钟的源振荡器没开，会产生振荡器故障：UCSCTL7 里的故障位和 OFIFG 置 1，可以用 NMI 来处理（M24）。

（有些资料里写成 ACKLREQEN、MCKLREQEN、SMCKLREQEN，是笔误。）进入 LPMx.5 前的请求一律被忽略（但 XT1OFF 或 XT2OFF = 0 时芯片根本不进入 LPMx.5，见 §6）。

§8测电流，算续航 M26.10

"省电"到底省了多少？把电流换成一颗纽扣电池能用的天数，就一目了然。Duración de la batería = carga (mAh) / corriente media.

在 LaunchPad 上这样测电流：jumpers de aislamiento (ES)——隔离跳线块里的 3V3 跳线串在板子 3.3 V 电源线上。拔掉它（同时拔掉 RXD、TXD），把万用表的 µA 档接在两个测点之间，就能测出电流 I，功率 P = I·V。

别被调试器骗了

在 CCS 里调试运行时，JTAG 调试接口也在耗电，读数会偏大。要退出调试器，按 S3（RESET）让程序独立运行，再读表，读数才和 §2 电流表里的值对得上。

电池能用多久，就是电荷量除以平均电流：

t(h) = C(mAh) / Ī(mA)　　t(天) = t(h) / 24

注意单位：µA 要先换成 mA（÷ 1000）。程序有醒有睡时，Ī 是按时间加权的平均：睡得越久，Ī 越接近睡眠电流（§0）。

为什么例 1、例 2 的 ACLK 是 REFO？

上电默认 ACLK 来自 XT1。但这两个程序没有把 P5.4、P5.5 配成 XIN/XOUT，XT1 起振失败，触发振荡器故障，ACLK 自动切到 REFO（M24 的 fail-safe）。例 3 配了这两个引脚，ACLK 才真正用上晶振。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01LPM3 是由 SR 中哪几位置 1 组成的？

B。LPM3 = 1101（SCG1 SCG0 OSCOFF CPUOFF）。四位全 1 是 LPM4（§1）。

02程序还没开 GIE（SR = 0x0000），直接执行 __low_power_mode_3()。此时 SR 的值是？

C。intrinsics.h 里 __low_power_mode_3() 就是 __bis_SR_register(0xD8)：0x80 + 0x40 + 0x10 再加 GIE 的 0x08，GIE 被顺手置 1。写成 LPM3 或 __bis_SR_register(LPM3_bits) 才只置 0xD0，SR = 0x00D0。0x00F8 是 LPM4（§1、§4）。

03在 LPM3 中，哪个系统时钟还在工作（不考虑外设的时钟请求）？

C。LPM2、LPM3 只留 ACLK；LPM4 才全部停掉（§2）。

04LPM0 和 LPM1 的区别是？

B。两者都停 CPU 和 MCLK，SMCLK、ACLK 照常；LPM1 多置了 SCG0，FLL 关闭（§2）。

05CPU 处于 LPM3。什么能把它唤醒？

A。LPM0–LPM4 只能由中断唤醒；CPU 睡着时 main 不会执行任何指令。只能靠 RST/上电/特定 I/O 唤醒的是 LPM4.5（§3、§6）。

06从 LPM3 唤醒后执行 RTI，RTI 没有修改栈里的 SR。RETI 之后会怎样？

D。RETI 恢复的是压栈时的 SR，里面带着 LPM3 的位（§3）。

07CPU 从 LPM3 被中断唤醒。RTI 执行期间，FLL 是什么状态？

B。进入 RTI 时 SR 除 SCG0 外全部清零，SR = 0x0040；需要时可以在 RTI 里自己清 SCG0（§3）。

08想让 RTI 结束后 CPU 醒着回到 main（LPM_c 的结构），RTI 里应写？

B。要改的是栈里的副本。A 改的是当前 SR，RTI 里它本来就是醒着的，RETI 一弹栈就被覆盖（§4）。

09RTI 里执行 __bis_SR_register_on_exit(OSCOFF)，进中断前是 LPM3。RETI 后？

C。栈里 0x00D8 | 0x0020 = 0x00F8 = LPM4。这样 LED 不会翻转。LPM4.5 还需要 PMMREGOFF（§4、§6）。

10关于 F5529 的 LPMx.5，哪一句是对的？

B。F5529 没有 LPM3.5；LPM4.5 关掉 VCORE，RAM 丢失，只能用 RST、上电或特定 I/O 唤醒（§6）。

11复位后不改 UCSCTL8。CPU 进入 LPM3 时，一个定时器正用 SMCLK 计时。会怎样？

B。请求默认总被满足，SR 的低功耗位不变，CPU 继续睡；代价是电流可能高于 §2 电流表里的 LPM3 值（§7）。

12125 mAh 的纽扣电池，电路平均电流 1.36 µA。理论续航约为？

C。125 ÷ 0.00136 ≈ 91 912 h，÷ 24 ≈ 3830 天（§8 例 1：3829.65 天）。D 忘了除以 24（§8）。
