Interrupciones

中断：让 CPU 不必一直盯着

10 个要点 阅读约 18 分钟

按钮什么时候被按下，CPU 事先不知道。它可以一遍遍地去问，也可以让硬件在事件发生时"拍它一下"。这一章把后一种机制拆开来看：事件怎样变成 interrupción (ES) / interrupt (EN)——中断，CPU 怎样保存现场、找到 RTI (ES) / ISR (EN)——中断服务程序、再回到原处；最后在 CCS 里把它写出来。

§0两种等待的方式

CPU 正在做别的事，按钮被按了一下。它怎么知道？¿Cómo se entera la CPU de que ha ocurrido un evento?

事件从哪里来：

中断是一种硬件机制：外设（或外部设备经由 E/S 外设）通过控制总线向 CPU 发出信号，打断当前程序，转去执行 RTI，之后再回到被打断的地方。

§1一条事件链 M21.1

按钮被按下，和 CPU 被打断，中间隔着几道门？Evento → flag → habilitación → interrupción.

先把四个词对上号：

  • evento (ES) / event (EN)——事件：输入、输出或外设里一个值得关注的变化，比如引脚从 1 变到 0。分内部（watchdog、定时器、振荡器故障……）和外部（引脚变化、通信外设收到数据……）。
  • flag de interrupción (ES) / interrupt flag (EN)——中断标志：事件发生时硬件自动把某个寄存器里的一位置 1，把事件"记下来"。flag 置 1 叫 activación（激活）。
  • habilitación (ES) / enable (EN)——使能：flag 置 1 不等于中断一定发生。外设寄存器里还有一个单独使能位（例如 P1IE.1），为 1 才允许这个事件去打断 CPU。
  • GIE (General Interrupt Enable)——总使能：状态寄存器 SR 的第 3 位。它为 0 时，所有 interrupciones enmascarables (ES) / maskable interrupts (EN)——可屏蔽中断都被挡住，单独使能位是什么都没用。

可屏蔽中断的请求条件。flag 由硬件置位，与使能位无关：使能关着时，flag 照样会被置 1，并一直挂着，直到被清掉。

试试看

GIE = 0 时按下 S2：flag 变成 1 但 CPU 没反应。不清 flag，直接打开 GIE：中断立刻发生。挂着的 flag 会在使能打开的瞬间触发中断，所以 §5 的配置顺序里要先清 flag，再开 GIE。

优先级 · prioridad

几个已使能的事件同时发生时，先处理优先级最高的，其余的挂起等待。MSP430 的优先级由向量号决定：号码越大越优先（Reset 是 63 号，最高）。完整的顺序见 §4 的向量表。

§2三类中断 M21.2 · M21.3

GIE = 0 能挡住所有中断吗？No todas las interrupciones son enmascarables.

no enmascarable

RESET

任何方式都关不掉，优先级最高（63 号，0FFFEh）。不管 CPU 在做什么，都会把系统带回一个已知的初始状态。

(no) enmascarable · NMI

UNMI / SNMI

不受 GIE 控制，但可以用外设里各自的使能位关掉。UNMI（用户）：RST/NMI 引脚设为 NMI 时的信号、振荡器故障、Flash 访问违例。SNMI（系统）：电源 PMM、访问未实现的内存、JTAG mailbox。SNMI 比 UNMI 优先；进入 NMI 会自动禁止同类 NMI，避免 anidamiento (ES) / nesting (EN)——中断嵌套。SNMI 还有防重入机制：RETI 之后主程序至少先执行一条指令，再进入下一次 SNMI。

enmascarable

可屏蔽中断

双重控制：外设里的单独使能位 + SR 里的 GIE。GIE = 0 时全部被挡住，不管单独使能位是什么。端口、定时器、USCI 等外设中断都属于这一类。

RESET 本身又分三层。看它们谁引发谁：

BOR 之后的状态

  • RST/NMI 引脚处于 RESET 模式
  • 所有端口引脚都是输入
  • SR 全部清零（GIE = 0）
  • watchdog 已经在计时，约 32 ms 后会触发 PUC 复位
  • PC 从复位向量 0FFFEh 取出程序入口地址，开始执行
  • 想知道复位是谁引起的，读 SYSRSTIV：00h 表示没有挂起的复位源，其余偶数编码就是上图每个起因左边的值，02h（BOR）优先级最高。写这个寄存器会清掉所有挂起的复位源 flag

所以 main 的第一行通常是

WDTCTL = WDTPW + WDTHOLD;  // 停 watchdog

不停掉也不按时"喂狗"，32 ms 后就会复位，程序陷入无限复位循环。watchdog——看门狗的本意是防止软件卡死：程序正常时定期重置计数，卡死时来不及重置，于是复位。

读寄存器表的记号

寄存器表给每一位标两件事：能不能读写，以及各种复位之后是什么值。后面各章的寄存器表都用这套记号：

§3八个步骤 M21.4

打断一个程序容易，难的是回来之后，它要像什么都没发生过一样继续。¿Cómo vuelve la CPU exactamente al mismo punto y en el mismo contexto?

这就是整个处理过程要解决的两个问题：去哪里找 RTI？怎样原样回来？下面一步一步看寄存器、pila (ES) / stack (EN)——栈和 tabla de vectores de interrupción (ES) / interrupt vector table (EN)——中断向量表怎样变化。场景假设 main 正在执行，S2 被按下，P1IE.1 和 GIE 都已经是 1。

压栈顺序，一句话记住

进来时：先 PC 后 SR，SP 共减 4。回去时（RETI）：先 SR 后 PC，SP 共加 4。栈是后进先出，所以顺序正好相反。

CPUx：20 位的 PC 怎么塞进 16 位的栈？ M21.5

F5529 的 CPU 是 CPUx：PC 有 20 位，可以寻址 1 MB。可栈上每个字只有 16 位，而且中断帧最好和老 CPU 保持同样大小（两个字）。办法是借用 SR 里没用到的高 4 位：

指令栈里保存什么能到哪里
CALL / RETPC 的低 16 位（1 个字）子程序必须在低 64 KB
CALLA / RETA完整的 20 位 PC（2 个字）整个 1 MB
中断 / RETIPC.15:0，再加 PC.19:16 + SR（2 个字）RTI 入口必须在低 64 KB（向量只有 16 位）；返回地址可以在 1 MB 内任何位置

SR 本身：位 15–9 保留，8 V，7 SCG1，6 SCG0，5 OSCOFF，4 CPUOFF，3 GIE，2 N，1 Z，0 C。有用的只有低 9 位，所以存 SR.11:0 时高 4 位腾得出来。

CALL 和 CALLA 的栈格式不同，所以必须配对使用：CALL 配 RET，CALLA 配 RETA。函数调用是程序员安排好的同步过程，只自动保存返回地址；中断是异步的，所以连 SR 一起保存。

I/O Port P1。8 个引脚共用这一个向量，属于多源向量：进入 RTI 时 flag 不会自动清，要在 RTI 里判断是哪个引脚，再清对应的 P1IFG 位，或者读 P1IV（§7）。

单源 vs 多源

有些资料举的单源向量是 57、53、49、44；按向量表，59 号（TB0 的 CCR0）其实也是单源。57 是 watchdog 的 interval timer 模式，53、49、44 是 TA0、TA1、TA2 的 CCR0。其余向量都是多源：flags 列里带 …IV 寄存器的，就是多源向量，读这个 IV 寄存器能知道具体来源。

F5529 还可以把向量表搬到 RAM 的最高地址：把 SYSCTL 里的 SYSRIVECT 置 1。BOR 会把它清零，所以复位向量必须始终在 0xFFFE。

关于 CPU39

CPU39 是这颗芯片的一条 erratum (EN)——芯片勘误：在调试器单步执行一条清 GIE 的指令时，PC 可能出错；解决办法是在后面加一条 NOP（__no_operation()）。另外，开中断指令的下一条指令总会先执行。所以在开关 GIE 的指令旁边放一条 __no_operation()，是个无害的好习惯。

§6忘了清 flag 会怎样 M21.8

RTI 执行完了，RETI 也回去了，为什么程序又立刻跳回 RTI？Atención a interrupciones: bajada del aviso.

CCS · punto de ruptura

punto de ruptura (ES) / breakpoint (EN)——断点：程序在执行这一行之前停下。Run → Toggle Breakpoint，或在行号左边双击。Toggle Breakpoint 的快捷键随 CCS 版本不同（Ctrl+Alt+B 或 Ctrl+Shift+B），以菜单里显示的为准。View → Breakpoints 里统一启用、停用，断点标着 [H/W BP]，即硬件断点；Run → New Breakpoint 还能设次数或条件。在 RTI 里设断点、按 Resume（F8），就会看到每次都回到 RTI 第一行；Registers 窗口里 P1IFG 的第 1 位一直是 1。

§7是谁触发的？ M21.9

8 个引脚共用一个向量。进了 RTI，第一件事是弄清楚：是谁？Identificación de la fuente de interrupción.

做个实验：S2（P1.1）控制红灯 LED1，再在 P1.2 上接一个外部按钮控制绿灯 LED2（P4.7）。按住 S2 不放，再按外部按钮：

if (P1IE & P1IFG & BIT1) {        // P1.1 有 flag，而且使能了？    if (P1IES & BIT1) { P1OUT ^= BIT0; P1IES &= ~BIT1; }  // 下降沿：翻转灯，改等上升沿    else              { P1IES |= BIT1; }                  // 上升沿：只改回下降沿    P1IFG &= ~BIT1;}if (P1IE & P1IFG & BIT2) { … P1IFG &= ~BIT2; }
switch (__even_in_range(P1IV, P1IV_P1IFG7)) {  // 读 P1IV 会自动清最高优先级的 flagcase P1IV_P1IFG1:                            // 0x04    if (P1IES & BIT1) { P1OUT ^= BIT0; P1IES &= ~BIT1; }    else              { P1IES |= BIT1; }    break;case P1IV_P1IFG2:                            // 0x06    …  break;default: break;}

为什么条件里还要 & P1IE：§6 最后那张 Registers 截图里，P1IE = 0x02，P1IFG 却是 0x03——P1.0 的 flag 也是 1，可它的中断根本没使能。flag 不管使能与否都会被置位；只看 P1IFG，RTI 就可能去处理一个不该处理的源。

P1IV 的值是偶数，而且有规律：

P1IV = 2·(y+1)，y = 0…7（0x00 = 没有中断）

P1.0 → 0x02，优先级最高；P1.7 → 0x10，最低。__even_in_range(x, max) 告诉编译器 x 只会是 0 到 max 之间的偶数，它可以生成更高效的跳转表。多个 flag 同时置位时，读 P1IV 先清最高优先级的那个；RETI 之后，剩下的 flag 会立刻再触发一次中断。

结论

即使只打算用一个引脚，也一定要在 RTI 里识别中断源。这能发现其他引脚的配置错误，也能防止 interrupciones espurias (ES) / spurious interrupts (EN)——误触发的中断带来的问题。

§8RTI 要短 M21.10

RTI 里多等一会儿，有什么关系？Una RTI larga retrasa a todas las demás.

volatile unsigned char evento_p1 = 0;   // volatile：RTI 会改它，编译器不能优化掉 int main(void) {    …                                    // 配置（§5）    while (1) {        if (evento_p1) {                 // 主循环检查标志位            evento_p1 = 0;            tarea_p1();                 // 慢的工作在这里做        }        …                                // 其他任务    }} #pragma vector=PORT1_VECTOR__interrupt void P1_ISR(void) {    switch (__even_in_range(P1IV, P1IV_P1IFG7)) {    case P1IV_P1IFG1: evento_p1 = 1; break;   // 只记一笔就走    default: break;    }}

RTI 使用建议

  • 不用的中断，明确确认它们是关闭的。
  • 不要拿 GIE 当开关反复开关全部中断（初始化时除外），优先操作各自的使能位。
  • 中断很多时，把所有没用到的向量都指向一个"无效中断"RTI，调试时能查出是谁误触发。
  • RTI 要短：只改标志位或变量，配置改动放回主循环。
  • 事件不紧急时，轮询（sondeo）有时更合适。

这个模型的局限（任务多了以后的优先级、时序）引出 M28 的各种程序架构：循环 + 中断、加入低功耗、调度器、RTOS。去抖更好的办法是用定时器，见 Bloque 3。

D。这就是"(no) enmascarable"的意思。另外 SNMI 比 UNMI 优先，进入 NMI 会自动禁止同类 NMI（§2）。

04BOR、POR、PUC 的关系是？

B。BOR ⇒ POR ⇒ PUC：上一级发生，下一级必然发生，反过来不成立（§2）。

05为什么 main 的第一行通常是 WDTCTL = WDTPW + WDTHOLD;？

C。BOR 之后 watchdog 自动开始计 32 ms；不停也不重置，程序会陷入无限复位（§2）。

06CPU 接受中断时，压栈的顺序是？

A。PASO 2 压 PC，PASO 3 压 SR；RETI 反过来，先弹 SR 再弹 PC（§3）。

07进入 RTI 时，SR 被怎样修改？

B。PASO 6。GIE = 0 意味着默认不嵌套；CPUOFF 等位清零，CPU 在 RTI 期间保持唤醒（§3）。

08P1 用 47 号向量。它在哪个地址？

C。0xFF80 + 2 × 47 = 0xFF80 + 0x5E = 0xFFDE。0xFFE0 是 48 号（§4）。

09哪个向量的 flag 在进入 RTI 时由硬件自动清零？

D。单源向量才自动清：57、53、49、44（还有 TB0 的 59）。其余都是多源（§4）。

10P1 的 RTI 里忘了清 P1IFG.1，会怎样？

B。P1 是多源向量，flag 不会自动清；请求条件一直成立（§6）。

11按住 S2（P1.1）不放，再按 P1.2 上的按钮。哪种方法不能正确判断中断源？

C。P1IN 反映的是电平，不是事件；两个引脚都是 0，代码会误以为 S2 也被按了（§7）。

12为什么不应该在 RTI 里用 __delay_cycles() 去抖？

A。RTI 要短；工作放回主循环，去抖用定时器（§8）。

13CPUx 接受中断时，PC.19:16 存在哪里？

A。PC.15:0 在 SP + 2，PC.19:16 借用 SR 没用到的高 4 位存在 SP 处；帧仍是 2 个字，RETI 能恢复完整的 20 位 PC（§3）。
