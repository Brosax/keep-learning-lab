Señales y temporización POSIX

信号与定时：让进程在对的时刻做事

10 个要点 阅读约 30 分钟

在微控制器上，定时器溢出会直接打断 CPU。到了跑 Linux 的板子上，硬件中断归内核管，程序拿不到。内核把"时间到了""有人叫你""你访问了非法内存"这类事件，换成发给进程的 señal (ES) / signal (EN)——信号。这一章先讲信号怎样产生、投递、被处理和被挡住，再讲 POSIX 怎样读时钟、睡眠、创建定时器，最后讲周期任务为什么会越跑越慢，以及怎样用绝对时间把它拉回来。

§1信号是什么 T3.1 · T3.2

硬件中断被内核拿走了。那进程怎么知道"时间到了"？Una señal es una interrupción software que el kernel entrega a un proceso.

信号是发给进程的一个异步事件：进程正在执行某一行代码，信号一到，执行流跳去运行一段事先指定的函数，跑完再回到原来的位置继续。听起来和中断一模一样，区别在于谁产生、发给谁：

hardware

中断 · interrupción

由物理设备产生，送到 CPU。在 Linux 上只有内核的驱动能处理它。

software

信号 · señal

由内核或其他进程产生，送到某个进程。定时器到期时，是内核替时钟产生信号。

为什么绕这么一圈？硬件只有一个时钟，只产生一种中断。内核接住这个中断，再按需要给许多进程各发各的信号；要是某个用户进程自己抢走了时钟中断，别的进程就都用不上它了。

收到信号后，进程有三种处置，按信号分别设定：

SIG_DFL

默认动作

由内核执行。多数信号的默认动作是终止进程，有的还会写 core dump，有的是暂停、继续或忽略（见下表）。

SIG_IGN

忽略

信号到了直接丢掉。注意：忽略不等于阻塞。阻塞的信号会挂着等，忽略的信号就没了（§3）。

handler

捕获

执行程序员写的 manejador (ES) / signal handler (EN)——处理函数。程序不会终止，除非处理函数自己决定退出。

常用信号和它们的默认动作（编号是 Linux 上的值，写程序时永远用名字）：

§2捕获信号：signal 和 sigaction T3.3 · T3.4

装一个处理函数只要一行。难的是：处理函数里能做什么？Armado de la función de tratamiento de señal.

最简单的 signal()

#include <signal.h>void (*signal(int signum, void (*handler)(int)))(int);

声明看着吓人，读法是：signal 接收一个信号编号和一个"参数为 int、返回 void 的函数指针"，返回原来的那个函数指针（失败时返回 SIG_ERR）。第二个参数也可以是常量 SIG_DFL（恢复默认）或 SIG_IGN（忽略）。处理函数收到的 int 就是信号编号，所以同一个函数可以处理好几种信号。

例：前两次 Ctrl+C 只打印提示，第三次恢复默认动作，第四次 Ctrl+C 才真正结束程序。

#include <signal.h>#include <stdio.h>#include <unistd.h> static volatile sig_atomic_t veces = 0; static void on_int(int sig) {    veces++;    if (veces == 3)        signal(SIGINT, SIG_DFL);           // 下一次 Ctrl+C 走默认动作：终止} int main(void) {    if (signal(SIGINT, on_int) == SIG_ERR) { perror("signal"); return 1; }    for (;;) {        pause();                              // 睡到任何一个被处理的信号到来        printf("Ctrl+C 第 %d 次\n", (int)veces);  // printf 放在主程序里，不放在处理函数里    }}
  • pause() 让进程睡到一个信号被处理为止，然后返回 −1（errno = EINTR）。在这里 −1 不表示出错，它只会这样返回。
  • 发信号：kill(pid, sig) 发给别的进程（pid > 0 是那个进程；pid = −1 是所有有权限发的进程，init 除外；pid < −1 是进程组 −pid）；raise(sig) 发给自己，等于 kill(getpid(), sig)。命令行里是 kill -USR1 <pid>。
  • 处理函数可以随时换：再调用一次 signal，生效的是最后一次装的那个。

完整的 sigaction()

signal() 的行为在不同 Unix 上不完全一样（处理完要不要自动恢复默认、被打断的系统调用要不要重启），而且拿不到"谁发的"这类信息。POSIX 推荐用 sigaction：

int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact); struct sigaction {    void     (*sa_handler)(int);                       // 基本形式：和 signal 一样    void     (*sa_sigaction)(int, siginfo_t *, void *);  // 扩展形式：多两个参数    sigset_t   sa_mask;                                  // 处理函数运行期间额外阻塞的信号    int        sa_flags;                                 // 行为选项，用 | 组合};

sa_handler 和 sa_sigaction 只能用一个。想用扩展形式，必须在 sa_flags 里置 SA_SIGINFO，这时处理函数收到三个参数：信号编号、一个 siginfo_t *（谁发的、为什么发、带了什么值）和上下文指针。oldact 不为 NULL 时，返回原来的设置，方便以后恢复。

sa_flags作用
SA_SIGINFO使用 sa_sigaction（扩展形式，拿到 siginfo_t）
SA_RESTART被这个信号打断的系统调用（read、write、wait…）自动重新开始，而不是返回 −1 / EINTR
SA_RESETHAND处理一次之后恢复成 SIG_DFL（"只捕获一次"）
SA_NODEFER处理函数运行期间不自动阻塞这个信号本身，允许它嵌套
SA_NOCLDSTOP（用于 SIGCHLD）子进程暂停时不发 SIGCHLD
SA_NOCLDWAIT（用于 SIGCHLD）子进程结束后不变成僵尸进程
SA_ONSTACK在 sigaltstack 设定的备用栈上运行处理函数

默认情况下，处理函数运行期间，正在处理的这个信号会被自动阻塞（除非 SA_NODEFER），再加上 sa_mask 里列的信号。处理函数返回时，掩码自动恢复。

siginfo_t 里常用的字段：si_signo（编号）、si_code（来源：SI_USER 是 kill，SI_QUEUE 是 sigqueue，SI_TIMER 是 POSIX 定时器）、si_pid / si_uid（发送者）、si_value（随信号带来的值，§4）。

例：用扩展形式记下是谁发来的 SIGUSR1，处理期间顺便挡住 SIGUSR2。

static volatile sig_atomic_t quien = 0; static void on_usr1(int sig, siginfo_t *si, void *ctx) {    (void)sig; (void)ctx;    quien = si->si_pid;                          // 只存一个值    write(STDOUT_FILENO, "USR1\n", 5);           // write 是 async-signal-safe} int main(void) {    struct sigaction sa;    memset(&sa, 0, sizeof sa);    sa.sa_sigaction = on_usr1;                   // 扩展形式……    sa.sa_flags = SA_SIGINFO | SA_RESTART;       // ……必须配 SA_SIGINFO    sigemptyset(&sa.sa_mask);    sigaddset(&sa.sa_mask, SIGUSR2);             // 处理期间额外挡住 SIGUSR2    if (sigaction(SIGUSR1, &sa, NULL) == -1) { perror("sigaction"); return 1; }    for (;;) {        pause();        printf("SIGUSR1 来自 PID %d\n", (int)quien);    }}

处理函数里能做什么

处理函数可能在主程序的任何一条指令之后插进来，包括主程序正在 printf 或 malloc 的半中间。如果处理函数也调用 printf，两边会同时改 stdio 的内部缓冲区，结果可能是输出错乱，甚至死锁（主程序拿着锁，处理函数等这把锁，而主程序要等处理函数返回才能放锁）。

所以处理函数里只能调用 async-signal-safe——异步信号安全的函数：可重入，或者在执行期间屏蔽了信号。

可以

write、read、_exit、kill、raise、sigaction、sigprocmask、clock_gettime、timer_getoverrun、sem_post，以及读写 volatile sig_atomic_t 变量。

不可以

printf 家族、malloc / free、exit（会刷 stdio 缓冲区）、pthread_mutex_lock，以及大多数库函数。

做法

和微控制器上"中断服务程序要短"是同一个道理：处理函数只置一个 volatile sig_atomic_t 标志（或者 sem_post），真正的工作放回主程序。volatile 让编译器每次都去内存里读这个变量；sig_atomic_t 保证一次读写不会被信号从中间打断。更彻底的办法是根本不写处理函数，用 §3 的 sigwait 同步地等。课程里不少示例在处理函数里用 printf，那是为了演示方便，正式程序不要这样写。

跳出处理函数：sigsetjmp / siglongjmp

处理函数正常是"返回原处"。有时原处已经没意义（比如出了错，或者主程序卡在一个阻塞调用里），可以用非局部跳转直接回到之前设好的位置：

#include <setjmp.h>int  sigsetjmp(sigjmp_buf env, int savesigs);   // 设跳转点：直接执行到这里时返回 0void siglongjmp(sigjmp_buf env, int val);      // 跳回去：sigsetjmp 这次返回 val（不能是 0）

sigsetjmp 的返回值告诉你是"第一次执行到这里"（0）还是"跳回来的"（val）。savesigs 不为 0 时，跳回去会恢复当时的信号掩码，所以从处理函数里跳出要用 sig 版本，而不是 setjmp / longjmp。还要用一个 volatile sig_atomic_t 标志确认跳转点已经设好，再允许跳。

§3信号掩码与阻塞 T3.5 · T3.6

有一段代码绝对不能被打断。怎样让信号"等一等"？Enmascarado de señales: bloquear no es ignorar.

每个线程有一个 máscara de señales (ES) / signal mask (EN)——信号掩码：一个信号集合，里面的信号被阻塞。被阻塞的信号照样产生，但不投递，而是挂起，等解除阻塞的那一刻再投递。这和 SIG_IGN 完全不同：

bloquear · sigprocmask

阻塞：先挂着

信号留在挂起集合里，解除阻塞后立刻投递。不会丢（但同一个标准信号挂着时再来，只记一次）。

ignorar · SIG_IGN

忽略：直接丢

信号一到就被扔掉，什么也不留下。之后改回处理函数，也找不回来。

信号集合 sigset_t

int sigemptyset(sigset_t *set);              // 清空int sigfillset(sigset_t *set);               // 放进所有信号int sigaddset(sigset_t *set, int signo);     // 加一个int sigdelset(sigset_t *set, int signo);     // 去掉一个int sigismember(const sigset_t *set, int signo);  // 在不在里面：1 / 0

sigset_t 是不透明类型，使用前一定要先 sigemptyset 或 sigfillset。早期 Unix 用一个 int 当掩码（sigblock、siggetmask、sigsetmask），只能表示前 32 个信号；POSIX 的 sigset_t 能表示系统里所有信号，包括实时信号。

sigprocmask

int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);
how新的掩码
SIG_BLOCK旧掩码 ∪ set（再多挡几个）
SIG_UNBLOCK旧掩码 − set（放开这几个）
SIG_SETMASK就是 set（整个替换）

oldset 不为 NULL 时返回原来的掩码；set 为 NULL 时只读不改。保护临界区的标准写法：先 SIG_BLOCK 并保存旧掩码，做完再用 SIG_SETMASK 恢复旧掩码（而不是 SIG_UNBLOCK，因为这些信号进来之前可能本来就是被阻塞的）。

sigset_t set, old;sigemptyset(&set);sigaddset(&set, SIGINT);sigaddset(&set, SIGUSR1);sigprocmask(SIG_BLOCK, &set, &old);     // 进入临界区：挡住这两个actualizar_tabla();                     // 处理函数也会读这张表，不能读到改了一半的sigprocmask(SIG_SETMASK, &old, NULL);   // 恢复：期间挂起的信号在这一刻投递
  • sigpending(&set)：把当前挂起（已产生、因阻塞还没投递）的信号放进 set，用来查询。
  • sigsuspend(&mask)：原子地把掩码换成 mask 并睡下，等一个信号被处理后返回，同时把掩码换回原来的。"先解除阻塞，再 pause"分两步写会有空隙：信号恰好落在两步之间，就被处理掉了，pause 会一直睡下去。sigsuspend 把两步合成一步，没有这个空隙。

线程里的信号：pthread_sigmask + sigwait

多线程程序里，掩码是每个线程各自的（新线程继承创建者的掩码），而处置（处理函数）是整个进程共用的。一个发给"进程"的信号（kill、定时器），内核会把它交给任意一个没有阻塞它的线程，你事先不知道是哪一个。

线程里改掩码用 pthread_sigmask，参数和 sigprocmask 一样（多线程程序里 sigprocmask 的行为没有定义）。常用的做法是根本不写处理函数：

  1. 在 main 里、创建任何线程之前，用 pthread_sigmask 把要处理的信号全部阻塞。之后创建的线程都继承这个掩码，所以没有哪个线程会被这些信号异步打断。
  2. 开一个专门的线程，循环调用 sigwait(&set, &sig)：它睡到 set 里的某个信号挂起，把它取走（不调用处理函数），把编号放进 sig 后返回。
static void *hilo_senales(void *arg) {    sigset_t *set = arg;    int sig;    for (;;) {        sigwait(set, &sig);                 // 同步地等：这里不是处理函数，什么函数都能调用        printf("收到信号 %d\n", sig);        if (sig == SIGTERM) exit(0);    }} int main(void) {    static sigset_t set;    sigemptyset(&set);    sigaddset(&set, SIGUSR1);    sigaddset(&set, SIGTERM);    pthread_sigmask(SIG_BLOCK, &set, NULL);       // ① 先阻塞：之后创建的线程都继承    pthread_t th;    pthread_create(&th, NULL, hilo_senales, &set);  // ② 专门等信号的线程    /* ③ 其他线程做正事，不会被这两个信号打断 */    pthread_join(th, NULL);}
  • sigwaitinfo(&set, &info)：同上，但把完整的 siginfo_t 带回来（谁发的、si_value），返回值就是信号编号。
  • sigtimedwait(&set, &info, &timeout)：最多等 timeout，超时返回 −1，errno = EAGAIN。
  • 要等的信号必须先阻塞：没阻塞的话，信号可能在 sigwait 拿到之前就按处置被投递掉（甚至按默认动作把进程杀了）。

异步的处理函数受 async-signal-safe 的限制；把信号阻塞起来，再用 sigwait 在一个线程里同步地取，就变成了普通的"等一个事件"，代码里怎么写都行。

§4实时信号 T3.7

标准信号只有一位，来三次只记一次。要是每一次都不能丢呢？Señales de tiempo real: SIGRTMIN…SIGRTMAX.

POSIX.1b 加了一段编号 SIGRTMIN … SIGRTMAX——实时信号，没有预先规定的含义，全部留给应用使用，默认动作是终止进程。和标准信号比，有三点不同：

标准信号实时信号
含义大多预先规定（SIGINT、SIGALRM…），只有 SIGUSR1/2 留给应用全部留给应用
挂起时再来合成一次排队，一次一项
投递顺序没有规定编号小的先；同一信号按发送顺序
附带数据没有si_value（sival_int 或 sival_ptr）

编号

SIGRTMIN 和 SIGRTMAX 在 Linux 上不是编译期常量，而是运行时才确定的值：内核提供 32 到 64，glibc 的线程库自己占用了最前面两个，所以程序看到的 SIGRTMIN 通常是 34，SIGRTMAX 是 64。所以：

SIGRTMIN + n = 34 + n　　SIGRTMAX − n = 64 − n

程序里一律写 SIGRTMIN + n，不要写死数字；用之前确认 SIGRTMIN + n <= SIGRTMAX。系统能排队的实时信号总数可以用 sysconf(_SC_RTSIG_MAX) 查。

带一个值：sigqueue 和 si_value

union sigval { int sival_int; void *sival_ptr; };int sigqueue(pid_t pid, int sig, const union sigval value);

sigqueue 和 kill 一样发信号，多带一个 union sigval。接收方用 SA_SIGINFO 的处理函数，或者用 sigwaitinfo，从 si->si_value 取出来；si_code 是 SI_QUEUE。跨进程时只有 sival_int 有意义（指针在别的进程的地址空间里没用）；进程内部，比如 §6 的定时器，传指针最常见。

/* 发送方 */union sigval v = { .sival_int = 42 };sigqueue(pid_receptor, SIGRTMIN + 3, v); /* 接收方：阻塞后用 sigwaitinfo 同步地取 */sigset_t set;  siginfo_t si;sigemptyset(&set);sigaddset(&set, SIGRTMIN + 3);sigprocmask(SIG_BLOCK, &set, NULL);for (;;) {    sigwaitinfo(&set, &si);    printf("值 %d，来自 PID %d\n", si.si_value.sival_int, (int)si.si_pid);}

§5POSIX 时钟与睡眠 T3.8

"现在几点"和"过了多久"，是两个不同的问题。Relojes: CLOCK_REALTIME y CLOCK_MONOTONIC.

实时系统要能在规定的时刻做事，需要三样东西：量时间的 reloj (ES) / clock (EN)——时钟、在指定时刻唤醒任务的机制，以及发现"等太久了"的 timeout——超时机制。

时钟是一个计数器

时钟 = 一个产生周期脉冲的振荡器 + 一个累计脉冲数的计数器，软件再把计数换算成时间。两个指标：精度（granularidad，一个计数代表多长时间）和范围（计数器装满之前能表示多长时间）。两者互相牵制：同样 32 位，精度越细，越快溢出。

范围 = 2³² × 精度 ≈ 4.29 × 10⁹ × 精度
精度32 位计数器的范围
100 ns约 429 s（7.2 min）
1 µs约 4295 s（72 min）
100 µs约 119 h
1 ms约 50 天
1 s约 136 年

注意：有些资料的表里 100 ns 一行写的是 4.3 s；按 2³² × 100 ns 计算是约 429 s，4.3 s 对应的是 1 ns 的精度。

时间的表示

Unix 把绝对时间表示成从 1970-01-01 00:00:00 UTC（Epoch）起经过的秒数，类型是 time_t（在 64 位 Linux 上是 64 位）。更细的精度用结构体：

struct timeval  { time_t tv_sec; suseconds_t tv_usec; };  // 微秒：0 … 999 999struct timespec { time_t tv_sec; long        tv_nsec; };  // 纳秒：0 … 999 999 999（POSIX 用这个）

旧接口：time()（秒）、gettimeofday() / settimeofday()（timeval，微秒）、difftime()（两个 time_t 之差）、struct tm（年月日时分秒，tm_year 从 1900 起算，tm_mon 是 0–11）和 mktime / timelocal（tm → time_t）。改系统时间需要超级用户权限。

POSIX 时钟

int clock_gettime(clockid_t clk, struct timespec *tp);        // 读int clock_getres(clockid_t clk, struct timespec *res);       // 分辨率int clock_settime(clockid_t clk, const struct timespec *tp);  // 设（只对 REALTIME，要权限）
CLOCK_REALTIME

墙上时钟

"现在几点"：从 Epoch 起的时间。会跳：管理员改时间、NTP 同步，都可能让它向前或向后跳一下。适合打时间戳、"在某个日期时刻做某事"。

CLOCK_MONOTONIC

单调时钟

"过了多久"：从某个没有规定的起点（通常是开机）开始，只增不减，不受改时间、NTP 跳变的影响。量时间间隔、排周期任务，都用它。

量一段代码用了多久：

struct timespec t0, t1;clock_gettime(CLOCK_MONOTONIC, &t0);trabajo();clock_gettime(CLOCK_MONOTONIC, &t1);long long ns = (t1.tv_sec - t0.tv_sec) * 1000000000LL + (t1.tv_nsec - t0.tv_nsec);

timespec 做加法时，tv_nsec 必须保持在 0 到 999 999 999 之间，超出就要进位到 tv_sec。很多函数（nanosleep、timer_settime）收到 tv_nsec ≥ 10⁹ 会直接返回 EINVAL。一个通用的小函数：

#define NS_POR_S 1000000000Lstatic void ts_add_ns(struct timespec *t, long ns) {    t->tv_nsec += ns;    while (t->tv_nsec >= NS_POR_S) {          // 注意是 >= 10⁹，减的也是 10⁹        t->tv_nsec -= NS_POR_S;        t->tv_sec++;    }}

让任务睡一会儿

函数单位说明
sleep(s)秒返回没睡完的秒数（被信号打断时）
usleep(us)微秒旧接口，POSIX 已经删掉，新代码用 nanosleep
nanosleep(&req, &rem)timespec相对时间。被处理函数打断时返回 −1、errno = EINTR，剩下的时间写进 rem
clock_nanosleep(clk, flags, &req, &rem)timespec可以选时钟；flags = TIMER_ABSTIME 时 req 是绝对时刻："睡到那个时刻为止"。出错时直接返回错误号（不是 −1）

nanosleep 睡到三种情况之一才返回：时间到了；有信号的处理函数被执行；进程被终止。被打断后接着睡剩下的时间，常见写法：

struct timespec req = { .tv_sec = 0, .tv_nsec = 200 * 1000000L }, rem;   // 200 mswhile (nanosleep(&req, &rem) == -1 && errno == EINTR)    req = rem;                                // 接着睡剩下的
实际睡多久

睡眠时间只会比要求的长，不会短：请求会向上取整到系统时钟的粒度，醒来后还要等调度器让任务重新运行。粒度和延迟取决于平台和内核配置，用 clock_getres 能查到时钟的分辨率。另外，上面的"接着睡剩下的"每被打断一次就多一点误差；要避免误差，用绝对时间（§7）。

§6POSIX 定时器 T3.9

睡眠会把整个任务停住。能不能让内核到点了"拍一下"，任务自己接着干活？timer_create, timer_settime, struct sigevent, struct itimerspec.

先看老办法：alarm 和 setitimer

  • unsigned alarm(unsigned s)：s 秒后给自己发一个 SIGALRM。再调用一次会重设（返回上次剩下的秒数），alarm(0) 取消。只有秒级精度。
  • setitimer(ITIMER_REAL, &it, &old)：用 struct itimerval（两个 timeval：it_value 第一次、it_interval 之后每次）设一个微秒级、可以自动重复的定时器，到期同样发 SIGALRM。
  • SIGALRM 的默认动作是终止进程：先装处理函数，再启动定时器，否则第一次到期程序就结束了。

它们的局限：每个进程只有一个这样的定时器；全都用同一个 SIGALRM；只能"多久之后"（相对时间）。POSIX 定时器把这三点都解决了：

#include <signal.h>#include <time.h>int timer_create(clockid_t clk, struct sigevent *evp, timer_t *timerid);int timer_settime(timer_t timerid, int flags, const struct itimerspec *nuevo, struct itimerspec *viejo);int timer_gettime(timer_t timerid, struct itimerspec *actual);   // 还剩多久int timer_getoverrun(timer_t timerid);int timer_delete(timer_t timerid);

在较旧的 glibc 上要加链接选项 -lrt；新版本已经把这些函数并进了 libc，加上也无妨。

到期时做什么：struct sigevent

struct sigevent {  int          sigev_notify;   // 通知方式  int          sigev_signo;    // 发哪个信号  union sigval sigev_value;    // 带给接收方的值  void (*sigev_notify_function)(union sigval);  pthread_attr_t *sigev_notify_attributes;};
  • SIGEV_SIGNAL：发 sigev_signo 指定的信号，si_value = sigev_value，si_code = SI_TIMER。
  • SIGEV_THREAD：新开一个线程执行 sigev_notify_function(sigev_value)。那是普通线程，不受 async-signal-safe 限制。
  • SIGEV_NONE：不通知，只能自己用 timer_gettime 去查。
  • evp = NULL：等于 SIGEV_SIGNAL + SIGALRM，sigev_value 是定时器的 id。

什么时候到期：struct itimerspec

struct itimerspec {  struct timespec it_interval; // 之后每隔多久  struct timespec it_value;    // 第一次到期};
  • it_value ≠ 0：启动（armar）。flags = 0 时它是"从现在起多久"；flags = TIMER_ABSTIME 时它是所选时钟上的绝对时刻（已经过去的时刻会立刻到期）。
  • it_value = 0：停止（desarmar），不管 it_interval 是多少。
  • it_interval ≠ 0：周期定时器，每次到期后自动重装这个值。
  • it_interval = 0：单次定时器，只响一次。

例：SIGEV_SIGNAL 的周期定时器

每 250 ms 发一次 SIGRTMIN，主程序数到 20 次就停。顺序是：先装处理函数，再创建定时器，最后启动。

#include <signal.h>#include <stdio.h>#include <time.h>#include <unistd.h> static volatile sig_atomic_t ticks = 0; static void on_tick(int sig, siginfo_t *si, void *uc) {    (void)sig; (void)si; (void)uc;    ticks++;                                     // 只记一笔；si->si_value.sival_ptr 指向 tid} int main(void) {    struct sigaction sa = {0};    sa.sa_sigaction = on_tick;    sa.sa_flags = SA_SIGINFO;    sigemptyset(&sa.sa_mask);    sigaction(SIGRTMIN, &sa, NULL);             // ① 先装处理函数     timer_t tid;    struct sigevent sev = {0};    sev.sigev_notify = SIGEV_SIGNAL;             // ② 到期时发信号    sev.sigev_signo  = SIGRTMIN;    sev.sigev_value.sival_ptr = &tid;    if (timer_create(CLOCK_MONOTONIC, &sev, &tid) == -1) { perror("timer_create"); return 1; }     struct itimerspec its = {0};    its.it_value.tv_nsec    = 250 * 1000000L;   // ③ 第一次：250 ms 后    its.it_interval.tv_nsec = 250 * 1000000L;   //    之后每 250 ms    timer_settime(tid, 0, &its, NULL);           //    flags = 0：相对时间     while (ticks < 20) {        pause();        printf("tick %d\n", (int)ticks);    }    timer_delete(tid);    return 0;}

例：SIGEV_THREAD 的单次超时

static void timeout(union sigval v) {             // 在一个新线程里执行    printf("超时：%s\n", (char *)v.sival_ptr);    // 普通线程，可以用 printf} struct sigevent sev = {0};sev.sigev_notify = SIGEV_THREAD;sev.sigev_notify_function = timeout;sev.sigev_value.sival_ptr = "esperando respuesta";timer_t tid;timer_create(CLOCK_MONOTONIC, &sev, &tid); struct itimerspec once = {0};once.it_value.tv_sec = 3;                         // 3 s 后；it_interval = 0 → 只响一次timer_settime(tid, 0, &once, NULL);
别的等法

timeout：限制等待一个事件的时间，可以用单次定时器（到期的处理函数让等待结束），也可以用 select() 的 timeout 参数：它在一组文件描述符上等"可读 / 可写 / 异常"，最多等 timeout 这么久（NULL 表示一直等），到期时返回 0、所有集合清零。timerfd（Linux 专有）：timerfd_create + timerfd_settime 得到一个文件描述符，read 会阻塞到定时器到期，读出一个 uint64_t：上次读之后到期了几次。完全不用信号。异步 I/O（aio_read 等）完成时的通知，用的也是同一个 struct sigevent。

§7漂移：相对时间与绝对时间 T3.10

每圈睡 50 ms，跑 100 圈，为什么用了不止 5 秒？Deriva local y deriva acumulativa.

最直观的周期任务写法是"做一次，睡一个周期"：

for (;;) {    tarea_periodica();    nanosleep(&periodo, NULL);     // 相对时间：从"现在"起睡一个周期}

它有两个毛病：没有扣掉任务自己执行的时间；醒来时还可能被别的任务、时钟粒度、调度粒度再耽误一点。每一圈晚一点叫 deriva local (ES) / local drift (EN)——局部漂移；因为下一圈从"晚了的现在"重新算，这些误差一圈圈加起来，就是 deriva acumulativa (ES) / cumulative drift (EN)——累积漂移。

相对睡眠：第 n 圈的累积漂移 ≈ n × (执行时间 + 唤醒延迟)　　绝对时间：每圈 ≈ 唤醒延迟，不累积

用绝对时间排周期

思路是让延时"可变"：每次只睡到下一个周期的起点。最方便的写法是在 CLOCK_MONOTONIC 上算出绝对的目标时刻，用 clock_nanosleep(…, TIMER_ABSTIME, …)：

struct timespec next;clock_gettime(CLOCK_MONOTONIC, &next);              // 起点for (;;) {    ts_add_ns(&next, 50 * 1000000L);                // 下一个目标 = 上一个目标 + 周期（§5 的函数）    while (clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &next, NULL) == EINTR)        ;                                             // 被信号打断：目标时刻不变，接着睡    tarea_periodica();}
  • 关键在 next 是在上一个目标上加周期，而不是在"现在"上加。读一次时钟只在开头。
  • 被信号打断时，绝对时间的写法直接重试同一个目标，不会像相对睡眠那样每次多一点误差。
  • 如果某一圈的工作超过了一个周期，目标时刻已经过去，clock_nanosleep 立刻返回：任务会连着补跑，直到追上。需要的话可以检测这种情况（相当于定时器的 overrun）。

同样的思路也适用于 POSIX 定时器：调用 timer_settime 时 flags 写 TIMER_ABSTIME，it_value 就是绝对时刻，每次处理完再把它加上一个周期、重新设。片段如下（定时器要建在同一个时钟上，周期这里是 500 ms）：

struct itimerspec its = {0};                        // it_interval = 0：每次手动排下一次clock_gettime(CLOCK_MONOTONIC, &its.it_value);for (;;) {    ts_add_ns(&its.it_value, 500 * 1000000L);       // 下一个绝对时刻    timer_settime(tid, TIMER_ABSTIME, &its, NULL);    pause();                                         // 等这一次到期的通知    /* …这一周期的工作… */}
it_interval 会不会漂

周期定时器（it_interval ≠ 0）的下一次到期，是内核在上一次到期时刻上加 it_interval 算出来的，和处理函数什么时候执行无关，所以它本身不会因为任务的执行时间而累积漂移。有些资料的说法比较保守："不确定 it_interval 有没有修正漂移，就自己在代码里用绝对时间修正"。真正一定会累积的，是上面"做一次、相对地睡一个周期"的写法。

累积漂移来自"每次从现在起算"。把下一个时刻定义成"上一个目标 + 周期"，并用绝对时间去等（TIMER_ABSTIME），误差就停在局部漂移那一点，不再一圈圈加上去。局部漂移消除不了。

自测 12 题

根据本章内容编写的练习题。每题只能点一次，答完会显示解析。

01信号和硬件中断最根本的区别是？

B。两者都是异步的，处理完都回到原处；不同在于谁产生、送给谁（§1）。

02哪一组信号既不能捕获，也不能阻塞或忽略？

D。内核要保证总能杀死或停住一个进程（§1）。

03用 sigaction 安装一个三参数的处理函数 void h(int, siginfo_t *, void *)，必须怎样设置？

A。两个字段只能用一个；扩展形式要靠 SA_SIGINFO 打开（§2）。

04在信号处理函数里，下面哪个调用是安全的？

C。write 是 async-signal-safe 的；printf、malloc、加锁都可能和被打断的主程序争同一份内部状态，甚至死锁（§2）。

05SIGUSR1 装了处理函数，并且被阻塞。期间别的进程用 kill 发了 4 次 SIGUSR1，然后程序解除阻塞。处理函数执行几次？

B。阻塞不会丢信号，但标准信号不排队，挂起时只有一位（§3、§4）。

06同样的情况，换成用 sigqueue 发 4 次 SIGRTMIN+3，每次带不同的值。解除阻塞后会怎样？

C。实时信号排队，同一个信号按发送顺序投递，每一项带着自己的 si_value（§4）。

07"信号 X 被忽略（SIG_IGN）"和"信号 X 被阻塞"的区别是？

A。"enmascarar"是阻塞，和 SIG_IGN 是两回事（§3）。

08多线程程序想在一个专门的线程里用 sigwait 处理 SIGTERM。正确的做法是？

D。发给进程的信号会交给任一没阻塞它的线程；所以所有线程都要阻塞它，sigwait 才能确定地取到（§3）。

09调用 timer_settime(tid, 0, &its, NULL)，其中 its.it_value = {0, 0}、its.it_interval = {0, 200000000}。结果是？

B。it_value 为 0 就是 desarmar，不管 it_interval 是多少（§6）。

10一个周期定时器的信号被阻塞了一段时间，解除阻塞后处理函数里 timer_getoverrun() 返回 2。这说明？

C。同一个定时器一次只挂一个信号，挂着期间的到期只让 overrun 加 1（§6）。

11为什么排周期任务时通常用 CLOCK_MONOTONIC，而不是 CLOCK_REALTIME？

A。REALTIME 是墙上时钟，会被调；从 Epoch 计时的是 REALTIME。两个时钟都可以配 TIMER_ABSTIME（§5）。

12循环里每圈做 3 ms 的工作，再 nanosleep 相对地睡 20 ms（忽略唤醒延迟）。跑 100 圈后，比理想时间 100 × 20 ms 晚了多少？怎样消除？

B。累积漂移 = 100 × 3 ms。固定地少睡 3 ms 只在工作时间恒定、没有任何延迟时才凑巧对得上；绝对时间才真正不累积（§7）。
